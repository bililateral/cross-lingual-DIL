# 完整群隔离元更新：实现与Linux手写核验

2026-10-04。本轮实现、必要手写核验已完成，尚未完成本方案网页外审，也没有正式实验结果。用户批准的研究问题、范围和预算见authorization.json及docs/SELLER_ALIAS_GROUP_META.zh.md。

## 实际实现

新增scripts/step28_group_meta.py，复用基础文本表示、BCE/rank/hard、LOGIT来源分数和六群记忆；父算法源码未改。当前群与历史群分别提供support/query完整群，四群账号及商品身份不交叉。Ls为LOGIT0.1监督，快参数为theta-A grad Ls；Lq确实以快参数预测另两个群；J=Ls+beta Lq保留内层create_graph，编码器和头均进入完整二阶反向。正式模型仅执行一次clip及AdamW。

train_stage接通原288步日程、当前query循环移位、历史query排除当步support、按历史UID取固定参考和记忆附属设置。此阶段编排经spy核对，并未执行288次BGE训练。API只接收已提供的当前群及合法记忆，本轮没有接入正式数据、校准、评价或新GPU作业。完整状态保存/恢复的相同下一步证据来自微型真实模型，不是原生BGE持久恢复。

## 防伪实现证据及其适用范围

1. 独立标量反例的精确梯度为0.1064；detach内层为0.308、查询使用原theta为0.21，均可被解析/有限差分区分。support试走一步改善自身却恶化query，完整元梯度改变更新倾向。
2. 微型文本模型完整四群目标：改历史query会改变真实梯度，encoder/head各有外层增量及Hessian校正；实际目标有限差分符合；临时过程不改原参数/全局RNG；beta0回到LOGIT梯度。
3. 微型真实update只clip/Adam一次；完整model/Adam保存恢复后下一步目标和最终参数摘要一致。
4. 阶段spy核对每当前群support/query各六次、288次update调用、1152次群梯度呈现，非默认Settings原样传入。最终夹具以每历史群不同的参考值识别错绑，不靠全零目标获得形式通过；存活参考不刷新，序列化含附属设置且≤1MiB。spy不提供288次真实优化证据。
5. 原生BGE实际完整J.backward和Adam更新，probe数据如下；不是只看总梯度非零。

## 当前科学判断与外审

机制直接对应少量历史更新能否有助于其他训练群，同时监督新群体学习。但六个历史query仍属见过的缓存，尚未验证旧分布未见卖家收益；现有结果未证明过拟合是唯一原因。通用结构与MER、La-MAML、MLDG等有直接重叠，不能把整群/LOGIT组合宣称非平凡创新。

当前float32/eager/no-checkpoint完整二阶路径开销较大，尚未验证正式GPU可行性；成功CPU峰值不能直接推定GPU显存。未来正式比较要区分四群呈现、额外计算、群隔离和元更新，不能直接把更多计算所得提升当机制贡献。当前不选正式超参数，也不据手写loss启动正式训练。
