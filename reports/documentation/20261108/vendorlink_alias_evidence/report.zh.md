# 原三市场跨账号马甲关系：现有证据与数据准备结论

2026-11-08；对象为已保存的 AlphaBay、Dream、Agora 商品包、规范缓存及用户补充批准的 Grams 身份 SQL／HTML。本报告是这一次有限核查的结论，不是训练结果。计算、证据判读及[主审](review/primary_disposition.zh.md)已完成；用户明确本轮免外审，没有上传审查包。有效范围见 [scope.zh.md](scope.zh.md)，原始执行汇总见 [audit01](audit01/summary.json)、[audit02](audit02/summary.json)、[audit03](audit03/summary.json)、[audit04](audit04/summary.json)；后三者是有具体缺口的增量核查，没有重跑模型或整套历史实验。

## 1. 对用户问题的直接回答

**现有数据确实包含真实、不同的观察账号之间的关联候选；但本轮没有建立足够可靠的跨账号同控／不同控标签，不能交付“可验证真实马甲识别及遗忘评价的数据集已就绪”的结论。** 因而按已确认的条件性准备分支，保存候选与证据缺口，不生成正式训练／开发／测试划分，不把同账号拆成两份来补正例，不训练。

这纠正两种不同的错误：不能因为旧实验只用了同账号视图，就声称原数据不存在跨账号关系；也不能因为 SQL 有共享公钥、HTML 有多个市场链接，就把它们直接升级为独立核实过的同控真值。当前有限核查接受的已验证同控对和已验证不同控对均为 0；这个数表示**本轮未建立满足约定依据的标签**，不表示真实世界没有马甲、不表示所有候选都是错的，也不表示已经穷尽所有可能的账号声明。

完整 H 的多记录账号对输入及集合评分能够承接这些不同账号，问题不在“账号必须拆成两份才能输入 H”。当前未具备的条件是可靠监督／评价关系、未知关系的处理、独立留出和可支持顺序学习的阶段组成。共享 PGP／Grams 归组可以支撑另一种明确标为“来源归组弱标签”的跨账号实验；这仍是真实不同账号的关联任务，但其评价对象和可声称的正确性弱于已核实同控，不能在本轮悄悄替换。

## 3. 关联证据究竟有多强

| 观察 | 实际结果 | 可以支持／不能支持的判断 |
|---|---|---|
| Grams 身份记录连接多个商品账号 | 1,096 组、2,461 个账号；360 组有不同名字；1,024 组跨市场；10 组含冒名标记 | 有实质跨账号候选。相同名字跨市场也属于不同市场的观察账号，但不能自动认定同控 |
| Grams link 与公钥归组是否独立 | 1,096 组的 ID 及成员完全相同 | 两种存储表示是同一来源关系；HTML 里的同组市场链接也不能算第三份独立验证 |
| 公钥解析 | 初次 1,091／1,096 正常退出；5 条非零退出仍可能输出指纹。只修复明确缺少空白分隔行的 1 条后，1 条恢复，另 4 条保守排除 | 指纹对应证明密钥内容的一致性，不能证明发布者持有私钥或所有账号同控；非零退出不能因为已有指纹就写解析通过。未继续为无关格式问题扩展解析工程 |
| 商品文本内公钥 | 宽松 BEGIN／END 词边界发现 239 条有两端标记的文本、28 个账号 | 严格 ASCII armor 的首次零匹配是格式问题，不能解释为没有 PGP。来源曾去标点／换行，有边界词也不保证密码学材料可恢复 |
| 商品文本内签名消息 | 41 条签名消息开始片段、9 个账号；这些片段均未保留完整签名结束标记 | 当前提取的片段不能验签。不是“历史上无人签名”，也不是穷尽任何格式的密码学证明 |
| 不同名字的明确账号关联语境 | 在已有 Grams 候选组内，召回并人工读了 3 个有向关系，未发现互为声明 | 一条账号迁移并声称同 PGP；两条列举自己的跨市场账号，其中一条说明旧账号不活跃。均为未签名、单边声明；重复商品版本不构成独立核实 |
| 账号登记 profile | 三市场相关登记的 profile 正文均为空 | 没有从这个字段取得额外身份声明 |
| 身份 HTML 补查 | 15,922 个身份页头部中，签名消息开始／完整签名块均为 0；44 个验证／冒名词命中均是同一通用冒名警示 | 未找到这些账号的独立控制权核验记录；通用警示不等于账号被验证，也不证明从未做过人工审核 |

主执行者对 3 条声明的逐条判读及来源身份留 Linux；[primary_summary.json](primary_summary.json)只回传聚合判断。声明召回是关键词和现有候选成员约束下的有限核查，可能漏掉别名、变体拼写、未保存页面或其他位置的证据；不能据此发布“所有原始文本都不存在可核实关系”的全称结论。

这里并没有设定“只有司法身份或数字签名才算证据”。有可追溯的可靠人工核实、独立账号控制证明或明确验证程序，同样可以支持关系标注。问题在于当前文件没有提供足以评估 Grams 逐关系核验可靠性的程序和记录。Tai、Soska、Christin 对这一历史来源的研究也明确区分 Grams／PGP 启发式和真值，并说明复制公钥与不同公钥的局限。该 2019 年材料仅用于核对本项目已有 2017 年 Grams 数据的来源，不作为新推荐的过时应用方法。[原论文 §3.3、§4](https://www.andrew.cmu.edu/user/nicolasc/publications/Tai-KDD19.pdf)

## 4. 数量是否足够：必须按关系组和阶段回答

剔除带冒名标记的组、尚未解决的公钥解析项、歧义登记匹配、仅大小写折叠匹配，并要求成员至少有两条不同原始商品文本、每组至少两个成员，得到 **1,013 个弱关联候选组、2,275 个实际账号，其中 323 组包含不同名字**。这不是 1,013 个已验证独立经营者；只是当前来源归组数量。

| 组涉及的市场 | 组数 |
|---|---:|
| Agora＋AlphaBay | 357 |
| Agora＋AlphaBay＋Dream | 210 |
| Agora＋Dream | 74 |
| AlphaBay＋Dream | 316 |
| 仅 Agora | 23 |
| 仅 AlphaBay | 29 |
| 仅 Dream | 4 |

以上 2,275 个账号分别为 Agora 696、AlphaBay 968、Dream 611。同一个多市场候选组中也可能有两个同市场账号，因此不能用“仅该市场”的组数估计市场内部正例容量。依据保存成员重新计数的正确结果见 [capacity_detail.json](capacity_detail.json)：

| 在该市场内至少有两个账号的候选组 | 组数 | 该市场账号数 | 无向候选对数 |
|---|---:|---:|---:|
| Agora | 30 | 62 | 34 |
| AlphaBay | 51 | 107 | 61 |
| Dream | 7 | 14 | 7 |

全部候选组合展开为 1,523 个无向对，组合数不是独立卖家数，也不是样本量自动变大。所有这些数都在最终清洗、屏蔽标签证据和训练／开发／测试划分**之前**；两条原始不同文本可能仅有微小差别或包含识别线索，未证明清洗后仍满足完整 H 的多记录需要。

因此，当前不能沿用旧 AlphaBay→Dream→Agora 的三个独立市场任务，声称每阶段都有足量已验证正例。跨市场关系只有两端账号均可见时才能形成账号对；提前把未来账号文本放进训练会改变持续学习协议。联合两个市场作初始阶段、以后扩展市场等做法在弱标签任务中可能值得讨论，但属于新的科学设计，当前没有暗中冻结或据结果选择。

时间也不能随意重建：AlphaBay 原快照覆盖 2015-07-14 至 2016-04-17，Dream 的五个快照覆盖 2016-04-09 至 2016-04-17，Agora CSV 没有逐商品日期。Grams 身份登记覆盖更晚年份，登记、更新、抓取时间不是当年商品账号控制权开始时间。旧 ABC 顺序可以是人工域顺序，不能写成严格自然时间到达。

## 5. 完整 H 能复用什么，什么条件仍缺失

实际方法入口 [step29_vendorlink_methods.py](../../../../scripts/step29_vendorlink_methods.py) 的 `records → table → h_pool` 接收每个账号的多条标题／描述，计算记录对评分并汇聚为账号对评分。它不要求两个账号是同一个账号拆出的两份视图。自然／身份内重组监督、历史回放和旧评分保持可在真实账号关系充分定义后保留；本轮没有削减 H，也没有改动它的训练入口。

但当前 `Group.labels()` 由 identity 相等与否生成所有二元标签，`h_loss` 还要求每个 query 有正例且至少五个负例。若把不同 Grams 组都指定为不同真实经营者，代码会把尚未证实的关系直接变成负例；若删除这一要求或改成只学正例，又是新的损失方案，不能称为原完整 H 原样应用。回放和保持项无法解决缺失的真值。

评价也需要同样清楚：在不完整候选名单上把所有未列出的账号视为非相关，会使 MAP／Recall 混入未知关系错误，不能称真实马甲识别准确率。原 VendorLink 学账号分类表示，再对**不同账号**的广告集合排序潜在马甲；原论文明确缺少潜在马甲真值，其分类 F1 不能替代马甲关系 F1。本轮保留这一区别，不因评价困难否认模型可以做候选发现。[原 VendorLink §4.1、§4.2、§5.2 及脚注7](https://aclanthology.org/2023.acl-long.481.pdf)

独立性也尚未建立。规范缓存已经用于旧来源盘点、清洗、代理划分及训练／评价，旧 dev 又用于后续全池分析。新关系标注不把这些文本变成未见数据。本轮没有获准读取旧 owners／qrels，也没有计算逐候选的旧 fit／dev／heldout 使用交叉表，因而没有凭猜测宣布存在独立确认集。旧总体使用历史从[原三市场接线](../../20261029/vendorlink/three_market/plan.zh.txt)和已保存正式结果追溯；需要新的具体用途决定与可访问来源才能进一步落实逐账号隔离。

完整 H 抗遗忘的原目标不变：先有合理学习、可重复且有实际幅度的旧能力下降，再比较 Full 与 SEQ／ER 的保持，同时保护旧域初学、旧域最终和新域能力，并和 VendorLink 等外部方法比较。本次没有训练或评分，既没有证明会遗忘，也没有证明不会遗忘。

## 6. 当前交付、费用和停止位置

已完成的是来源定位、不同账号连接候选、公钥格式／同源依赖／声明与验证记录核查、容量统计和条件判断。没有产出正式跨账号训练集、划分、候选评价池或同控真值文件。Linux 保存最终候选依据及人工判读；它们须带弱证据状态，不能被后续训练器当作已批准标签自动加载。Windows 只保存聚合与文档。

六项有 GNU time 原件的作业累计 **171.88 秒**，包含一次手写 SQL／标记解析核验、初核、原包补查、格式／关系增量和 HTML 头部补查，退出码均为 0。另有少量部分计时的 schema／语境／计数核对；预算保守计费 **200／3,600 秒**，预留差额 28.12 秒覆盖这些短调用及启动，不冒称 200 秒是精确测量值。剩余 3,400 秒不自动授权新方向。最高实测 RSS 为 214,380 KiB（约 209.36 MiB），单 CPU worker、最多两核；GPU、载模和训练均为 0。SSH／SFTP与文档／审阅工期单列，不计为训练时间。详见 [budget.json](budget.json) 及各 `.time` 原件。

当前按证据不足分支停止正式数据准备，不继续为得到预期结果搜索更多种子、划分或生成伪正负例。用户在具体包准备后明确本轮免外审；主审已核对标签结论强度、实际解析／计数、完整 H 与持续学习条件，不冒称获得网页外审通过。

用户随后明确：“完成后，记得把你此次构建数据集生成的脚本和中间文件都删掉”。收尾时删除本轮新增脚本及工作副本、临时包、可再生成中间文件；已有原始来源不动。最低必要源码版本按科研纪律留在本地 Git 历史供追溯，工作区和 Linux 不继续保留一次性脚本；最终报告、原始运行费用、来源身份、必要候选证据及审阅／清理记录保留。清理前仍需完成这一次的核查验收，不能把“待删除”记成已经删除；最终数量由实际清理回执更新。

## 7. 下一项实质决定

当前不需要用户再确认普通收尾步骤。若继续要求**已核实同控的训练和遗忘评价**，这批已存材料尚不足，后续需要有可追溯验证依据的新证据来源或限定人工核实，而不是重训旧代理。若用户接受**以 Grams 来源归组为弱标签的真实跨账号关联**，当前千组规模有进一步准备价值，但必须另行明确弱标签主张、未知负例、账号映射误差、证据遮蔽、旧数据用途和阶段组成；不能先启动后再补解释。这两条选择都不保证出现遗忘或 Full 获胜。

当前建议：先认可“发现了跨账号候选，但未建立所要求的真值与独立评价条件”这一实际结果，保留证据并完成清理；不把已知不足的数据强行冻结为正式遗忘基准。
