# 单 worker GPU 核验

2026-11-07，本次获准核验一次通过；正式 Evolution 训练尚未开始。依据是[实际计算回执](gpu01/receipt.json)、[完整进程生命周期](gpu_lifecycle.json)和[退出及模型文件核对](completion_observation.json)，不是仅凭退出码判断。输入全为固定手写文本，没有读取真实 Evolution 正文或 dev/test 标签。

## 实际行为和结果

同一个 GPU 进程先后执行 H_full/H3 与 V_ER/V0，使用既有 bert-base-cased 和未修改的生产训练、保存及恢复入口（生产来源 Git 2ba0f685）。每域保留 160 账号、20 群、每群32记录，三域各1轮；H 实际到达256 tokens、V 到达512 tokens。六群/1MiB历史机制保持。

全部更新检查有限、非零梯度；H 日志有实际非零出生保持项，V 的40次历史分类损失进入训练。其数学作用的独立参考和去项证据沿用[实现说明](../implementation.zh.md)及已闭合 CPU 审查，本次 GPU 总梯度不是它们的替代品。九格恢复只检查每域一个手写群，不能冒称正式 dev/test 整批评价完成。

只生成六个紧凑阶段模型和两个小型起点引用，共8文件、2,606,203,006逻辑字节（2.427 GiB）；没有每 epoch 完整训练状态。模型仍留 Linux，等待本轮必要审查完成后按实际用途收尾；未下载 Windows，未删除其他任务资产。

## 双路执行的证据边界

用户后续指定每 worker 14GiB上限，并确认最多两路、资源足够一条可先开始后补槽；最新纠正要求失败槽退出而健康槽继续领取后续任务。具体增量见[执行补充](../execution/scope.zh.md)，不修改冻结方案或单路核验原件。

实测12.1875GiB支持在新上限内继续实现，但旧 Vendor 单路14.1504GiB证据仍保留，不能保证所有正式任务都低于14GiB。正式执行不得为过门缩短文本、改批形状、改目标或重试；实际超限按新补充处理。正式旧控制器仍存在 `pynvml` 依赖且仅支持串行，必须把经核验的读取方式、双路承诺扣除、计费及故障行为接入真实入口，并完成定向 CPU 与实现审查。

[21:29只读现场](final_resource_observation.json)：H仍为PAUSED_DRAINING，AccountPool PID1396928（身份/命令/cwd见原件）仍用7.496GiB；GPU空闲23.594GiB，尚须保留其10.25GiB合同承诺未体现部分。允许先一槽的前提仍须在实际启动时重新核对，不能把本观测当永久准入。
