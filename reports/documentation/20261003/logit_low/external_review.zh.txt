## 4. 真实计算与梯度：完整 0.1、独立 0.5

### 4.1 目标展开与底层语义

实际目标展开为：

    BCE_current + Rank_current + 0.5 Hard_current
    + 0.1 BCE_history + 0.1 Rank_history + 0.05 Hard_history
    + 0.5 mean_378((z_history - target)^2)

所以历史 hard 的有效系数是 0.05；MSE 的有效系数仍为 0.5。没有除以 1.1，也没有把 MSE 再乘 0.1。[S3：242–250；S5]

底层 BCE 对 378 个无向账号对取均值。query rank 对 28 个查询，分别计算 27 候选的 logsumexp 减正例 logit 均值，再对查询平均。hard 只从已知负例中稳定选 top 5，计算正负 raw logit 差的 softplus；detach 仅用于选择索引，被选中的 live score 仍参与梯度。检查了该具体数据流，未见把历史 rank/hard 的梯度切断的操作。[S5：step28_chinese_base.py 165–191；step28_alias_ranking.py 89–129]

对于固定 target，0.5 mean((z−target)^2) 对每个历史 logit 的导数是 (z−target)/378；误再乘 0.1 会令这部分缩小十倍。这个导数只描述 MSE 分量，不能由此推断裁剪后总梯度、AdamW 参数步长或效果也按相同比例变化。

### 5.2 原生 4 次与 tiny 288 步严格分开

stdout 中两组到 288 的进度来自两个 Tiny 模型用例，带 handmade_fixture 标记；随后才开始两臂 native_start/native_end。原生每臂只有一次 warm 更新，其后将已有 Adam step 从 1 手写设为 288，再执行一次 weighted 更新至 289。moments 来自一次真实 warm，并非真实训练 288 步的 moments。源码和 JSON 的 counter_fixture 都明确这一点。[S7；S3 的 check.py 27–40、72–74、108–109]

本轮核验没有原生连续 288 步或正式 1728 步的证明，也没有声称有。不能把计数、Tiny 更新或网页 spy 调用合并成原生训练数。

### 5.3 独立 MSE 梯度是否真正到达模型

原生核验先由同预热模型 eval 产生 target，再在 train/seed=108 下单独对 0.5 MSE 调用 autograd.grad。随后在真正生产 update 中对两个参数注册 gradient hooks，分别取得 current 和 history 两次反向的贡献，再逐元素核对：

    g_LOGIT_history = g_ER0.1_history + g_independent_0.5MSE

两臂初始模型、warm 后模型、加权前 Adam、全部当前/历史 378 logits 相等；当前梯度要求逐元素完全相等。原生 history 比较使用 rtol=2e-5、atol=2e-8。[S7；step28_er_weight_check.py 48–79、178–194]

| 组件探针 | 独立 0.5 MSE 梯度 L2 范数 | 保存的逐元素等式最大残差 |
|---|---:|---:|
| 编码器第一层 query.weight | 8.615575643489137e-5 | 1.000444171950221e-11 |
| head 隐藏层 weight | 0.001860779826529324 | 2.764863893389702e-10 |

另有 29 个参数的非零有限梯度和实际变化观察：24 层 query.weight、词 embedding、两个 head Linear 的 weight/bias。这支持所选各层被更新；**两组件分解检查不等于所有参数的 MSE 增量逐元素检查**。[A5]

按保存的头部维度及范数，逐元素容差对应的误差 L2 上界约 2.06082e-5；若漏 MSE，差为 0.00186078；若 MSE 误再乘 0.1，差约 0.00167470。故在这些原生记录成立的条件下，两种伪实现都应被这项探针断言检出。这是基于保存范数的独立数学敏感性核验，不能称为本网页重跑真实 BGE 梯度。[A5]

## 6. 首域恢复、target 生命周期及数据访问

### 6.1 起点和供给

新分支从原三个 shared 首域完整 model/Adam/RNG 与 first_map 恢复；明确使用 logit_after1 缓存，既不从 ER0.1/LOGIT0.25 的后续末端续训，也不重训首域。实际入口在消费新 train 监督之前核对原 checkpoint/cache 文件身份；恢复后要求 Adam288、首校准映射、缓存成员和目标起源匹配，并回放全部 60 群首域盲分数，再恢复 RNG。[S4：181–245]

ContinuationSupply 只从阶段 2 开始，按 order 提供当前域 48 拟合与 12 校准群。实际生产 Supply 和 Memory 已在本网页手写夹具上运行，旧阶段、未来阶段和重复阶段请求均被拒绝。[A4]

### 6.2 target 生命周期

阶段二完成当前分支训练和 checkpoint 后，只对最终新入缓存的当前域群调用本路径模型 eval 评分；存活旧 target 字节不刷新，淘汰 target 删除。draw 返回副本；origin 只取对应阶段 1/2。缓存仍为模型无关 Algorithm R 六完整群，全部历史及附属状态计入 1 MiB。[S4：255–277；S5：Memory.retain/draw；A4]

### 6.3 1728 次参数转发的证据含义

### 6.4 盲门与失败处理

每终点有校准 raw、valid raw、stage-cal、first-cal 四数组；六终点合计 24 数组。只有三个 valid 角色形成指标，所以新增 18 套指标/计数。execute 的实际顺序是：全部训练 → blind_gate → before_valid → 一次 development 解析 → collect → finalize。[S4：100–178、294–422、505–513]

## 8. 冻结端点与原 23 项：没有新增成功线

对于任一顺序，R(t,j) 表示阶段 t 在第 j 个到达域的相应群指标；先按每个顺序定义，再对三顺序等权聚合。实际域的同一留出群保持配对。

|---|---|

| N | (R(2,2)+R(3,3))/2 |

| F_first | R(1,1)−R(3,1) |
| F | [R(1,1)−R(3,1)+R(2,2)−R(3,2)]/2 |
| G | [R(2,2)−R(1,2)+R(3,3)−R(2,3)]/2 |
| final_all | [R(3,1)+R(3,2)+R(3,3)]/3 |

F_first/F/G 中 Brier 和 log_loss 的符号按原定义反转。区间是条件于已训练模型、校准结果和已开发数据的实际域分层整群区间，不包含重新训练、校准重拟合或适应性选择的不确定性。[S6；A6]
