# 四组 FIT12 开训前定向审查

本包请求审查新市场适配器训练、正式派发和评价。方案的初稿标题记录提案时点，随附授权为后来用户决定。本批有四种训练方法、三个配对开发 seed、三个市场及同一组预先写定的开发判据。仅有手写合成资格和此前调度核验。尚未运行本批正式训练，尚无本批实测效果。

1. 沿 run.execute、MarketH、AccountModel 和优化器，检查 A 的共享编码器、B 的首套增量、C 对 B 的独立复制。检查当前域、旧群标签和确定性出生教师三条反传，特别是非重入检查点的重算、单一关系头的梯度、Adam 状态和 RNG。资格是否确实能发现错路、空更新或旧参数漂移？
2. 检查六群、原抽样、同 seed 的配对、出生教师和采样状态与两套适配器的 1 MiB 总帽。检查 H_SEQ 的零群状态，一条轨迹的一份 A 共享基座、四个端点和双方重新编码的九格恢复。合成资格中的最大合法群、双 256 token 与实测 GPU 整 PID 峰值怎样限制可作的资源主张？
3. 对照方案查逐轨迹的训练权限、当期 fit 访问、完成身份、九格盲评分、整批一次 dev 分析和 confirm 隔离。逐项核对 Full−ER、Full−SEQ、遗忘压力、两个外部读取器的判据、净学习的高起点备选、每个 seed 的保护以及旧 ER／β 对照的来源。指出实现会误过或误拒的具体输入。
4. 检查 V 单跑、九条 H 先两路再满足条件补三路、同一控制器的领用、按同配置和 seed 恰一次具名 OOM 重试、首败与费用保留、健康槽继续和不完整批次关闭下游。审查累计 111/5/4 小时预算、单任务上限、资源预留、首次启动与重入边界。既往 OOM 合成调度核验的模拟 NVML 与本次原生 GPU 证据分别判断。
5. 请逐项给出可复核的源码定位、实际触发条件、严重性和放行意见。对假想优化与开训前必须修正的问题分别标明依据。无需搜索新方法、访问外部数据或推测效果。请完整回复中文意见并提供同内容的 UTF-8 Markdown 文件。
