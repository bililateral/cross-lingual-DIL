# 条件启动与自删的定向审查

此次中文六方法的科学入口、CPU／GPU 资格和 OOM 调度已有独立主审。本包仅审本次增加的条件开训行为。请从实际 Linux 启动、资源等待、正式派工和首条原生优化记录追踪到删除一次性副本。

1. 是否只有具名 VendorLink 四组整批运行终态与进程释放才放行。检查还在训练、评分、分析，旧 PID 复用，阶段不完整和正常科学负结果的区别。前序未决技术故障应保留证据。
2. 是否只创建一批中文队列。等待中换门或来源失效、重复调用、直接绕过监听、在途预算和首槽资源不足分别会怎样。判断现有证据可支撑到哪一步。
3. 自删是否绑定本批 worker、真实正更新、正确的原生 run_id 与已核文件身份，能否留下第一笔更新和删除的可恢复证据。保留原调度的手动 OOM 一次重试。
4. 预训练及具名训练输入的隔离、原资格费与本次监听计费、新 gate／授权和 Linux 部署检查是否足以执行用户批准的具体批次。只指明影响实际执行的缺口、触发条件、最小修复和验证。
