## 三、问题一：实际 Q2/FIT12 接线、两次独立扰动及覆盖范围

### 3.1 角色、阶段和市场的职责没有混淆

顶层 `score()` 从 manifest 按 `domain:role` 和 `domain:fit` 取得每市场两份文件，经 `load_role()` 读取。`load_role()` 检查账号唯一且排序、账号数量，以及查询每账号 2 条、FIT 每账号 12 条；随后 `score()` 检查两角色账号顺序一致，记录 UID 与视图 UID 不相交。[E：`load_role()`，L17；`score()`，L171、L179、L184、L188]

这些是实际生产评分入口中的角色与标识校验。本轮传入的 `dev` 只是合成角色名，不能因此说打开了真实 dev。这里的“不相交”也明确是 UID 层校验，不能推广成对任意输入文本内容重复的完整检测。

阶段负责恢复**当时的端点状态和已存在的参数集**。`restore()` 核对端点的 identity、task、model_binding、stage；适配器分支再恢复共享编码器、单一关系头，按顺序进入阶段，必要时载入历史包。[R：`restore()`，L195；A：`restore_scoring_endpoint()`，L165]

市场负责选择**这次评分使用的编码路径**。`score_market()` 给查询和 FIT 两次 `encode()` 都传入相同 `market`；H 分支将其写入 `Group.domain`，`MarketH.records()` 再用该 domain 建立路由上下文。标题与正文的整个原 `records()` 调用都处于这个上下文中。[E：`score_market()`，L164；`encode()`，L29、L35；A：`records()`，L102；P：`records()`，L37]

实际路由为：

\[
\mathrm{route}=\mathrm{DOMAINS}\!\left[\min\bigl(\mathrm{market\_index},\max(0,\mathrm{stage}-1)\bigr)\right].
\]

因此，未开始学习的市场使用当时最后可用的编码器，而已经建立的旧市场仍使用自己的路径。[A：`routing()`，L91]

**判断：通过。未发现只路由 Q2、漏掉 FIT12，或只路由标题、漏掉正文的静态接线错误。**

### 3.2 原共享关系头及 24 对聚合保持一致

原记录编码节录使用最后四层输出求和，按有效 token 平均；标题与正文分别归一化，拼接后除以 \(\sqrt2\)。本轮回执中的记录维数为 1,536，Q2 为 `3×2×1536`，FIT12 为 `3×12×1536`，账号矩阵为 `3×3`。[P：`text_pool()`，L5；`records()`，L37；J：`query_shape`、`fit_shape`、`score_shape`]

`MarketH.head` 直接返回 `self.h.head`，并未创建市场私有关系头。`rectangular()` 对每个查询账号与参考账号的全部 \(2\times12=24\) 个记录对，使用共同头计算

\[
k_{rs}=h\!\left([|z^q_r-z^f_s|,\ z^q_r\odot z^f_s]\right),
\]

再聚合为

\[
S(q,f)=\tfrac12\operatorname{mean}(K)
+\tfrac12\left(\operatorname{logsumexp}(K)-\log24\right).
\]

聚合在 double 精度中进行，结果转回 float 后输出 NumPy 矩阵；顶层实际调用 `np.save()` 落盘并记录文件绑定。[A：`head`，L70；E：`rectangular()`，L51、L69、L70、L71；`score()`，L203]

**判断：通过。这里验证的是原始账号聚合分数，不是概率、宏 F1 或排序效果指标。** 原 `AccountModel` 完整模块不在包内，因此对原模型内部未改部分的判断同时依赖 P 的节录与 J 的复用来源摘要，不能称为已重新逐字审完全部旧实现。

### 3.4 候选分差正确排除了统一偏置，但没有证明排名翻转

脚本定义

\[
\Delta_{ij}=S^{\rm after}_{ij}-S^{\rm before}_{ij},\qquad
G=\max_i\left(\max_j\Delta_{ij}-\min_j\Delta_{ij}\right).
\]

这正是某一查询下任意两个候选的分差改变量的最大绝对值。若只给每个查询的所有候选加同一个常数，即使常数因查询而异，\(G\) 也等于零。因此实际非零 \(G\) 支持“至少一个查询中，候选相对分差改变”，足以排除纯统一加性偏置的解释。[C：`differences()`，L55]

但这不证明候选次序已经翻转，更不证明改变方向有益。两类干预的参数维度和扰动幅度也不同，不能因为共享头引起的分数差较大，就推导它在真实训练遗忘中的贡献比例。[C：`shift_bank()`，L61；头扰动，L171]

**判断：两次独立干预成立，统一偏置解释被本夹具中的非零分差否定；真实排序改善仍没有证据。**

## 四、问题二：1 MiB 序列化、六群历史与恢复

### 4.1 两套 rank-8 FP32 参数量和全部文件开销均已计入

\[

\]

\[

### 4.2 六群是完整原格式历史，教师分母与评分分母不同

评分夹具每市场 3 个账号；容量夹具另使用每市场 **16 个合成 FIT 账号**，调用原 `groups_for()` 生成每域 6 群。两种夹具用途不同，并不存在用 3 个评分账号构造 8 账号训练群的矛盾。[C：L101、L106、L138；R：`groups_for()`，L18]

原构群按每账号 12 条记录分成三包，每包两个视图、每视图两条；本轮完整群为 8 个账号、16 个视图、32 条记录。原 Memory 节录保留 `asdict(group)` 全内容及 origin，只为新存活条目计算教师，原有教师不刷新；`state()` 包括 `seen`、`entries`、`rng`。[R：L30、L33、L36、L37；P：`retain()`，L65；`state()`，L88]

教师来自群内全部记录无序对：

\[
\binom{32}{2}=496\quad\text{个 FP32 分数/群}.
\]

六群共 **192 条记录、2,976 个教师分数、11,904 字节教师裸张量**。这里的 496 是群内出生教师的记录对数，前面的 24 是一个 Q2/FIT12 账号对的评估记录对数，二者不可混用。[P：`table()`，L49；`teacher()`，L55；J：`capacity.groups`]

本次 Algorithm R 共见到 **12 个候选群**，存活来源依次为 `[1,1,2,2,1,2]`，即 AlphaBay、Dream 各三槽。这是本次固定输入和种子的抽样结果，**不是六槽算法保证每个市场恰好三槽的配额**。[P：`retain()`，L70；J：`capacity.reservoir_seen`、`groups`]

64,597 字节包括完整文本、各类标识、教师、采样状态及序列化结构。扣除教师裸张量后的余数不能直接命名为“纯文本字节”。

**判断：源码及回执支持保存完整群和逐记录对出生教师，未见只保存向量或以简化占位数据替代六群状态的实现。这里的完整文本仍是合成文本，不是真实市场正文。**

### 4.3 恢复检查支持评分与历史状态恢复，不等于训练续跑

恢复逻辑先检查包长和精确路由元数据；适配器加载检查参数键集、形状、FP32 dtype，再按值复制。Memory 恢复加载原 `seen/entries/rng` 状态。[A：`load_adapters()`，L116；`restore_history()`，L152；P：`restore()`，L91]

实际核验包含以下内容：

1. 新建 `Memory(0)`，从历史包恢复；主模型在头扰动后已恢复原头，并从共同起点适配器载入保存后的状态。
2. 恢复后 Agora 的 Q2、FIT12、账号矩阵和候选分差与保存前均为零差。
3. 六槽的完整 group 字典和来源逐项相等；教师为 FP32、形状 `(496,)`、有限且非恒定，与保存教师逐值相等。
4. `seen` 和 reservoir RNG 状态完整相等；12 个相同外部 `draw_seed` 下抽得的群与教师相等。

上述检查对应 C 的 L176、L178、L180、L183、L186、L188、L192，结果见 J 的 `restored_Agora`、`capacity.rng_restored`、`draws_equal`。

这里要保留三个具体区别。

**首先，直接恢复分支新建的是 Memory，对模型本身是载回已有对象；顶层九格评分则通过 `restore()` 的工厂为各阶段新建模型。** 两部分共同提供当前历史恢复与新模型评分恢复证据，不能把前一分支单独称为“所有对象都从零重建”。[R：L200；A：L173；C：L176]

**其次，12 次抽样没有使用 reservoir 的内部 RNG。** 原 `draw(draw_seed)` 调用 `random.Random(draw_seed).choice()`，因此这项检查证明“恢复条目＋同一外部种子”产生相同抽样；内部 reservoir RNG 的恢复由另一个 `getstate()` 相等检查支持。没有实际继续执行 `retain()` 并比较后续替换轨迹。[P：`draw()`，L100；C：L180、L192]

**最后，教师与当前模型重新计算相等，只在本合成状态中有解释。** 本轮没有训练共享头或基础编码器，也没有继续改动旧域适配器，所以旧教师可以与当前前向一致；这不意味着真实后续训练中出生教师必然仍等于当前分数。代码仍保留“旧教师不刷新”的机制。[P：L68、L79；C：L188]

**判断：本轮历史状态和评分恢复证据可接受。没有优化器恢复、全局训练 RNG 恢复或继续训练轨迹的证据，也不需要为本次任务补做这些范围外工作。**

### 4.4 超限保护：打包端已动态覆盖，恢复端只做了静态核对

`pack_history()` 和 `restore_history()` 均以 `min(settings.memory_bytes, CAP)` 检查包长。动态负例在一个合成 description 后增加 `CAP` 个 ASCII 字符，再调用 `pack_history()`。[A：L147、L153；C：L196、L198]

**判断：保存端的超限拒绝有运行回执；恢复端的同类守卫在源码中存在，但本轮没有另外执行“超限输入恢复失败”的动态用例。** 不应把两者合写为两个方向均已实测。这不是现有合成样本超限或被错误接受的证据。

### 4.5 共享编码器、共同头和旧 Memory 换算的归账正确，但适用条件必须写清

本轮 1 MiB 合同针对**历史附加状态**。单一共享基础编码器与当前单一关系头作为在用模型不计入该历史包；Dream 和 Agora 两套市场参数都计入，包括当时当前市场 Agora 的参数。[S：L16；A：`metadata()`，L128；D：L33]

在同样适配器布局、序列化格式、64 字符身份和封装条件下，Memory 外的固定部分为

## 五、问题三：证据最多支持什么，哪些缺口会改变主张

### 5.1 可以保留的工程结论

在本次固定合成夹具、所附源码和保存回执范围内，可以保留：

- 市场适配器已经接入实际市场内 Q2/FIT12 评分入口，两侧使用同一所评市场路径，原共享头与 24 对聚合保持。
- 仅改 Agora 适配器时，本实例中 AlphaBay、Dream 两侧表示与全部账号分数不变，Agora 两侧表示及候选相对分差能变。
- 仅改共享头输入权重时，三市场表示不变而分数及候选分差能变；因此编码路径隔离本身不保证旧市场排序能力完全固定。
- 同基座、同原头的合成端点完成了九格恢复及矩阵导出，包括 Dream、Agora 学前路径。
- 两套适配器与本次六群完整合成历史的保存总长为 861,243 字节；评分、Memory 恢复及所测保存超限拒绝与回执一致。

这些结论分别由第三、四节所列实际源码位置与 J 的对应字段支持。

### 5.2 不应据此形成的科研结论

本轮没有真实市场训练或真实评价数据，没有 Full 与 ER 的效果比较，更没有统计检验。因此不能据此判断：适配器是否能学好 Dream 或 Agora、遗忘是否减少、旧域最终能力是否提高、新域质量是否受损、Full 是否优于 ER，或该参数分配是否已经解决原研究瓶颈。[Q：L7；S：L18；J：`validation_inputs`、`training_updates`]

共享头扰动恰好说明一个需要保留的机制边界：即便旧市场编码表示隔离，共同头仍可改变旧市场候选分差。但本轮既没有测得真实遗忘，也没有证明未来一定会遗忘；它只显示这条作用通道仍存在。
