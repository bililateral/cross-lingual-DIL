# 当期 fit 构群能找回多少旧错误对手

2026-11-18 用户批准一次无训练诊断。输入限 AlphaBay 和 Dream 各自当期 FIT12 文本、原群索引。每个训练 seed 51、52、53 做 1,000 条完整配对轨迹，全部清单冻结以后才用既有 H_ER 的 12 个开发分数矩阵。一次结果合审，外发另按具体包确认。

1. 原 epoch 0 的每个账号占据一个匿名位置，在三个记录包中各出现一次。每个包用该账号自己的四条记录，维持原来的两个双记录视图和顺序。复用原始候选群的位置、大小、任意群间的成员重叠数及原记录分包。对整个市场使用一个账号到位置的双射。改变账号时，两份视图连同原记录与观察账号身份一起移动，群 UID 按原内容公式重建。
2. 复用上一轮已经审过的 fit 提名。仅在本市场内轮流留出一份双记录视图，以剩余十条为参考，标题、正文分别计算词级 TF-IDF 余弦，各占一半。每折每账号按原账号序破同分，取最多五个严格正分的其他账号。将六折的双向提名次数相加，每个无向账号对得 1 至 12 分。先按分数降序、同分按独立可复现的随机优先级，贪心取两端均未用的账号对。每个账号最多显式配一个对手。
3. 枚举原模板中至少一起出现一次的位置对，去重，按独立随机顺序贪心取不相交位置对。打乱已匹配的位置对，按账号边的固定优先次序放入，可容纳多少放多少，每对随机定方向。其余账号均匀无放回填空。主对照为一次全市场均匀随机置换，在三个包共用，与定向组拥有完全相同的位置和结构。原历史成员编群另列为参照。构群随机数与蓄水池随机数分离，每次构群均不使用该次抽中的位置。
4. 三个版本都按原模板 UID 序给 Algorithm R 输入相同的位置、抽数与淘汰槽。沿用原六群随机留存，跨两市场合计六槽，保留同一条轨迹的 seen、采样器状态与旧群。当期结束后只带走自己这条轨迹的六群。每种构群给 Full、ER 提供一份共同的分槽、账号、视图与记录清单。用原 Memory.bytes 对各实际六槽、实际正文、采样状态和原形状的 float32 教师容量占位逐一计量，上限 1,048,576 字节。另核原历史抽样和六份原索引。历史抽样单列，不计入 1,000 次均值。没有模型教师推理或训练。清单密封于 Linux，汇总回传。容量超限、正式访问或执行故障保留记录，不补抽。
5. 所有市场、种子、三个版本及两个时点都冻结后，读取 ER 的 R11/R31、R22/R32 各一次。评价单位为起点检索正确第一、终点跌出的查询×seed，配其终点错误第一账号，沿原列序破同分。对原候选池从未将二者放在同一群的事件，按市场和 seed 记候选池可同群、出域六槽同群、AlphaBay 进入 Agora 前同群；Dream 出域即进入 Agora 前。进入 Agora 前的 AlphaBay 命中须可追溯到本次 AlphaBay 出域的同一存活槽。原可达的补集和全部事件同时报告。每格给出两边均中、仅定向、仅重新随机、均未中、两臂命中均值及配对净差分布。分母是每个 seed 的固定事件数，单次按查询去重。三个 seed 的均值相加，不把抽样并集或重复账号当作找回量。
6. 继续讨论的预定条件为，原漏的 47 个 AlphaBay 事件在出域六群的跨 seed 净增合计至少 1 对，至少两 seed 正向，进入 Agora 前净增合计大于零；全部 49 个 AlphaBay 事件的出域、留存净差合计各不低于零。对照是重新随机编群。Dream 七个原漏事件及全部八个另列。此门只决定是否有足够理由继续讨论。开发矩阵属于同一历史 ER，结论只覆盖直接同群机会。

诊断使用 Linux 既有 py310、一个 CPU 核。当前训练监督、损失、教师、标签、学习率及正式实验均未进入本任务。所有详细名册和映射只留 Linux，当前结果包须逐包许可，本次 Git 交付限本地。
