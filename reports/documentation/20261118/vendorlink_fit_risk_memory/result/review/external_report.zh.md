## 三、问题一：预测来源、六折定义、方向及分母

### 3.1 仅使用当期 fit 的路径成立

`freeze()` 按 AlphaBay、Dream 的阶段顺序读取各自冻结 fit，核对账号数和账号顺序 SHA；`select_market()` 从当前 `accounts` 生成原第 0 轮的 pool 与 views，再调用 `predict(views)`。预测函数没有 ER 开发矩阵输入，也没有跨市场旧词表或旧风险表参数。上一阶段传入的对象用于保留旧槽、实际群及采样器状态，不用于计算新市场词面预测。[E02：`freeze()`、`select_market()`、`predict()`]

这意味着当期风险信号的直接输入是 fit，但不意味着整个研究流程从未使用开发结果。历史遗忘事件和前序诊断本来就已经使用这批开发材料；本次先冻结再读矩阵，不能把它重新变成未使用的确认试验。[E00][E01][E07]

### 3.2 六折两条查询、其余十条参考与词面计算正确

原构群先将每账号 12 条互异记录按固定 seed／域／第 0 轮顺序处理，分成 3 个记录包，每包形成两份双记录视图。`make_pool()` 要求每账号六份视图完整、每份两条、合计 12 条互异记录。`predict()` 依次以第 `fold` 份双记录视图作查询，其他五份视图合计十条作参考。[E04：`groups_for()`、`make_pool()`；E02：`predict()`]

这是 **同一账号 fit 记录内的六种互补划分**，不是六套独立开发集，也不是六个独立训练试验。查询和自身参考的记录不重叠；每个参考账号都排除该账号当折的两条记录。

标题与正文分别建词级 TF-IDF，每字段在当折参考端 `fit_transform`，查询端只 `transform`；配置为小写、unigram、L2 归一化、平滑 IDF、非次线性 TF、float64。两路余弦各乘 0.5 后相加，没有把标题和正文合成一条长文本后只算一次。若某一路没有可用词，该路贡献零，不重新放大另一路。[E04：`cosine_field()`；E02：`predict()`]

### 3.3 自身、平手、弃权、有向边和 min 折数符合合同

| 合同规则 | 实际实现与判断 |
|---|---|
| 包含自身竞争第一 | 评分矩阵没有屏蔽对角线，对整行 `argmax`，自身参与竞争。 |
| 正最高分平手 | `argmax` 取首个最大值，沿冻结账号顺序；账号顺序另外被排序检查和顺序 SHA 约束。 |
| 无正分弃权 | 最高分必须严格大于零，否则该折 winner 为 −1；弃权不产生竞争者边。 |
| 仅当自身与具体错误账号都赢过 | `risk_edges()` 要求 `counts[q]>0`，并逐个输出实际出现过的 `j≥0`、`j≠q`。一直不胜的查询按合同不产边。 |
| 有向性 | 输出完整 `(q,j)`；反向 `(j,q)` 是另一条边，不能替代。 |
| 权重 | `w(q,j)=min(c(q),c(q,j))`；不是错误折数之和，也不是所有对手合并后的 min。 |
| 每 seed 预测一次 | 每市场、seed 的 `ordered_risks` 固定后，1,000 次布局共用，不随布局或开发事件重新预测。 |

证据：E02 的 `fold_winners()`、`risk_edges()`、`predict()`，E03 的 `validate_pair()`；E08 的手算同时覆盖正分平手、全零弃权、有向 min 折数及两条查询／十条参考的文本例子。六格回执均记录弃权折数为零；这只描述本次输入，并不删除弃权规则。[E05：`stats`]

### 3.4 三种分母不能混用

设某 seed 的固定历史事件集合为 `L`，固定预测边集合为 `P`，第 `r` 次布局某策略能同群覆盖的事件集合为 `C_r`。

| 量 | 正确含义与分母 |
|---|---|
| `guessed` | `|L∩P|`，按查询×seed的固定事件计数，只计一次。AlphaBay 原漏为 5/47，Dream 为 3/7。 |
| `uniform`、`priority` 的均值 | `Σ_r |L∩C_r| / 1000`，包含准确预测和偶然同群，是每次布局平均事件数。 |
| `guessed_uniform`、`guessed_priority` 的均值 | `Σ_r |L∩P∩C_r| / 1000`，是准确预测与覆盖的交集，同一事件可在不同布局重复出现。 |
| 跨 seed 合计 | 先求各 seed 均值，再将三个均值相加；等价于三个 seed 的事件×布局整数总量之和除以 1000。 |

`5/47≈10.64%`、`3/7≈42.86%` 可以称为“固定原漏事件集合上的精确有向竞争者命中比例”。它们不是 1,465／313 条全部预测边的总体精确率，也不是对未来未见遗忘事件的已验证召回率。47、7 按查询×seed计，不保证跨 seed 是不同账号。[E03：`cover()`、`paired_tally()`；E06：`rows[*].subsets.original_miss`]

例如 AlphaBay 风险策略原漏出域共 90 次事件×布局覆盖，报告的 0.090 是 `90/1000`，不是“9% 的事件被带走”。如果另外计算三个 seed 的布局合并平均，则是 `90/3000=0.030`；这是另一描述量，不能拿来替代合同的跨 seed 均值之和或改变原门。

**本项处置：接受所示预测实现。无需修源码或追加试验；后续引用必须沿用上述分母。**

## 四、问题二：同池公平、受约束六槽选择、容量和旧槽留存

### 4.1 主对照确为同一定向成员布局上的均匀六槽

入口要求上轮冻结臂的 `arms[2]` 为 `directed`，恢复其布局置换、原模板 UID 顺序、抽样器状态和 Algorithm R 替换位置，重建后的 `baseline` 必须严格等于原冻结 `layout["slots"]`。只使用原配对序号 1—1000，历史示例 0 被跳过。[E02：`freeze()`、`select_market()`；E04：`random_slots()`]

因此，对照的随机性在于 **相同定向成员布局中的六槽写入选择**。上轮“重新随机编群”改变的是位置到账号的布局，两者不是同一随机基准。本轮不能借用上轮随机编群臂数值，替换当前同池均匀写入对照。评价器还用上轮 `directed` 臂的整数池可达量和均匀覆盖量作锚点。[E03：`evaluate()`]

### 4.2 位置到账号的变换与实际记录包对应

模板成员是位置索引，冻结 `perm` 把位置映到账号。`candidate_edges()` 使用 `np.argsort(perm)` 将账号 q、j 反查回模板位置，再判断某记录包是否同群；`materialize()` 则正向使用 `perm[p]`，从该账号、该记录包的原视图表取出实际记录。两条映射方向互相对应，没有把账号编号误当作模板位置。[E02：`candidate_edges()`；E04：`view_table()`、`materialize()`]

候选限定在同一冻结置换内；每槽只从 **同记录包、同群大小** 的模板列表选择。评价器再次校验包号、成员数、实际记录 UID 推导出的 group UID；并非只检查账号个数。非恒等置换的合成手算提供了定向核验回执。[E03：`validate_pair()`；E08]

### 4.3 高阶交叠确实被保持

对当前要替换的槽，`select_slots()` 为每个候选成员构造位掩码，记录其属于其余哪些槽；然后比较整个候选群的位掩码多重集。若两个多重集相同，则它们与任意其他槽子集的交集基数均相同，包含三重及以上交叠，不只是两两交集。[E02：`select_slots()` 内的 `masks`、`signature()`]

每次只改变一槽且保持上述量，顺序执行后仍保持整体交叠结构。评价器另以 `incidence()` 对最终成员所属槽位模式做 Counter 比较。旧市场与当期市场账号属于不同命名空间，旧槽不参加当期账号的交叠计算是正确的；旧槽内容保持其自身存活群。[E03：`incidence()`、`validate_pair()`]

### 4.4 严格提高、去重和并列规则正确

`covered` 是其余槽已覆盖的有向边集合；当前候选只获得尚未覆盖边的权重。多群覆盖同一条有向边只计一次。`occupied` 排除其他槽已经使用的模板；最终又核查六个不同索引和六个不同 UID。[E02：`select_slots()`、`objective()`、`select_market()`]

候选只有在 `score > value` 时才更新。因而原槽与最优同分时保留原槽；优于原槽且同为最高分的多个候选取模板列表中先出现者。槽 0 到槽 5 各处理一次，是顺序贪心；不保证六槽组合全局最优。合同和报告没有把它冒称全局最优。[E01 第2项；E02：`select_slots()`]

每次冻结还检查目标值不下降，并检查“发生替换”与“总目标严格提高”等价。AlphaBay 3,000 次布局中 2,998 次提高的是 **fit 预测边权目标**，不代表有 2,998 次改善历史遗忘事件覆盖，更不代表模型改善。[E02：`select_market()`；E05：`stats`]

### 4.5 旧域群只沿本次、本臂、同一槽位存活

AlphaBay 阶段为每次抽样保存原对照 `baseline`、本策略实际 `ids/groups` 及 RNG。进入 Dream 时，以原 baseline 维持相同淘汰位置；对未被淘汰的旧槽，复制本次抽样、本策略、同一槽的实际旧群。评价器再次检查上阶段该槽的索引和 UID。未见从别的抽样借群、从上域全池重新挑旧群或把已经淘汰的群复活的路径。[E02：`select_market()`；E03：`validate_pair()`]

`cover()` 使用后续阶段的实际槽数组计算进入 Agora 前的留存，并断言 `pre_agora ⊆ exit ⊆ pool`。Dream 出域就是进入 Agora 前，不额外伪造一个独立留存时点。[E03：`cover()`；E01 第4项]

## 六、问题四：六格、跨 seed 合计、净差分布与预定门复核

### 6.1 独立算术方法

我直接解析 `summary.json`，使用整数及十进制简单算术检查全部 **27 套 tally**：三个 AlphaBay seed × 三子集 × 两时点，以及三个 Dream seed × 三子集 × 一时点。没有调用附件的评价函数。[E06]

逐套复核：

1. `both + only_uniform + only_priority + neither = 1000 × events`。
2. `uniform = both + only_uniform`，`priority = both + only_priority`。
3. `net = priority − uniform = only_priority − only_uniform`。
4. 每个 `means` 等于对应整数 `totals / 1000`。
5. `net_histogram` 频数之和为 1000，加权和等于整数 `net`。
6. `all = original_miss + original_reachable`，对事件数、猜中数、池均值，以及各时点所有 `totals` 和 `means` 字段成立；不同子集的净差直方图不能直接相加。
7. AlphaBay 两臂的留存总量及猜中留存总量不高于对应出域量；猜中覆盖不高于总覆盖，出域覆盖不高于池可达量。

以上全部通过。它们验证已保存聚合的内部一致性；不能从边际计数恢复未提供的逐布局布尔矩阵，也不能重新推导每一个原事件身份。池可达字段仅保存均值，表中相应累计量由其精确到 0.001 的均值乘以 1000 恢复；不冒称另读了未附的池整数原表。

`37 + 2×3 − 38 = 5`，故均值净增 `5/1000=0.005`。

## 七、问题五：准确猜到、带出域、跨域保住与训练效果

### 7.1 当前证据支持到哪一层

**可以接受的表述：** 所示实现以方向及竞争者身份严格一致的历史事件为对象，匿名汇总记录了非零的“准确预测∩出域同群”和“准确预测∩进入 Agora 前仍同群”交集；配对比较还显示 AlphaBay 原漏覆盖有小幅正向净增。[E02][E03][E06]

这里的“具体”指实现匹配的对象是精确 `(q,j)`，不是模糊主题相似度或任意对手。但外审没有真实 q、j 名册和逐事件分布，因此不能点名确认是哪几个账号，也不能声称已经逐个核验5个AlphaBay事件或3个Dream事件的实际留存。

特别是，A51 猜中2个事件、准确预测出域累计10次／留存累计7次；A53 猜中2个事件、出域和留存各累计2次。这些累计可能集中在其中一个事件。**不能据此断言全部5个猜中事件都至少被带走一次，更不能断言5个全都跨域保住。** 在所示实现与匿名回执成立的层级，每个AlphaBay seed准确预测且留存交集均非零，足以支持各seed存在这类交集事件；无法由聚合恢复其唯一事件数量。[E06]

### 7.2 保留的是 fit 账号对的同群机会

原历史事件来自 dev 查询；原评分规则要求 dev与fit账号同序，但查询记录与fit参考记录不重叠。此次写入Memory的是对应账号的fit记录包，不是原dev查询文本。所谓“带出”“跨域保住”，准确含义是对应账号对的fit记录仍共同出现在该臂实际保留的群中。[E04：`load_role()` 与 `score` 摘录、`materialize()`]

它不等于保住模型原来的第一名预测、参数能力或训练后排序表现。即使某对确实同群，回放如何改变梯度、是否足以修复该事件、是否伤害新域，都没有本次新分数可回答。

### 7.3 本轮不能证明的效果

本轮没有新模型分数、训练后指标或Full/ER实际消费证据，因此不能证明：

- 训练后遗忘减少、旧域最终能力提高或新域学习受到保护。
- Full相对ER有效，或出生评分保持、回放机制、其他组件已有新增贡献。
- 该词面信号在新的数据、未见身份、未来域或独立seed上有效。
- 同账号dev/fit监督事件已经变成真实跨账号同控马甲关系真值。

这些结论缺少相应观察量，不是用统计显著性措辞可以补齐的。现有1,000次布局只描述固定开发事件在不同布局及写入槽中的覆盖，不提供1,000个独立训练seed。三个seed也可能包含重复查询账号；本次没有开放确认集。[E01][E03][E04][E06][E07]
