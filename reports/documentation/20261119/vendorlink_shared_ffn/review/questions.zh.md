# 共享前馈层接线与合成 CPU 回执增量审查

请审查这次改动的实现、CPU 实测和结论边界。应用是用同一观察账号的不同商品文本做检索。每次评价在一个阶段的状态下重新编码该市场的双记录查询、12 记录参考，再经过共享关系头进行记录级匹配与账号聚合。两个后续市场原来只能训练本市场的 Q/V 增量和关系头。原四组开发结果的关键数值已写在范围说明。本次获准的输入是虚构文具文本及官方预训练。

1. 对照训练的真实入口与恢复路径，检查 AlphaBay 的训练方式，及 Dream/Agora 更新的两层前馈、当期增量、共享关系头。特别检查旧市场路由、冻结范围、阶段间 Adam 状态与反向重算。
2. 分别跟踪 ER 旧标签和 Full 出生教师损失，判断实测能否识别切断共享前馈梯度、误把旧群送进当期增量，或用 AdamW 衰减冒充历史监督作用。
3. 检查当前前馈参数、历史记忆和阶段评分副本的用途。阶段 0 至 3 的评分能否恢复正确的编码器和关系头，使 Q2、FIT12 及最终矩阵都能复现？1 MiB 数字实际覆盖了哪些状态与样例？
4. 判断这批合成 CPU 证据足以支持哪些接线结论，仍须 CUDA 短测覆盖哪些影响执行的缺口。是否存在正式训练之前的具体阻断？请给出文件、调用或回执字段以及复现条件，区分必修事项与可选建议。真实市场效果与开训留给后续决策。
