一、这次决定推进什么

用户在澄清 R0、S、C 的角色后，要求围绕三件事执行：C 比 S 多使用什么有效历史信息；原保持方式为何未转化为收益；一个新机制如何针对有依据的缺口。用户引用的安排是“保留 S 的有效结构和训练方式，以 S 为主要内部对照，先形成一份针对 C 历史保持机制的实质改进方案”，随后问“那你看看怎么执行”。

据此继续文献、实际源码和已开放证据阅读、数学推导、手算及方案整理。当前没有新的算法、数据读取、CPU/GPU科研计算或上传包许可。这不妨碍完成设计工作，也不把上一轮已结束的训练预算移给新研究。S 是本研究构造的内部方法，同时作为强对照；不能从“S 是我们提出的”推导“现在改以 S 为最终论文主体”。C_plus 固定配置负结果和撤下状态保留。

本轮交付是这一份可讨论的执行工作稿及静态排除结果，不是新算法已经设计成功。后续具体机制若仍没有实质依据，应报告未形成候选或停止该具体方向；不能用损失换名、增加模块或反复试参充当完成。

二、必须保持的比较基础

S 的中文 BAAI/bge-large-zh-v1.5、记录表示与记录对头、A0/A1 监督、0.1 历史监督、0.5 A0 历史评分保持、合法六群 Algorithm R／全部历史状态≤1MiB、数值设置和共同过拟合诊断，作为后续设计比较的明确基准。若新方案确需改变其中某项，主动披露并说明比较含义；不削弱 S 来制造优势。

原 C/S 共享来源时的瞬时目标为：
  J_S = Bbar(current) + 0.1 Bbar(history) + 0.5 D0；
  J_C = Bbar(current) + 0.1 Bbar(history) + 0.25 D0 + 0.25 D1。
D0 是原账号分组下当前分数与该群历史分数的均方差；D1 是同控重分配后的同类误差。它们使用同一种完整历史记录对得分表，而非两套预训练模型。两臂后续各有自己的训练轨迹和新出生历史表，不能把同状态公式当作全程逐步相同的比较。

已有证据：原 C−S 的 O MAP 差为 −0.000138641，条件区间跨零；C_plus 恢复完整 0.5D0 再加 0.25D1 后，仍未建立相对 S 的 O MAP 增益，并有 N/Z 损失。因此“只把被分走的 D0 权重补回来”已经在该固定配置下试过，不能再次作为首选解释和改进。三臂 S−R0 的 O/N MAP 约 +0.016436／+0.015999，说明重组监督整条训练策略有收益，不证明 D1 有收益。历史五项／23项判据及 LOGIT R1 边界不变。[E1–E4]

三、第一件事已经推进到哪里：额外信息的准确位置

以下为根据实际 account_logits／objective 的静态推导，不是新数据计算，也不是原创性主张。

固定一个存活群及一次学生随机前向。将所有无序非对角记录对分数记作 k，历史表记作 t，差为 e=k−t。L_A 是按账号记录数归一化、将记录对表汇总为378个账号对分数的线性映射。则
  D_A = ||L_A e||² / m，m=378。

1. C/S 保存的历史对象种类相同，使用的查询不同。
S 的历史评分约束只直接约束 L_0 e；C 还约束 L_1 e。原账号之间同一个记录块内部，各记录对分数上升和下降可以互相抵消，不改变原账号总分；原本在同一账号内的记录对不进入 A0 的账号间分数。重新分配能使其中一部分变化重新可见。S 仍有 A1 标签监督，所以不能把这些方向说成 S 完全没有学习或完全没有约束。

数学上，L_0 的各行作用在互不重叠的原账号间记录块上，且每行非零。令
  P_0 = L_0^T (L_0 L_0^T)^−1 L_0。
它把每个原账号间记录块替换为块均值，同账号内部的位置投影为0。于是
  L_1 e = L_1 P_0 e + L_1 (I−P_0)e。
后一项是 A0 输出不能直接看见的部分，但 D1 同时含前一项及两项的交叉项；不能把 D1 整体都叫独立新信息。这是表空间的分解，尚未证明相应方向在真实 BGE 参数空间可达或有利。

一个表空间手算：同控账号 x={1,2}、p={3,4}，另一个控制者的账号 n={5,6}。两张表仅在 Δ13=h、Δ14=−h 上不同，其他位置差0。A0 的所有账号对分数相同；改为 x={1,3}、p={2,4} 后，x−p 分数差 −h/4，x−n 差0。因此“正候选与负候选的分差”可以受到额外表信息影响。这个例子只证明能影响排序余量，既不证明哪张表正确，也不证明未见卖家受益；实际模型可达性还需另证。不能把它当作已完成神经网络核验。

2. 保持重组响应，不等于让响应对重组不变。
令 A 在合法同控均匀重分配中取值，Lbar=E_A L_A。在固定 k、t 的条件下，
  E_A D_A = ||Lbar e||²/m + E_A ||(L_A−Lbar)e||²/m。
这是均值—方差恒等分解。第二项要求学生的重组响应变化接近历史模型的变化；历史模型对组合敏感时，C 可以把这种敏感性一起保住。它没有直接要求学生所有重组得到同一分数。该式对 D1 的重组期望成立；原 C 的 D0 仍另占0.25，不能遗漏。若再对 Dropout 求期望，还包含相应随机前向影响，不能把训练残差全称确定性分配漂移。

3. “把重组旧评分全部平均”不能直接成为新核心。
对不同同控分量 c、d，设各自总记录数为 N_c、N_d，原账号 a 的记录数为 n_a。任取重组后的账号槽 i∈c、j∈d，由均匀分配及两个分量独立分配可得
  E_A s_ij(A)
    = [Σ_{r∈c,s∈d} K_rs]/(N_c N_d)
    = Σ_{a∈c,b∈d} [n_a n_b/(N_c N_d)] s_ab(A0)。
所以这部分均值已由原账号分数与计数确定。用它重新加权训练仍可能改变优化，但不能称新增历史信息。

同一分量内的两个不同账号槽则有
  E_A s_ij(A) = 2 Σ_{r<s, r,s∈c} K_rs / [N_c(N_c−1)]。
它包含原账号内部记录对，不能一般地从 A0 账号间分数恢复。即便保留这部分新增均值，也只是保存更多同控记录作用，不自动建立未见身份收益或方法贡献。

这轮筛查把问题收窄为：A0 未直接约束的细粒度组合信息中，是否存在值得保持、能支持自然账号正负候选区分的部分？“更多查询”“缓存拟合更好”或“平均更平滑”都不足以回答。

四、第二件事怎么查：把三个解释分开，而不是先宣布根因

解释A：额外约束主要重复已有约束。
需要辨别 L1 的作用中哪些已由 L0 覆盖，哪些落在原分组不可见部分，并检查后者是否影响正确的正负次序。上面的分解提供定义；单个 D0、D1 大小或残差交叉均值不提供参数梯度角度，也不提供泛化证据。

解释B：历史重组分数没有足够可靠的任务信息。
已知二值训练标签保证同控重组后的关系标签，不能保证历史模型给出的连续分数正确。生成器在每个账号的逐记录循环外确定样式；混合同控不同账号的记录可以产生原生成机制不产生的账号样式组合。这个支持集差异来自已读生成器源码，不是对正式数据频率或模型捷径的实测判断。S 的有效结果说明标签监督增强有价值，仍不能证明旧模型在这些输入上的每一个数值都值得保留。[E5]

若未来确有必要读取旧 Memory，只能在新明确范围下检查缓存历史表、合法 fit 标签及规定重组的排序正确性／变化；这种结果最多说明缓存内教师行为，不能测旧分布未见身份，也不能凭它选全研究最有利的群。当前未申请、未解析 Memory。完整 Memory 保管并非分析或重新训练许可。

解释C：约束妨碍新学习。
在同一参数、同一随机前向及同一历史表下，
  ∇θ(J_C−J_S) = [J_k^T (L1^T L1−L0^T L0)e]/(2m)。
这明确了原干预同时改变原分组保护与重组保护。真正的更新还经过共同裁剪和有历史状态的 AdamW；不能把损失差、上式单步梯度或一次余弦当作整个训练的根因。

现有诊断 capture 临时计算 live 表，但最终保存的是四项残差摘要、fit/cache 指标和 valid 盲分数，没有保存完整历史分支逐步参数梯度或任意重组下的 live 表。三臂和原 C/S／五臂权重已按许可删除。这意味着不能靠现有归档凭空补出历史梯度因果诊断，也不应为了给旧实验强行定根因而全面重训。[E6–E7]

未来仅在具体候选需要时，在新批准的小核验中用相同 model/Adam/RNG 作分支更新：记录该项的实际更新作用、旧记忆排序与当前监督变化，检查移除该项是否消除预期作用。若要声称对未见卖家有效，仍需后续完整开发比较。诊断只做决定候选去留所必要的部分，不把三个假说扩成三组大实验。

五、第三件事怎样形成单候选

优先研究的问题是：能否从允许的历史状态中，识别并保留对自然账号的正负排序有意义、又未被 S 的历史约束充分表达的细粒度作用，同时允许与任务无关的分数变化？这是待推导问题，不是已经命名的新算法。

候选形成前必须完成以下实质内容：
（1）明确历史量来自哪批合法输入、何时生成、存活时是否刷新、逐出时删除什么；不悄悄扩大历史覆盖或选择机会。
（2）给出从这个量到目标／更新的完整运算，包括编码器、记录对头、梯度链、裁剪／Adam、首阶段、恢复和推理；不能只给“可靠性权重”或“选择算子”的符号而不定义算法。
（3）说明它与未见身份相关所需的假设，及这些假设为何比“所有同控记录可交换”更有依据。当前生成机制不支持后一假设作为无条件事实。
（4）主动检验是否只剩已知排序蒸馏、缓存比较或普通鲁棒重放的直接适配。若是，按用户原要求否决为实质贡献不足，不换名推荐。
（5）给出可推翻其作用的手算／移除机制反例，以及完整 S 对照下应出现什么变化、什么结果会否定推荐。

本轮已排除的直接答案：再次加大 D1；只恢复原0.5D0；只蒸馏全部重组平均；把 MSE 换成排序项或置信度过滤就称新方法。它们分别遇到已发生负结果、信息重复或直接近邻重叠。这里不宣判相应方法家族在所有任务无效。

尚未解决的关键缺口是“为什么保留的额外细节可迁移到未见身份”。目前不能据已完成推导推荐一个具体新 C 进入训练，也没有宣布 C 路线永远无效。若下一份具体机制仍只能以更多缓存约束或常规损失拼接解释价值，应停止该改进提案并向用户重新讨论方法定位，而非默认生成下一个训练候选。

六、形成候选以后的最小执行顺序

1. 先向用户提交一份完整单候选方案，附近邻对照、最小核验和预算／读取草案。不同语义的未决选择才询问；日常实现细节不重复确认。新实质方案按科研纪律第6节送指定本地 Playwright MCP 网页外审，具体包先准备好、按已有许可覆盖范围补充上传确认；本工作稿未上传，也不把旧包许可扩大。

2. 用户批准相应实现与手写核验范围后，在 Linux 既有 py310 做最小 CPU 核验。使用独立手算／直接图，证明新操作实际产生预期梯度；移除它、改变关键历史信息或故意断开其梯度应让核验失败。已有未变部分的核验与数值设置复用，不另造通用测试框架。

3. 必要的手写真实 BGE/GPU 核验只查受影响路径、一次真实更新、峰值和时间。候选需要 Adam 历史状态时不能只测新鲜优化器。它只能证明计算接通及资源可行，不证明效果。新预算先明确，超限或无恢复条款的失败停下；不继承已结束的72小时额度。

4. 效果比较首先回答“完整 S 与一个固定新候选，谁的旧域未见身份排序更好、代价是什么”。旧 C、C_plus 与 LOGIT 已审结果作背景；跨运行比较不作为新增机制净效应。初轮不默认重训 LOGIT/R0 或恢复五臂。确需一个去掉新信息的机制对照时，必须在具体算法形成后定义它，确认保留监督、训练机会和合理强度；不能先造一个故意劣化的教师当对照。

如新机制仅作用历史保持，三顺序可在同一新训练的 S 首阶段 model/Adam/RNG/Memory 后分支。两臂、三顺序、每阶段288更新的纸面工作量为3×288＋2×3×2×288=4,320更新；若前瞻增加一个同起点机制对照，则为6,048。只是规划算式，不是批准数量或资源承诺。若机制改变首阶段，应各自完整训练并重新算量，不能假称起点可共享。不能把已删阶段权重或旧三份不同架构共享起点当成可直接加载的 S 首阶段。

5. 评价以最终旧域 O MAP 和 final_all 为核心，完整报告 N/A2/Z、原22指标、逐域、校准／阈值代价及共同过拟合诊断。原五项／23项历史验收保留；新幅度与停止规则须在开放结果前按问题固定，不从已有差值倒推。三个顺序不是三种子，反复使用的 valid 继续标作开发集。盲存、统一开放、失败记账沿新合同落实，不借诊断增加中途调参。

6. 若只有缓存误差改善而未见群不改善，不能称解决研究问题；若只有对 LOGIT 有效但相对完整 S 无增量，不能将共同结构／监督收益记到 C 新机制；若代价超前瞻接受范围或增量方向未确定，如实判定失败或证据不足，结束该固定候选，不自动加权、换种子或放宽门。多种子及独立最终确认属于有价值候选之后另定范围。
