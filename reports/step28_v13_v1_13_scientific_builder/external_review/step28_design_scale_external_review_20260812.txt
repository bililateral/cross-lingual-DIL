Medium
Medium 1：500/500 明显降低规模选择自由度，但修订件尚未精确冻结“误拒率”的解释边界
具体原因

直接事前固定：

train       500 worlds
development 500 worlds
audit_a       2 worlds
audit_b       2 worlds

比先生成多个规模、比较结果后选择 50/100/200/500 中的一个严谨得多。它采用原科学合同已经冻结的正式每拆分 500-world 统计单位，不把 v7 数据、v7 随机权威或简化模拟用于挑选一个经验上更容易过门的规模。修订件还明确禁止多盐、预览多个候选根、按质量分数换盐或定向重编号，因此没有保留明显的规模／随机权威选择自由度。

但“500 世界”只能合理预期降低有限样本波动，不能单独证明：

67 个元数据特征取最大后的家族误拒概率是多少；

七视图、十四模型取最大后的误拒概率是多少；

0.52/0.53/0.01/0.015 构成了某种已校准的家族显著性水平。

这些门更准确的性质是冻结效应量筛选门，而不是已经证明控制在某个 α 水平的假设检验。修订件目前说明 500 消除了额外规模选择自由度，但还没有明确写出这一统计解释边界。

可执行修复

在机器策略和方法文档中增加：

quality_gate_interpretation:
  deterministic_effect_size_screen: true
  familywise_type_i_error_claimed: false
  scale_selected_from_v8_results: false
  v7_or_simulation_pooled_into_v8_result: false

并在生成前做一次不使用任何 v8 数据、随机权威、候选根或真实盐的零信号操作特征检查。它可以使用精确的：

500-world cardinality；

378/372 行结构；

67 特征和 14 模型家族大小；

固定标签比例；

独立、卖家共享和世界共享等若干预注册相关性情形。

该检查只报告门在典型零信号条件下的误拒敏感性，不得据结果选择 50/100/200/500，不得改本轮阈值，也不得生成多个真实数据盐。如果该无数据检查揭示门几乎必然误拒，应在生成数据之前停止并重新审查，而不能靠不断生成数据寻找 PASS。

必须增加的测试／证据

证明零信号检查不调用数据构建器；

不读取 v7 回执以外的任何已删除数据；

不产生或消费 v8 随机权威；

输出只作方法诊断，不影响冻结规模、阈值或盐；

v8 最终报告不得把 500-world 选择表述为“已证明控制家族误拒率”。

Medium 2：流式 bootstrap 的科学目标正确，但批次、随机流和内存上界仍需机器化冻结
具体原因

修订件要求 9,999 次按世界有放回重抽样与逐行重复世界完全等价，同时改用固定小批次流式实现，禁止构造随“开发行数×世界数”增长的巨大稠密张量。这一方向正确，也不会改变统计估计目标。

STEP28_V13_V1_13_QUALITY_AUDIT_…

但实施前还需冻结：

bootstrap_batch_size 的具体整数；

PCG64 随机整数流的平铺和 reshape 顺序；

dtype、endpoint、世界 ordinal 顺序；

最后不足一个完整批次时的处理；

每批先计算每个模型，再取该 replicate 的十四模型最大值；

9,999 个精确 replicate 最大值全部保留后，再执行 quantile(method="linear")；

禁止近似流式分位数算法。

否则两个实现都可以自称“小批次流式”，却因 RNG 调用形状、批次边界或近似分位数产生不同上界。

可执行修复

机器策略增加类似：

bootstrap_streaming:
  batch_size: <事前固定整数>
  draw_layout: replicate_major_c_order
  world_index_dtype: int64
  rng_calls_independent_of_batch_boundary: true
  exact_quantile_values_retained: 9999
  approximate_quantile_forbidden: true
  replicate_refit_forbidden: true

每个 replicate 应以世界 multiplicity 计算并列感知的加权 AUC/AP；不得通过 np.repeat 展开约 189,000 行，也不得构造：

9999 × 189000
9999 × 500 × 378
batch × full_row_count

一类矩阵。

必须增加的行为测试

小样本流式结果与逐行展开在全部 9,999 replicate 上逐位一致，而不只比较最终分位数。

固定同一 draw stream 时，批次大小为 1、策略批次、非整除批次和 9999 时结果一致。

500-world synthetic fixture 上与非流式加权参考逐位一致。

覆盖大量并列分数、全常量分数、相同 AUC 不同 AP、不同 AUC 最大模型等情形。

验证每次先取十四模型最大值，而不是先求各模型 95% 分位数再取最大。

在独立子进程测量峰值 RSS；不能只用 tracemalloc，因为它可能漏掉 NumPy 原生内存。

策略冻结明确的峰值辅助内存上限，且改变开发行数时辅助内存不得按 replicates × rows 增长。

批次边界、世界顺序或 RNG layout 任一变化都必须触发合同失败。

Medium 3：失败回执方向正确，但“模型最大项”必须拆成两个不同赢家并冻结并列规则
具体原因

修订件要求元数据和文本各保留五道硬门的布尔值、最大项名称与数值、模型最大点估计与名称及两个 bootstrap 上界，同时禁止保存逐行分数、标签、预测或大矩阵。这个边界基本正确。

但每个家族的五道门实际上是：

最大单特征对称 ROC-AUC；

最大模型对称 ROC-AUC；

最大模型 AP uplift；

bootstrap 模型家族最大 AUC 的 95% 上界；

bootstrap 模型家族最大 AP uplift 的 95% 上界。

第 2 项和第 3 项的赢家可能不是同一个模型。“模型最大点估计及名称”若只有一组字段，会丢失其中一道门的根因。多个特征或模型恰好并列时，也需要确定性规则。

必须增加的测试

AUC 赢家与 AP 赢家不同；

多个特征完全并列；

第十四个模型是唯一赢家；

最大值只超出一个门；

改变任一标量、名称、阈值或 tie 信息后，回执自哈希和验证必须失败。

Medium 4：“一套数据、一个随机权威”原则正确，但执行错误后的重试语义需要事前写死
具体原因

修订件已经明确只生成一套 v8 数据，不试盐、不预览多个候选根，不按质量结果换盐。它也区分构建／审计器执行错误与预注册数据门失败。

STEP28_V13_V1_13_QUALITY_AUDIT_…

尚需明确的是：如果出现代码、依赖、内存或写盘错误，修复后允许怎样继续。若每次执行错误都可以重新产生一套新公开随机权威，就会重新引入隐藏多盐自由度。

可执行修复

在任何数据生成前公开冻结：

v8_random_authority_commitment
v8_world_count = 1004
attempt_index = 1
alternate_authority_forbidden = true

并规定：

审计器执行失败、数据根已完整提交：保留同一数据根；修复审计器后只能对同一字节重新审查，不能重新生成。

构建执行失败、未形成完整根：修复构建器后只能使用同一公开随机权威确定性重建同一目标数据；不得产生新盐。

数据质量门失败：版本永久结束，删除失败载荷；不得以相同 v8 名义重新生成。

任何代码修复都需要新实现字节和新运行前外审，但不得改变已冻结随机权威。

必须增加的测试

执行失败后申请第二套 authority 必须关闭；

相同 authority 的两次确定性构建必须逐字节一致；

审计器执行失败不得删除已完整提交的数据根；

统计门失败不得走“执行失败重试”路径；

v8 数据质量失败后不得再创建 v8_attempt_2、v8_alt_salt 或同义输出根。

A–G 逐项裁定
A. 是否存在结果驱动规模选择

当前方案比候选规模选择严谨，且可以接受。

500/500 是在任何 v8 数据生成前固定，并直接来自既有正式合同的每拆分规模。v7 结果和简化模拟影响了“需要修订设计规模”的认识，但没有被用来在多个 v8 真实数据规模之间选择最容易过门者。只要严格执行单 authority、单数据根、无 fallback，便不构成新的结果驱动选择。

STEP28_V13_V1_13_QUALITY_AUDIT_…

必须禁止的后续行为包括：

500 失败后回到 200；

500 构建困难便降到 100；

重编号或换盐；

将 v7 与 v8 合并报告；

把 v7 当作 500-world 方案的先导样本。

B. 500/500 是否解决 v7 小样本不稳定

它显著改善并消除规模错配，但不等于形式化证明误拒率。

它使质量门的训练／开发统计单位与未来正式拆分一致，是当前最少自由度的规模选择。不能再声称 50-world 结果代表正式 500-world 门的稳定性。

但应把门解释为冻结效应量筛选，并补充上述不使用真实盐的操作特征说明。无需、也不应生成多个真实数据盐来估计误拒率。

C. audit A/B 各 2 世界

合理。

它们不是性能样本，不拟合模型、不计算监督性能、不影响质量门数值。2 个世界足以执行 split-specific 路径、文件、字面和盲化调用链测试；它们不能证明未来 500-world 审核性能，也不能用于任何性能区间。

D. 阈值不变与流式 bootstrap

科学估计目标可以完全等价。

前提是：

随机 draw sequence 不因批次变化；

世界 multiplicity 与逐行重复严格等价；

每 replicate 内先取完整模型家族最大值；

最终分位数仍是完整 9,999 值上的精确 linear 分位数；

不采用近似 quantile；

有明确的 500-world 内存上界测试。

满足这些条件，流式只是计算实现变化，不是统计方法变化。

E. 最小失败回执

修订方向正确。

应保留门级标量、赢家名称、阈值、布尔结果、计数、随机与顺序 commitments、完整结果哈希和失败分类；不保存逐行分数、标签、预测或大矩阵。

最重要的修订是分别记录 AUC 模型赢家和 AP 模型赢家，不能合并成一个“最大模型”。

F. 是否修改 UID 或空白字符机制

当前不应修改。

v7 的 absdiff__seller_uid_digest_02=0.522011... 是冻结 67 项家族最大值中的一个事后赢家。它足以触发既定数据失败，却不足以独立证明 UID 生成器与控制者存在确定性因果耦合。

同理，旧回执没有保存具体文本失败门，不能把描述空白字符认定为充分原因。现在修改 UID 或空白会构成基于失败结果的定向生成器调整，并可能删除合法作者风格信号。修订件规定只有出现生成器级因果反例才允许修改，是正确的。

未来可以构成因果反例的证据应是：

代码调用链或密钥复用证明；

固定输入下只改变该机制便确定性改变标签相关性；

不读取 v8 质量分数即可复现的机制级测试。

单次最大 AUC、赢家名称或相关性图不足以构成该证据。

G. 是否存在 Blocker/High

没有。

当前修订件：

事前固定单一规模；

使用全新且唯一的设计随机权威；

不试盐、不重编号；

不改变冻结质量门；

不让审核甲乙进入监督路径；

保留 v7 失败而不夸大其因果解释；

不根据失败结果清洗 UID 或空白；

明确 v8 通过也不授权正式数据或训练。

这些原则没有破坏数据质量、统计有效性、盲化隔离或可复现性的 Blocker/High。

已独立认可的设计事实

v7 仍永久失效。 0.522011...>0.52 足以执行原合同，但不能升级为“确定性编号泄漏已证实”。

500/500 是预注册规模，不是候选规模竞赛的赢家。

v8 不复用 v7 数据、登记表、随机权威、候选结果或质量结果。

单特征、模型点估计、AP uplift 和两个 bootstrap 上界的阈值全部不变。

67 项元数据、F/P/U 七视图和十四模型全部保留。

AP 基线在世界数改变后仍是 20/378 和 20/372，因为每世界类别比例没有变化。

审核甲乙没有质量门性能角色。

流式计算可以保持统计量完全不变；它不能使用近似分位数或改变随机流。

失败回执增加门级诊断是对 v7 证据不足的正当修复，不是放宽质量门。

不修改 UID 和空白机制是当前避免事后生成器过拟合的正确决定。

即使 v8 最终通过，也只能进入“讨论正式生成”的下一次合同修订，不能直接生成正式数据或训练模型。 修订件自身明确要求在质量门完成后自动暂停。
