## 输入形状与数值边界

复用Group.validate的28账号、每账号2—8记录，完整群最多224记录；标题和描述分别编码，共448段，每段含特殊token≤256，不截断。先按账号顺序/账号内记录UID顺序取全部标题，再同顺序取全部描述；连续4段一个微批，padding到该微批最长，不做长度排序或额外去重。最大核验群每账号8记录、两个通道均256 token，112个微批。手写小模型可用更短文本，但不能提供最大形状资源结论。正式输入遇到规格外形状须停止，不能删记录适配。

模型主参数/梯度/Adam为FP32；只有BGE前向处于CUDA BF16 autocast。记录归一化、均值/总体标准差、账号归一化、关系头和当前群评分在关闭autocast的FP32中；历史p、K、v及二次式在FP64中计算，保持已核验代码的舍入位置。规范z是该路径产生的FP32 32×378矩阵；参考保存同字节FP32，从此z转FP64构造H/b和求解，不重新在FP64编码。历史目标通过dtype转换反传。CPU小例以FP64独立核对运算；CPU小编码器路径FP32。旧参考和统计停止梯度，当前z和w的全部路径保留。

编码器与头train，torch Dropout概率以及BGE隐藏/注意力Dropout设0，加载后检查具体模块和配置；原生非重入检查点开启且需实际证据。参考前向也是train、相同微批/模式，仅no_grad。原生同参数参考与带图z容差预定atol=1e-5、rtol=1e-4；超过则停止调查，不放宽过关。CPU独立公式FP64 atol=1e-10/rtol=1e-9，有限差分atol=2e-7/rtol=2e-5，CPU串行/联合FP32梯度及更新atol=2e-6/rtol=2e-4。
