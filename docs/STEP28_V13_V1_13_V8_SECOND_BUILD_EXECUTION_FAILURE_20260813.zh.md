## 精确根因

同一固定权威的内存重放仅检查已经暴露的训练集序号 0 至 29。前 29 个世界
均已按实际顺序接受，其中候选 0 接受 27 个、候选 1 接受 2 个；累计当前数据
商品文档、卖家文档和身份值登记数分别为 2,805、812 和 2,436。

目标世界的 32 个候选均且仅命中 `historical_item_document`，每个候选恰有
一个历史商品文档交集；历史卖家、当前数据商品／卖家、同世界商品／卖家交集
均为零。32 个候选共同碰撞的唯一历史商品文档摘要为：

```text
1b27758b380e57e90baf967db68a319540ea7909581d96aab7b4c4953ac03082
```

该摘要只属于永久失败的 v1.12 历史排除，不属于成功的 v1.2。对应商品在
32 个候选中的品类、商品名、属性、配送句、服务句、标题模板、描述模板、
标题、基础描述和噪声句全部只有一个取值，最终可见商品文档也只有一个取值。
因此增加候选次数不可能避开碰撞。

结构原因是 v8 为保持跨作者风格的画像谱系，把可见词表按渲染响应进一步细分，
但标题修饰语虽在受限安全词表中，却仍由固定商品代码直接选择，没有进入候选键
驱动的安全置换。失败商品的其他可变域恰好全部落入单例类，形成候选不变的完整
商品文档。此前孤立训练世界 69 的回归没有带入前序世界累计登记表，也没有覆盖
这种历史排除中的候选不变文档，因而不足以保证顺序构建闭合。
