# Step28-v13 v1.12 可见文本捷径与反事实审计合同

## 1. 状态与结论边界

本文冻结正式密钥生成前的设计级文本捷径审计。当前仅授权修改设计草案、实现审计程序、增加测试并运行使用设计密钥的训练集／开发集预检；正式密钥生成、正式数据生成、模型训练和审核集真值解封继续保持关闭。预检通过只能说明审计机制可进入最终冻结，不能写成正式数据或科研结果成功。

## 2. 要回答的问题

原始五字段文本中的作者风格是冻结英文基底模型的合法输入，因此原始文本攻击只作描述。正式硬门回答的是：在切断“控制者系统性共享风格”后，除预先登记、按设计就携带可见负例语义的机制外，公开五字段文本是否仍能预测同一控制者标签。

## 3. 控制者盲的卖家风格错排

每个世界对 28 个卖家的原始有效风格做一次全局一一错排。映射构造器只允许读取固定公开域、拆分名、`world_uid` 和按 UTF-8 字节序排列的卖家编号集合；禁止读取控制者、样本对、标签、机制、33 项身份特征、基础风格编号和任何风格值。

错排公开域固定为 ASCII 字节 `step28-v13-v1.12-visible-style-counterfactual-derangement-v1`。卖家编号先按 UTF-8 字节序排列，再逐项编码为“四字节无符号大端长度＋UTF-8 正文”；尝试计数编码为四字节无符号大端整数。每次尝试的种子为公开域、拆分 ASCII、`world_uid` UTF-8、卖家集合编码和尝试计数按冻结的 `0x1f` 分隔后所得 SHA-256。每个尝试使用独立计数器流；区块计数从零开始，编码为八字节无符号大端整数，区块为 `SHA256(attempt_seed || block_counter)`，并把完整 32 字节解释为无符号大端 256 位整数。

`randbelow(m)` 令 `limit = 2^256 - (2^256 mod m)`，拒绝不小于 `limit` 的区块，接受后返回该整数对 `m` 的余数。Fisher–Yates 固定按 `i=27,...,1` 执行，每步调用一次成功的 `randbelow(i+1)`。每次候选洗牌因此均匀；仅当完整候选存在固定点时递增尝试计数并重试，最多尝试 1024 次。该拒绝条件不得查看任何私有关系或攻击结果，耗尽后只能关闭失败，不能换公开域。输出必须满足：28 对 28、一一双射、来源集合与目标集合完全相同、固定点为零、相同输入逐字节重放一致。允许来源控制者偶然等于目标控制者，也允许同一正例的两端偶然取得相同基础风格；这类随机重合不得被构造器排除。

每个世界只生成一套反事实文本。训练集和开发集各 500 个世界，因此共有 1000 个独立的世界级错排；不得增加多套反事实后选择有利结果。

## 4. 反事实重渲染闭包

唯一干预是：目标卖家的有效风格改为其映射来源卖家的原始有效风格。世界编号、卖家／商品编号、市场、时间、类别、商品、属性、标题与描述骨架、商品码、商品数量、缺失状态、噪声槽、登记覆盖、样本对、标签和 33 项身份特征必须保持不变，不重新抽取任何随机量。

反事实重渲染必须先形成完整的原始可观测世界，禁止直接由私有抽象语法树拼出五字段攻击输入。以原世界经过高语义覆盖后的抽象语法树非风格字段为权威输入，只替换有效风格六元组。高语义目标原有的类别、商品、属性、标题骨架、描述骨架、商品码、配送和服务字段原样复用；不得重跑覆盖对象、商品、主题或骨架选择，也不得根据反事实文本重新执行原词汇接受门。全部反事实基础标题完成后，按原 `registered_override_audit` 的来源、目标和方向重新取得反事实标题快照并逐字节施加完全标题克隆。

随后逐商品复用原噪声表面值、身份值、角色、槽成员关系、槽编号及槽顺序，以同一商品编号重新运行生产描述渲染器和上下文护栏选择。基础文本长度改变时，身份和噪声字符偏移必须按反事实原始文本重新计算；原偏移数值不要求保持。完整反事实原始商品必须依次重跑生产解析器、解析器与私有计划逐行核对、生产脱敏登记、生产脱敏器、脱敏与私有计划逐行核对以及资料安全商品构建。任何额外解析行、缺失计划身份行、身份表面残留、噪声漂移或受保护内容冲突都关闭失败。

一个世界的全部 28 个反事实卖家和商品必须一次性交给相同的第三步 `build_world_profiles()`，重新计算该世界的专异性目录并完整定稿 28 份资料；禁止逐卖家打补丁。机器测试必须证明非风格渲染抽象语法树字段逐字段相等，键集合、标签、身份特征、噪声和覆盖登记均不变。仅用于重渲染闭包单元测试的恒等映射可以显式绕过正式错排固定点校验；它不得生成任何设计攻击行或质量证据，并且必须逐字节重现生产公开商品和五字段资料。

## 5. 映射自身的私有审计

私有控制者和风格信息只能在映射完成后评价结果，不能反馈到映射或更换公开域。逐卖家报告“来源控制者等于目标控制者”，另描述“来源基础风格等于目标原基础风格”和“来源有效风格六元组等于目标原六元组”；后两项只量化随机重合，不增加阈值，也不进入样本对曲线族。逐样本对报告：来源控制者相同、来源基础风格相同、来源有效风格完全相同、`separator`、`ending`、`line_mode`、`english_tag`、`traditional_variant`、`repeat_punctuation` 六项分别相同，以及六项相同比例。不得对这些类别或布尔因子计算无意义的绝对差。

均匀错排的解析零假设使用容斥精确计算。对固定目标端点和合法有序来源端点，剩余 26 个位置的无固定点完成数按其可固定位置数计算；不得把正负关系差强制为零。期望逐世界条件于实际 28 个卖家、实际控制者成员关系、实际控制者基础风格分配和 28 个原始有效风格六元组；唯一求和的随机量是控制者盲均匀错排，禁止用总体边际频率、风格因子独立假设或跨世界近似替代。训练集和开发集均报告观测值、解析期望和残差。开发集上，各直接关系作为独立分数的最大对称受试者工作特征曲线下面积不得超过 0.52；按世界进行 9999 次自助抽样后，整个关系族最大值的单侧 95% 上界不得超过 0.53。这里不再拟合分类器，也不新增事后显著性门。

## 6. 公开文本攻击

模型矩阵只能来自反事实后的五个公开字段：`category_concat_top`、`signature_title_concat`、`title_concat_top`、`signature_description_concat`、`description_concat_top`。样本端点只用于连接，编号字符串不得进入矩阵。

冻结三个视图：

1. 全文本视图：各字段及合并文本的字符三元组、词一元／二元相似度，加上长度、缺失、空白、换行和标点表面特征及近重复摘要；
2. 主题视图：只使用公开类别字段及其确定性统计；
3. 模板表面视图：对公开标题／描述逐字符把 Unicode 字母替换为“字”、数字替换为“数”，保留标点、空白、换行和字段边界，再计算冻结相似度与表面统计。

每个视图只训练固定二范数逻辑回归和固定浅层梯度树。只在设计训练集拟合；训练集按世界分组的五折交叉验证仅作求解和过拟合诊断；所有硬门只看世界完全隔离的设计开发集。

原始五字段文本另行执行纯描述攻击：每世界保留全部 378 对，在五个字段及其冻结分隔符合并文本上分别计算字符三元组和词一元／二元余弦，共 12 项直接分数。该分支不得拟合分类器、阈值或硬门。描述分层固定为 20 个正例、2 个完全标题克隆负例、4 个高语义相似负例和 352 个其他负例；六个登记负例仍须按“机制映射、资产序号、规范样本对编号”与覆盖审计逐行重放一致，不能只核对数量。

在第一次 500＋500 世界数值预检前，必须发布并自哈希一份机器可读的文本捷径攻击策略，逐项冻结：三个视图的特征名称与顺序、分词、向量化、大小写、归一化、空向量处理、字段顺序和分隔符、近重复摘要、Unicode 模板掩码类别；两个模型的全部超参数、求解器、收敛条件和随机状态；按世界的折叠分配；自助抽样种子、抽样算法和单侧 95% 分位数离散取值方法。任何参数依赖库默认值、运行期自动选择、未登记值或未解析值时，不得执行数值预检；语义上明确要求 Python `None` 的参数必须以 JSON `null` 登记，并由策略声明二者的精确映射，不能把字符串 `"none"` 当作空对象。

## 7. 两种评价口径

全量口径包含每世界全部 378 对，只作描述，用于报告移除系统风格绑定后还剩多少总体可见标签信号。

机制中性口径是文本硬门。排除规则在基础生成策略中预先冻结：只排除 `exact_title_clone_target` 和 `high_semantic_similarity_target` 对。排除集合必须先且仅由 `oracle/negative_flags.csv` 中这两个精确枚举的样本对编号并集构造，再与 `audit/registered_override_audit.jsonl` 按“机制映射、资产序号、规范样本对编号”一一重放核对。每世界必须恰好排除 2 个完全标题克隆对和 4 个高语义相似对，六对互异；分类标签不得参与排除成员资格，集合冻结后才用控制者监督独立确认六行均为负例。不得依据预测分数、分类标签或四十对候选诊断集增加排除。其余身份困难负例和每卖家噪声全部保留。于是每世界硬门集合固定为 372 对，其中 20 个正例、352 个负例；点估计平均精确率随机基线固定为 `20/372=5/93`。每次世界自助抽样仍从实际权重重算正例率并要求精确等于 `5/93`，否则视为排除或抽样实现漂移。

## 8. 文本统计硬门

开发集机制中性口径必须同时满足：

- 任一冻结单特征的最大对称受试者工作特征曲线下面积不超过 0.52；
- 三视图、两模型组成的完整攻击族最大对称受试者工作特征曲线下面积不超过 0.53；
- 完整攻击族最大平均精确率相对当次有效患病率的提升不超过 0.01；
- 9999 次世界自助抽样中，每次对六个已经用训练集拟合并冻结的攻击使用同一份开发世界权重重新计算指标，不得重新拟合；每项曲线下面积先转换为对称值、每项平均精确率先减去该次正例率，再分别在六项中取最大值。全部重复完成后，按机器策略冻结的离散分位数方法计算两个族最大值数组的单侧 95% 上界；曲线下面积上界不超过 0.53，平均精确率提升上界不超过 0.015。

原始文本的字符／词攻击继续只作描述。设计预检必须验证训练集与开发集的世界、商品、卖家、样本对和控制者编号交集为零，并同时验证脱敏商品标题／描述散列、正式质量审计同口径的非空五字段换行拼接散列以及完整五字段规范记录散列交集为零；禁止的控制者、标签、机制或身份编号字面残留必须为零。设计能力不等于正式身份能力，因此历史身份散列交集审计必须明确延后，待正式身份生成后由特权持久化数据审计重新计算，不得用设计身份冒充。近重复进入攻击和分层报告，但不设置无依据的绝对余弦阈值。

每个原始世界和反事实世界都必须把生产解析、脱敏和资料构建审计的完整结果计算为规范 SHA-256，再纳入拆分级逐世界审计散列。通过注册门后只保留这些小型审计元组，释放训练集与开发集攻击矩阵后再构造原始描述世界；不得持久化设计世界或大型矩阵。

## 9. 失败纪律

任一结构闭包、映射审计、文本硬门、跨拆分隔离或逐行重算失败，都必须停止 v1.12，记录运行编号、失败阶段、根因、关键哈希和不可复用边界，然后删除失败的大型数据、缓存、临时工作区和专用失败代码。不得更换正式密钥、公开域、错排结果、排除规则或阈值来挽救同一版本。

策略、运行编号、源文件闭包和其后每个计算阶段都必须带明确阶段名。异常必须生成一次不可覆盖、自哈希、正式授权全关闭的小型失败回执并以非零状态退出；即使策略或源闭包本身损坏，也只能降级为不抛异常的最小源快照，不能因此丢失失败记录。注册的错排零假设门或可见文本门一旦失败，必须立即停止，不得继续构造原始 500＋500 世界；失败回执须保存训练集与开发集反事实逐世界审计聚合散列。

成功与失败回执的源闭包至少绑定本运行器、三类攻击和错排实现、生产解析／脱敏／资料链、世界生成及其身份／非身份／结构／渲染依赖、机器策略、本文档和经验证的正式构建设计主草案；后者同时保存文件散列和规范自散列。普通异常与注册门失败使用同一不可挽救声明。所有回执继续明确：正式密钥访问为否、正式数据产生与审计行数为零、模型训练未授权、审核真值未解封。
