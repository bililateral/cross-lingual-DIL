## 已确认的研究场景

用户要求重新生成合成数据，并明确选择：**“不同分布的新卖家群体分批加入”。**每阶段加入新的卖家群体；模型仍判断两个中文卖家账号是否属于同一控制者，并据此检索马甲。

据此拟检验：在历史训练记忆有限时，学习新群体后，模型在已见分布的留出卖家上能否保持识别能力，同时学会新分布？不同阶段不是同一控制者陆续新开马甲的追踪任务；阶段编号不表示真实经营日期。身份分类头扩容、跨阶段连接新旧账号、不断扩大检索库均不属于本次场景。

用户随后明确选择：**“先改变经营品类与商品内容分布（推荐）”**，并对“首轮只使用统一遮盖联系方式的商品标题和描述”回答**“可以，开始执行”**，又以**“按该方案生成”**批准三域、每域 60／20／40 群、0.75／0.70 共享机制、根种子 20260909 和 Windows 单 CPU／256 MiB 上限等具体生成参数。不重复确认这些选择，不另加文风或身份线索机制随域变化。下文“拟／建议／提案”在生成参数范围内表示已经获准的方案；未来训练与最终评价仍为后续范围。

## 分布差异的建议

**按用户确认，以经营品类与商品内容分布为变化轴；生成时文风与身份线索保持同一机制。**进一步建议各域账号数量与正负关系比例一致，避免混入样本量／标签先验变化。这里的“固定”指同一概率机制，不要求不同阶段使用重复文本或相同卖家；模型全程只接收遮盖联系方式后的标题与描述。

已确认的生成结构如下：

| 层次 | 拟生成内容 | 必须避免的问题 |
| --- | --- | --- |
| 群体／域 | 同一中文商品主题集合，不同主题混合比例；各群体仍有重叠主题 | 仅改目录／编号；为某域设置专用标签；用完全互斥的词表替代有意义的差异 |
| 控制者 | 经营组合由域的主题混合影响；表达习惯从不依赖域的共同分布抽取；偏好可由多个控制者共享 | 一个控制者一个专用模板、关键词或主动分配的唯一组合，造成身份查表 |
| 马甲账号 | 继承控制者的部分偏好，独立扰动；同一控制者的账号完整进入同一阶段和分区 | 把同一身份拆到训练与评价；强制所有正例逐字相同 |
| 商品记录 | 按账号偏好生成多条标题和描述；存在同品类异控账号及跨账号共用表达 | 让“同品类”直接等于同控，或让所有负例都跨品类 |
| 同控标签 | 只由生成时的控制者归属产生，定义在所有域保持一致 | 从文本相似度、模型分数或要验证的选择器倒推出标签 |

上述共同潜在偏好是合成身份相关性的假设，不是从真实跨卖家关联统计中估计出的规律。主题名称、混合比例、控制者内／间变化、身份线索共享与缺失规则，都须在训练前写成明确参数。不得调大域差异或改变身份线索来追求某方法获胜；固定机制也不保证可见输入对应的标签后验完全相同。

域参数只控制经营主题混合；文风潜变量、账号扰动和身份线索共享／缺失采用全域一致的机制。有限抽样以及商品内容本身可使长度等观测统计不同，不要求反复重抽直到所有边际完全相等。账号文本先独立于配对对象生成一次，再按控制者归属给账号对标注；同一账号的文本不能随正负配对改变。

同控账号应有部分共同偏好及账号层扰动，既非完全复制，也非独立到毫无可见身份关联。多品类经营时，同控账号的经营组合可不相同，不能使“不同品类必异控”成为确定规则；同品类异控也必须具有预设支持。共同词表／普通模板跨分区复用不自动构成泄漏，随机出现的稀有组合也不自动违规；不主动编码唯一身份，也不声称验证了未见模板或未见生成机制泛化。

下面把三个群体具体化为首轮 Windows 数据生成提案。它足以观察一次以上的后续更新；三个域不是对真实市场数量的估计。旧 500 世界、五批、512 KiB 和旧训练时长均不自动成为新预算。

### 主题与账号相关性

拟采用“数据资料、数字账号、软件服务”三个宽泛经营主题，每主题下人工编写四个细分类；它们是本实验选择的合成主题，不是从已匿名的真实类别概率恢复出的市场品类。词表只描述商品用途、规格、交付和售后，不含真实原文、身份值、实际账号凭据或可用联系方式。共同词表在三域及各分区使用，域编号不进入文案。

细分类提案为：数据资料中的企业资料、教育资料、行业名录、商品目录；数字账号中的社交账号、内容平台账号、游戏账号、工具平台账号；软件服务中的资料整理、格式转换、检索辅助、维护支持。这里只生成商品说明，不生成其中实际出售的人员资料、登录凭据或服务载荷。完整普通词表及句式需在实现时逐项审读，不能把这十二个名称本身当作已验证文本质量。

| 新群体 | 数据资料 | 数字账号 | 软件服务 |
| --- | ---: | ---: | ---: |
| A | 0.60 | 0.20 | 0.20 |
| B | 0.20 | 0.60 | 0.20 |
| C | 0.20 | 0.20 | 0.60 |

这些概率用于抽取控制者的经营偏好及账号的背景商品，不声称最终商品比例恰好等于表中数字；每主题的四个细分类在该主题内等概率。无放回抽取两个主营细分类本身会改变总体边际，不只是有限样本波动。按下述机制枚举 66 个无序主营组合，可得 A 域商品主题的总体期望约为 `0.589597523 / 0.205201238 / 0.205201238`，其余两域轮换；这是分数算术核对，不是生成结果。

拟采用一个简单的部分共享机制：

1. 每个控制者从上述细分类权重中依次抽取两个不同的主营细分类；第二次排除第一次结果后重新归一化。这两个偏好可由其他控制者独立抽到，不做唯一性分配。
2. 每个马甲账号以 0.75 概率沿用这组偏好，以 0.25 概率按同域规则独立重抽一组；不能因重抽结果碰巧相同而再抽。每条商品以 0.70 概率从该账号两个主营细分类中等概率选一个，以 0.30 概率按同域整体细分类分布选取。
3. 控制者从全域共同资源池对标题顺序、描述布局及服务措辞三个轴分别独立均匀抽取；各轴分别有 3、3、4 种普通选项。账号对每轴以 0.75 概率继承，否则独立均匀重抽该轴；域不改变这些概率。不是给每个控制者编写专属模板组合。
4. 商品名、普通属性与句子变体从细分类／共用资源池抽取，先一次性生成该账号全部记录，再构造账号对。两个同控账号可以商品组合不同；两个异控账号也可以经营组合及表达偏好相似。上述概率不是按旧方法成绩选择的，也不以新方法排名反向调整。

这些明确参数用于形成可检验的共同经营／表达信息。解析核对中，异控账号主营组合相同的概率约为 0.026536246，同控约为 0.574109608；三／四选项的风格轴，同控一致概率分别为 0.708333333／0.671875，异控为 1/3／1/4。这证明潜变量设定保留了统计关联而非确定等同；它不是实际文本可识别率，也不证明模型能提取该信息。这些参数没有真实跨马甲关联估计支持，不能把这种相关性强度写成真实市场规律。

### 文本与联系方式投影

每账号记录数拟按已发布的 2—8 条商品数概率抽取，而不是固定每群恰好 99 条。该聚合的期望为 3.602071 条／账号；只能作为数量参照，不能把旧逐卖家长度分位数直接当成逐商品长度分布使用。

标题与描述使用人工词表组合，拟限定标题不超过 48 个字符、描述不超过 720 个字符；这属于规模和文案设计限制，不宣称拟合了真实长度分布。内容在规则内完成，不在模型输入时截断长文；超限是生成实现需修复的问题，不按标签选择截断位置。每账号至少两条非空标题／描述记录，不额外加入缺失字段研究。

**建议按统一去联系段规格，直接生成商品标题和描述。**商品内容 C 与联系段 L 在规格中分开，投影为 `projection(C,L)=C`；联系值、数量和长度不反向决定正文、文风、记录数或正文长度预算。所有域和分区使用同一规格，不保留联系类型、数量、长度、相等关系、哈希或控制者占位符。因此不实际生成随后要丢弃的联系人值和私有身份资产；不声称本次验证了任意真实原文的自动脱敏，也不声称验证了某种联系值共享／缺失机制。共同经营和表达偏好仍是身份相关信息，不能把产物称为“无身份信息文本”。首轮没有联系方式或身份特征支路。

语义示例仅帮助核对生成意图，不是生成数据或证据：同一控制者的两个账号可以分别写“企业资料栏目样本，分项说明随包”和“提供栏目示例，支持分项交付”；另一个控制者也可以使用“企业资料”主题及“随包说明”。同控依据来自生成的控制者归属，不能从这两句话的相似度倒推标签。

### 本阶段资源与验收

建议只在 Windows 使用一个 CPU 进程生成，GPU 使用为零；新数据目录及生成审查记录合计上限 **256 MiB**。正文最大为 185,794,560 字节，即 177.1875 MiB。JSONL 使用 UTF-8、`ensure_ascii=False` 和紧凑分隔符，不能把中文转为六字节的 `\\uXXXX` 再沿用三字节预算。词表使用基本多文种平面字符，不含孤立代理字符或除换行／制表外的控制字符；ASCII 引号、反斜杠及允许换行的 JSON 转义计入预算。

拟限制每个公共／控制者 ID 为不超过 32 字节的 ASCII 字符串：每商品除正文外的元数据不超过 256 字节，账号归属行不超过 192 字节，配对 CSV 行不超过 128 字节，群索引行不超过 256 字节，清单／政策／审查等其余小记录合计不超过 4 MiB。按所有账号均有 8 条记录的最坏情况，保守总上界约 219.4 MiB，低于 256 MiB；本地已用最大长度占位字符串核对序列化公式，未生成研究数据。实现仍需按实际导出字段确认这些界限，若确需超限先报告，不无声扩大。按群流式写入，不按边复制全文，不保留重复数据副本。

最小验收覆盖：手算群配对／标签；独立控制者隔离；同一账号只对应一份文本；生成权重及随机流调用的实现；标题／描述投影不受联系值或私有编号影响；输出文本确实包含预定经营内容差异。按固定方案报告实际主题比例、重复文本及同／异控主题重叠，不通过重新抽种子把统计修到预期值，也不以遗忘或 ER 优势验收。上述实现、12 项合同、实际 GPT 6 Pro 实现外审及正式输出核验已完成，记录见[结果页](SELLER_ALIAS_CONTINUAL_DATA_RESULT.zh.md)；这不是后续固定 smoke 仪式。

该规模先用于机制可行性和后续预算估计，不预先承诺论文效应的检验功效。评价的固定群 AP、查询 MAP 和逐阶段矩阵沿用本页骨架；最终主终点、阈值、模型和训练预算在生成方案确认后另行具体化，当前不启动四臂训练。

## 已确认的模型输入

用户已确认只使用商品标题／描述，统一遮盖联系方式，不输入身份特征。该实验支持的是文本条件下的马甲识别，不能称为完整公开身份信息系统的表现。首轮不同时运行另一套包含身份特征的四臂。

这项选择不改变各域身份线索的生成机制，改变的是全程一致的模型可见信息。遮盖规则必须在训练、评价、记忆保存中一致，且不能通过掩码、额外数值列或账号 ID 重新传入被排除的身份信息。完整合成同控／异控训练监督仍可在后续获准阶段使用，“不输入身份特征”不表示隐藏训练标签。

本次静态核对旧 `step28_continual_text_data.py` 的 `WorldArchive.read` 及 `step28_continual_text.py` 的输入合同、聚合和拼接函数：旧头使用 18 项原数值、6 项可微文本汇总、33 项身份特征，共 57 项。旧“文本四臂”不是纯文本实验；输入选择改变后，旧合同／加载器不能不加修改直接使用，旧负结果仍只属原输入。

## 评价怎样对应问题

建议每个域分别生成控制者隔离的训练、开发、最终评价账号。域内训练和评价服从同一预定机制；不同域及各分区使用不同控制者和身份值。分区在生成前确定，不能先生成全部账号再随机拆账号对。开发用于获准的调试／选择，最终评价在合同冻结后使用；新阶段的具体监督访问另行明确，不继承旧 train／development 的一次性许可。

各域评价集的商品记录、查询、候选账号及标签固定。每次模型更新后，对这些相同记录重新推理；可以改变学习到的表示，不能把旧模型缓存表示与新表示混用。训练器只看已到达训练群体和允许保留的历史状态；即使评价未来域用于记录更新前能力，也不把未来输入、分数或标签交给训练／选择流程。

首轮建议在同域的固定候选集合内评价，不将因控制者跨域互斥而必为负例的跨域账号对大量加入以抬高指标。使用统一判别器，域编号与私有生成画像只用于编排、分组和生成正确性核验，不作为打分特征，也不用域编号选择专用模型／阈值；这种分域评价不代表全市场统一候选库的检索结果。

令 `R[t,j]` 为第 t 阶段结束后，模型在第 j 个到达域的固定评价集上的表现；保留初始模型 `R[0,j]`。换到达顺序时，j 随该顺序重新映射到具体域。

| 要回答的事 | 建议记录 | 解释边界 |
| --- | --- | --- |
| 新域学到了多少 | `R[t,t] - R[t-1,t]` | 与更新前同一模型在同一评价集比较，不以不同域的分数差充当学习增益 |
| 旧域保留了多少 | 对每个 `j < t` 记录 `R[t,j] - R[j,j]` | 负值为相对学完该域时的退化；若该域原先没学好，稳定不等于成功保持 |
| 中途最佳表现后是否退化 | `max(R[k,j], k=j..t) - R[t,j]` | 与前项分列，不能把两种定义混为同一个遗忘指标 |
| 同阶段方法整体比较 | 对同一个已见域集合等权平均并列出逐域结果 | 同时看新域学习、旧域变化及成本；跨阶段的已见域集合在变，其均值变化不能单独证明模型改善 |

前后更新比较使用同一旧域集合，单列新域表现。新域同时报告更新前后绝对值和增益；更新前已经表现好时，零增益不等于学不会。此处“更新增益”不称为经典前向迁移，也不以必须正增长作为数据合格条件。

采用每域多个互不共享控制者的固定账号群。成对 AP 明确为**一个群的所有无序账号对整体排序所得 AP**，先对群等权，再对域等权；MAP 则先对每个查询的其他账号候选列表计算 AP，再按冻结层级平均，两者不混为重复证据。查询检索另报 MRR、Recall@1/3/5/10、NDCG@1/3/5/10。AP 与梯形 PR-AUC 分开；群大小、控制者账号数分布及正例数已按上文生成方案确认，不含单马甲控制者。主终点及阈值判定评价仍待合同明确。排序改善不自动证明固定阈值误报率改善。

采用上述互斥账号群后，建议按完整账号群在同域内配对重抽样，而不是按账号对或单个查询重抽样；共享图库的不同查询仍有依赖，负边也不能随意归给一个控制者充当独立样本。每域 40 个 heldout 群已按生成合同固定，重抽样等最终评价参数仍待确认。报告到达顺序差异；不把少数顺序的区间解释为覆盖生成机制及全部训练随机性。

## 首轮比较与判断建议

先比较首批后冻结、普通继续训练、有限历史随机重放及累计历史训练。共享必要初始化、新样本顺序与输入；明确优化器状态、历史损失权重、记忆加入／淘汰时点。累计训练是可访问历史的参照，不是数学上界，不宣称等计算。

历史预算按能够真实继续训练的持久状态计费，包括去重账号文本、关联、标签及必要选择状态；不能只存账号 ID，再从全量旧数据无限回查。正负比例、缓存利用率、重放频次和实际更新量必须报告，避免把这些差异错归因于关系选择器。具体模型、字节预算、训练日程及后续强基线仍待确认，不自动沿用旧 57 维组合输入。

生成器资格首先检查标签与控制者的一致性、拆分隔离、模型可见分布差异、文本重复与明显配对捷径。固定生成规则是否被实现，与模型是否学会、是否遗忘、重放是否改善分开判断。没有遗忘或重放优势也保留结果，不能据此宣布生成失败并寻找有利种子。若模型没有学会，先核验输入和实际更新，不能把无学习误报为抗遗忘。

首轮结果只有在确实学会旧域与新域、旧域受到后续更新影响且简单参照仍有明确改进空间时，才支持继续研究记忆选择。具体贡献还须超过随机／分层随机及适用的现有持续学习方法；重新生成数据和迁移到中文卖家题目本身不证明论文创新。
