# Step 7-v4：原始商品级作者风格基底模型选择

## 1. 要回答的问题

Step 7-v4 只回答一个问题：在固定的英文马甲识别数据边界内，哪一套可跨语言执行的冻结表示与分类头，最适合作为后续 Step 28 的英文基底 M0？M0 是完整流水线，不是某个编码器的名字：

> 身份信息删除后的标题/描述 → 冻结编码器 → 固定商品级聚合 → 英文训练得到的分类头。

本轮不得使用中文结果选模，不得打开历史英文 test 标签。父数据原有 152 条 valid，其中 1 条配对后来被原始表结构审计确认由两个商品描述续行伪装成“卖家”组成，必须在不读取标签的前提下隔离；因此 v4 有效 valid 为 151 条，且仍只能作一次开发诊断。正式认定 M0 仍需新的真实英文确认集。

2026-07-23 正式上机前的独立终审撤销了草案 `v1_20260722`：其最小 GPU 包在 `load_policy()` 时会间接导入一个未同步的父清洗模块，且把原生窗口为 256 token 的 LaBSE 错误向上改成 512、喂入 480-token 块。该版本只完成了 CPU public 产物准备，没有运行 GPU 编码、分类器训练或选模，不能产生科研结论；失败产物删除，只保留本文记录。修复版使用 `v2_20260723`，GPU 策略校验不再依赖父原始数据栈，且严格服从各冻结模型的原生输入窗口。终审同时要求私有投影逐行重放固定父标签/证据文件，并要求 valid 指标只从已落盘并锁定的无标签预测重放。

修复版的正式 CPU 准备已经完成：公开边界为 109,756 条商品、733 条 pair、853 个卖家、33,434 个全局唯一清洗文本，公开清单内容哈希为 `bcd838667fcb4708fdb97ffdec8c689e0e8f2b3549823dbca20d22aa2ad059fa`。私有投影保持 train 401 条（116 正、285 负）和 valid 151 条（42 正、109 负），标签与 evidence 物理分离并从固定父文件逐行重放；私有清单内容哈希为 `910585cfc8bda6672e9ed3955e149433dbc15b1c7555ea280483dd4be1fccad9`。最小 GPU 同步清单只含 7 个文件、25,653,396 字节，禁止路径 14 条，内容哈希为 `b9d2a5718e2bb89182af3a7e9b8d4b336615ff161c269ce3f4d1e410018f4705`。2026-07-24，四模型 GPU 编码和修正后的 CPU 选择均已完成；正式结论为 `no_stable_unique_provisional_m0`，详见 `docs/STEP7_V4_RESULT_AUDIT_20260724.zh.md`。

## 2. 为什么不能沿用 v3.1

v3.1 所谓“完整文本”实际上是 Step 3 的压缩摘要：每个卖家只保留有限数量的标题、描述片段和类别。它解决了摘要被单窗口截断的问题，但没有覆盖完整商品历史。父 Step 2 边界原记为 109,758 条商品；v4 原始表预检发现其中 2 条 Agora 记录其实是上一条长描述的续行，价格、来源地和评分被整体移入错误列，却被误建成两个卖家并互相组成 1 条 valid 负例。v4 用固定的 pair/seller/item 哈希、原始行号、九列字符串长度和整行内容指纹隔离该独立连通分量，不修改历史产物，也不按标签或模型结果决定删除。有效边界因此为 109,756 条商品、733 条 pair、853 个卖家；401 条 train 完全不变。

v4 从 Step 2 行级清单回到两个不可变原始快照，只读取有效边界内商品的完整标题和描述。有效来源计数固定为 `market_item.xlsx=109,703`、`Agora=53`。所有来源行保留在审计血缘中；模型主输入按“卖家 × 字段 × 身份删除后完全相同文本”去重，记录 multiplicity 但不把它作为模型特征或主聚合权重。两条被隔离的续行仍须在 CPU 预处理阶段按原始工作簿逐字节结构重放并通过指纹验证，但不得进入文本、特征、GPU 或标签产物。

## 3. 文本与身份隔离

- 只使用 `title` 和 `description`；类别、市场、卖家名、联系方式、结构化身份字段不得进入编码器。
- 标题和描述始终分开，商品之间不拼接。只有单条超长文本才分块。
- 统一换行后复用经 v3.1 审计的身份规则，但 v4 增加两道不可绕过的边界。第一，只有固定白名单中的完整/截断 PGP 块、PGP 指纹，以及“联系提示词与 `+` 在前、完整号码或国家码/区号之后的号码尾段因原始排版落到随后 1 至 3 个换行之后”的电话允许跨行；其余卖家别名、联系方式、语境别名和模糊 handle 规则必须逐逻辑行定位。该电话例外要求 `call/text/phone/contact` 等明确提示、字面 `+` 和受限电话结构同时成立，不能用一般的 `\W` 跨行。第二，所有规则只在同一份“删除前的规范化原文”上做一次非级联匹配，随后合并跨度并统一替换为空格；前一条规则的删除结果不得触发后一条新匹配。原因是父规则中的 `\W` 会匹配换行，而且顺序删除手机号或真实 handle 后会制造原文不存在的新邻接关系，进而把同一行或下一行 `Master Kush`、`Quality ATM...` 的首词误当新 handle。对原文中已经存在的异常重复邮箱（如 `name@domain@domain`）以及明确的“联系服务 + at + 字母数字 handle”（如 `Wickr at express74`），使用单独、高精度的原文整段规则覆盖，不靠第二轮级联补删。唯一允许的受限桥接是：先在原文定位卖家本地身份跨度，仅把这些跨度等长遮蔽后检查是否形成已人工审计的固定身份短语；例如 `Tech Programmers Hackers` 中 `Programmers` 是本地身份、`Tech Hackers` 是固定身份时，一次删除整个组合。任何其他规则都不得参与桥接。标题和描述内的换行仍保留，规则不得吞掉商品正文；清洗后独立残留扫描若发现未删除的精确别名、复数/身份后缀形式或其他高置信身份则整轮失败。一字符缺失变体只允许在删除前原文中本来就满足身份语境时参与删除；删除其他身份后新形成的模糊匹配只作碰撞计数，不得当作身份继续删除或宣称为身份残留。例如删除 `Empire Market` 后，`seller ... without` 会碰撞到别名 `withouth` 的一字符缺失变体，但普通词 `without` 必须保留。
- 固定快照还存在逗号分隔的市场身份列表，例如 `Dream market, agora market, wallstreet, grey, samsara, alphabay market verified vendor`。逐个删除已知市场名会在结果中才拼出 `grey ... verified vendor`，因此不能依赖第二轮级联补删。v4 只在删除前原文同时出现至少 3 个固定已知市场名、逗号列表结构和末尾 `vendor` 提示时，一次删除整段列表；普通颜色词 `grey` 不匹配。
- 对同一行串联多套联系方式的固定异常，v4 还在原文直接覆盖 `google voice + 电话`，以及 `WhatsApp + 电话 + Wickr + 混合字母数字 handle` 整段；后者允许 U+00A0 不换行空格但禁止跨行。这避免旧规则先删第一套联系方式后才暴露第二套号码或 handle，同时不把第二轮级联重新引入生产流程。
- 独立最终审计在固定教程清单中会把 `Phone Numbers (NEW Revision, 4.14)` 与下一项编号 `026` 连成电话。该正文不得删除，也不得用规则级白名单放过。策略只登记这一条记录的卖家哈希、完整清洗文本哈希、审计规则名、命中表面哈希和精确次数；四者或次数任一漂移即失败。清单基于无标签内容审阅，未读取 pair 标签或 evidence type。
- 删除器的词典只来自固定英文快照和身份信号，不读取 pair 标签或 evidence type；上述两个伪卖家也不得向 v4 的全局身份词典贡献商品词汇。移除它们后必须重建剩余 853 个卖家的清洗记录，并逐单元验证全部 legacy18 与冻结父特征完全一致，否则隔离失败、实验停止。一字符缺失表还要在训练前做固定英文原始快照内容碰撞审计：先确认 `withouth` 自动生成的 `without` 是普通功能词，再对 109,756 条商品全扫；初筛后的模糊规则实际命中 16 种表面词、1,697 次。人工逐组查看原文后，`account`、`discount`、`dumps track`、`exchange`、`legit documents`、`password`、`premium account` 与 `without` 共 8 种内容碰撞禁止模糊删除，但对应精确别名仍保留；`Lordparma`、`medicalfamer`、`VATSALMEDS` 等有明确自称、联系或店铺语境的 9 种身份变体继续删除。过滤后正式原文审计必须严格重放为 9 个表面词、892 次，并逐表面词校验哈希计数；出现任何新词或计数漂移即停止。该审计不允许读取 pair 标签、evidence type 或模型结果。
- 原始表预检还发现卖家别名与普通商品词碰撞：例如卖家名 `master` 的无条件删除会误删 `Master Kush` 和 `Master Card`。v4 将父策略中 22 个受保护词/短语与本地卖家别名做精确 compact 匹配；命中的 11 个卖家不再无条件删除该别名，只在 `welcome to`、`seller`、`shop`、`contact` 等明确身份语境下删除，且不允许一字符模糊匹配。同一批保护词还必须从全局语境别名表中剔除；固定快照中因此排除 `250mg`、`25inbome`、`amazonprimestore`、`bet365`、`westernunionstore` 5 项，避免把 `25I-NBOMe vendor` 之类商品描述误当身份。无身份语境的歧义词保留并单列审计，不能宣称“所有潜在身份均已消失”。
- 内容保留率按不嵌在更长 ASCII 字母数字串中的完整表面词计数，并从原文分母中排除高置信规则在删除前已经明确定位的联系方式/身份跨度。因此 `Master444`、`grandmastershop`、邮箱，以及同一行 `wickr me-private message` 中随整段联系方式正确删除的词，不会再被误算成普通内容损失；下一行的 `Master Kush`、`Quality ATM...` 和普通 `private listing` 仍计入并必须保留。身份跨度审计使用与生产删除器完全相同的跨行白名单，不能把生产中禁止的跨行匹配拿来缩小分母。每个“源商品 × 字段”先独立计算可解释删除、未解释删除和新生表面词，再求和；不同商品或字段之间不得用新增同名词抵消误删。所有排除跨度先在未删除原文上定位，防止用最终清洗文本反向制造 100% 保留率。降低 80% 门槛不是允许的修复方式。
- GPU 工作区只接收删除身份后的唯一文本、卖家到文本的索引、无标签 pair 清单、代码和模型；原始快照、逐 pair 标签/证据表和卖家资料必须物理缺席。完整预注册策略仍会携带总样本数、证据类型词表以及输入文件路径/哈希，但没有任何 pair 到标签或证据的对应关系；清单必须如实区分“汇总监督元数据”与“逐样本监督值”。GPU 清单中的卖家和 pair 只用固定顺序生成的 `seller_000001` / `pair_000001`，不得携带原始 `seller_uid`、split、component 或来源行号。
- CPU 公共准备同样不得打开包含 `review_label` 的 Step16i `component_assignments.csv`，即使代码声称只取其中的 pair/component 列也不行。v4 直接读取并校验已经冻结、哈希固定且只有 `pair_uid/split_name/component_id/两端 seller_uid` 的父 `pair_manifest.no_labels.csv`；含标签的 train/valid 文件只允许在独立私有投影阶段打开。
- 准备脚本不提供 `--stage all`。先在独立进程运行 `python scripts/step7_v4_prepare_source_data.py --stage public`，公共产物完全写完并自校验后，再用第二个进程运行 `python scripts/step7_v4_prepare_source_data.py --stage private-labels`。省略 `--stage` 也只能执行 public，不能为了方便把两类数据放回同一进程。
- 私有投影清单必须逐项绑定策略中哈希固定的父 train/valid 标签文件。每次验证都重新从父文件执行隔离 pair 投影，并逐行精确比较 train/valid 的标签表和独立 evidence 表；仅检查样本数、类别数或输出自哈希不够。该验证只在 CPU 主仓库进行，当前私有输出以及两份父标签输入都必须被 GPU allow-list/forbidden-path 双重排除。

## 4. 公平分块与聚合

PCM、mStyleDistance、multilingual-E5-large 和 LaBSE 接收完全相同、顺序相同的文本块。PCM、mStyleDistance 和 E5 的冻结原生窗口为 512，LaBSE 为 256；代码必须在加载后核对该原生值，禁止向上覆盖。共享块预算因此固定为 256 token，而且预算已经包含 E5 前缀和各 tokenizer 的特殊 token；全文仍通过增加块数无重叠、无采样地精确重建。

`SentenceTransformer` 模型文件可以自带 `default_prompt_name`，而 `encode()` 在调用方不指定 prompt 时可能把对应文字暗中加到输入前。v4 不允许这种未登记输入：四个模型均显式传入空 `prompt`，加载后把 `default_prompt_name` 清为 `None`，并把模型原始 prompt 配置写入运行清单。E5 所需的 `query: ` 仍只通过策略中可见的 `text_prefix` 加入；分块 tokenizer 重放的正是最终实际编码字符串。当前 Linux 版本若不支持显式 `prompt` 参数，实验直接停止。

原始 `AutoTokenizer` 的 token ID/长度还必须与实际 `SentenceTransformer.tokenize()` 的 attention-mask 有效 token 逐块同哈希重放；这样 wrapper 预处理或模型内截断不能被“只检查底层 tokenizer”掩盖。真实 5.6.0 返回的 `BatchEncoding` 是字典式映射而非原生 `dict`，实现与测试均按映射接口读取，避免在 Linux 上误拒绝正常结果；同时策略固定 `sentence-transformers==5.6.0`，运行清单核验四个模型的库版本、GPU、CUDA/cuDNN 与计算能力在同一轮内完全一致。Linux runner 的第一遍编码器调用会在内存构造共享块，并逐个真实加载四个模型，选择各自 token 最长的实际块编码两次，核验原生窗口、prompt、token ID、维度、单位范数和逐字节确定性；该冒烟不写正式结果。只有四个模型全部通过，才开始全量编码。

四个冻结编码器按固定顺序运行。CUDA 随机种子固定为 `20260722`，启用 PyTorch 确定性算法，关闭 cuDNN benchmark 与 TF32，并把运行时设置写入每个模型清单；若当前 Linux 环境不能满足该合同，实验直接失败，不能悄悄换成另一套数值路径。

聚合分两级：先把一条商品文本的全部块向量归一化平均为商品向量，再对卖家商品向量计算：

1. 标题商品向量质心余弦；
2. 描述商品向量质心余弦；
3. 标题双向逐商品 top-3 局部匹配均值；
4. 描述双向逐商品 top-3 局部匹配均值；
5. 标题/描述等权质心均值；
6. 标题/描述等权局部匹配均值。

局部匹配按固定 256 行分批计算，只限制峰值内存，不抽样、不近似；单元测试必须证明它与一次构造完整相似度矩阵的结果一致。

主聚合中每个唯一文本等权。按原始重复次数加权的同名指标只作敏感性审计，禁止进入候选模型；最终报告必须逐编码器、逐聚合项给出两种算法的可比较 pair 数、非零差异数、平均/P95/最大绝对差，不能只生成列却不审计其影响。

## 5. 候选与对照

- `control__legacy18`：现有 18 项无直接身份标识的结构/内容对照，所有 IDF 和百分位统计必须在每个训练折内部重算。
- `control__stylometry`：只看字符长度、数字、Unicode 标点/符号、空格、换行、句末、括号、分隔符、重复标点和列表行等 22 项成对绝对差；不含词汇、语言、市场、商品数或重复次数。
- `encoder__e5`、`encoder__labse`：同一原始文本合同下的语义编码对照。
- PCM、mStyleDistance、E5、LaBSE 都同时保留“编码器 6 项单独使用”和“编码器 6 项 + 同一套 stylometry22”两种候选，禁止只给某一类编码器附加特征。
- 四个编码器还分别与同一个 `legacy18 + stylometry22` 对照组成第三层消融；不能只让风格编码器获得 legacy18。
- 风格候选还包括 PCM 与 mStyleDistance 的组合。
- 融合候选：风格主干分别加入 E5、LaBSE，或加入 legacy18；另保留 `legacy18 + PCM + mStyleDistance + E5/LaBSE` 两个完整融合候选，避免只比较两两组合而漏掉互补信息。E5 与 LaBSE 不再彼此叠加，以限制样本仅 401 条时的冗余维度和候选膨胀。语义编码器不能被单方面给予不同字段、块数或聚合规则。

编码器全部冻结；训练的是候选特征之上的 L2 逻辑回归。训练选择标签文件只保留 `pair_uid`、正负标签和连通分量；证据类型放在另一份物理文件中。在候选排序、L2、阈值、最终系数及无标签 valid 得分全部锁定前，选择器不得打开证据文件。证据类型只作锁定后的结果切片，不能决定样本权重或模型选择。

## 6. 训练和选择

全部 401 条 train pair 按重算身份连通分量隔离。外层使用 5 折 × 5 个固定种子的重复分组交叉验证；每个外层训练集再用 4 折分组交叉验证选择 L2。缺失值中位数、标准化、legacy18 参考统计和分类器都只能在当前训练折拟合。

每条训练对会得到 5 个真正的外层 OOF 概率，取算术平均作为候选排序和阈值选择分数。最终模型的 L2 取 25 个外层折内所选 L2 的中位数；阈值只按这些重复 OOF 分数上的连通分量等权平衡准确率确定。

L2 初始网格为 `1e-3 ... 1e3`。最优值落在边界时按十倍继续搜索到 `1e-6` 或 `1e6`，但边界最优本身不构成拒绝产出的理由。所有拟合必须满足归一化梯度收敛门槛；任一正式拟合不收敛即整轮失败。

L2 的数值固定解释为“加权平均 log loss + `0.5 × L2 × 系数平方和`”。底层求解器内部使用加权损失总和，因此 v4 每次拟合都将传入求解器的惩罚量乘以该折样本权重总和；这样内层约 240 条、外层约 320 条、最终 401 条以及各留一市场子集中的同一个 L2 才表示同一正则强度。不得把按总损失调出的原始惩罚量不经换算直接带到不同规模的最终训练。

主排序指标为重复嵌套 OOF 的连通分量等权 AP；同时报告 ROC-AUC、普通 AP、PR-AUC、F1、Precision、Recall、Balanced Accuracy、Brier、log loss，以及仅对同时具有正负候选的查询计算的 MRR/Hit@1/Recall@K。还必须报告硬负样本、直接身份正样本、无完全文本克隆和留一市场压力测试。

留一市场只对已经选定的赢家做训练集压力诊断：凡连通分量触及目标市场，整个分量进入留出侧；剩余分量内部重新用 4 折选择 L2 和阈值。该结果不参与选模，也不代替新的英文确认集。

训练 OOF 决定候选、L2 和阈值。赢家不仅要在连通分量 bootstrap 中超过当前次优项，还要在同一批重采样中以至少 95% 的概率严格超过全部候选，避免另一个候选在重采样后反超却被“只比次优”掩盖。文本克隆检查不是把原模型的 OOF 预测事后筛一遍：程序必须先删除双方存在任何完全相同清洗标题/描述的全部 train pair，再对剩余数据从分折、内层 L2 到外层 OOF 完整重跑 5 个种子 × 5 折嵌套训练。原始赢家在这套无克隆重训中至少 60% 的外层重复仍须排名第一，且以至少 80% 的连通分量 bootstrap 概率压过全部候选；否则只能报告“总体排名受文本克隆捷径影响”。风格增益的正式归因固定检查预先指定的 `style__pcm_mstyle_stylometry`，事后挑出的最佳风格候选只报告、不负责通过增益门槛。

“哪个编码器最强”另设严格匹配比较：只比较 E5、LaBSE、PCM、mStyleDistance 各自的 6 项聚合加同一套 `stylometry22`，不混入 legacy18 或双编码器融合，并报告四者的单独排名及赢家同时超过另外三者的 bootstrap 概率。它与“哪套完整 M0 流水线最好”是两个不同结论。

训练集候选排序、L2 和阈值确定后，程序先把训练选择锁写成不可变 JSON。随后使用已锁定配置拟合全部 train 分类头并对尚未读取标签的 valid 盲算；最终模型参数、只含 `pair_uid/candidate_id/probability` 的无标签 valid 预测和盲算锁都必须先写盘并逐文件固定哈希。概率使用可精确往返的浮点字符串；写盘后按候选、pair、唯一键、数量和 `[0,1]` 有限值严格回读，删除内存原数组，后续 valid 指标只能使用这份锁定回读值。只有这两道物理锁全部验证后，程序才可打开 train 证据类型以及 valid 标签/证据做一次诊断；带标签预测另存文件，不能覆盖盲算文件，结果不得反向改变方案。若最佳候选不稳定，或预指定风格模型不能超过相匹配的简单/语义对照，应明确报告“没有唯一的编码器型 M0”，不得制造成功结论。

## 7. 结论边界

本轮最多产生“待新英文数据确认的 provisional M0”。它能证明英文数据中哪套流水线最有支持，不能单独证明中文迁移成功。Step 28 才能冻结该英文流水线并比较无适配、无身份信息对照和合成身份适配模块。

## 8. 2026-07-24 正式执行结论

正式 GPU 运行生成 `41,808` 个共享块，四模型均无超预算输入；冻结特征随后用于 `22` 个候选的完整嵌套选择。原选择器在一个已到 float64 目标函数分辨率平台的逻辑回归拟合上，把 `1.026485e-9` 的梯度误报为未收敛。数值补丁没有放宽 `1e-9` 门槛，也没有改动任何数据或选模合同；复跑 `32,423` 次拟合全部严格达到原门槛，数值兜底使用次数为 `0`。

训练主口径暂列第一的是 `legacy18 + E5 + stylometry22`，但相对 `legacy18` 的连通分量等权 AP 只增加 `0.000939`，bootstrap 区间跨 0；去除完整文本克隆并从头重训后，该候选降至第 9，五个外层种子一次都没有获胜。匹配编码器比较也无法区分 E5、LaBSE、PCM 与 mStyleDistance。因此 Step 7-v4 没有找到稳定、唯一、可归因于编码器的 provisional M0，旧 valid 与历史 test 均不得用来补救该失败。
