# Step28-v13 v1.13 v9 质量审计一次性授权覆盖合同

## 1. 目的与当前边界

本合同只解决一个状态转换缺口：成功设计根钉住的冻结质量政策必须继续保持 `quality_audit_run=false` 和 `metric_generation=false`，而冻结运行器的公开入口又要求二者为真，因此当前字节不能合法进入质量审计。不得修改成功设计根、四份拆分清单、冻结质量政策、原质量运行器或验证器，也不得重跑 1,004 世界设计构建。

覆盖层只允许在后续独立复审明确放行后，运行一次设计级质量审计。它不授予正式种子、正式 500×4、审核甲乙真值、模型训练或模型效果指标权限。当前阶段只允许实现和夹具测试；不存在外部回执时，生产入口必须在读取任何设计视图、标签或真值前关闭失败。

提交后复审发现第一版覆盖入口仍不能运行：冻结政策既没有构建完成后才能确定的 `design_root_manifest` 根钉，冻结监督验证器又同时要求该政策的生产授权位保持关闭和质量审计授权位为真。第一版测试模拟了私有审计体，因而没有触发这两层确定性死锁。该版本没有创建或消费正式回执，没有读取行级设计数据或真值，也没有产生质量结果；它只作为 Git 历史中的失败实现保留，不得运行。

第二版显式执行适配器提交 `ff7fc6038e755d389449757e52850b4988f297af` 后仍未获运行许可，也从未创建回执或运行。复审确认其把谱系使用的仓库相对完整根清单路径直接传给只接受数据根内 `root_manifest.json` 的真值能力，必然在首个训练／开发标签字节前失败，并会被错误归为数据无效。该候选还没有在适配器内重验真实已消费回执文件，终态发布遇到已有结果时会静默返回，且合同把实际逐字节验证范围写得过宽。后继候选必须关闭这些问题；`ff7fc603` 只保留为失败实现 Git 记录，不得运行。

待用回执固定为 `private_custody/step28_v13_v1_13_v9_quality_audit_authorization.json`。仓库代码不得生成它。回执必须是无重复键、无非有限数的严格 UTF-8 JSON，并以删除顶层 `canonical_self_hash` 后的规范 JSON 摘要自证。

回执必须精确绑定：

- 后续复审网址、回复完整摘要、复审时间和最后一行“允许运行一次冻结质量审计”；
- 当前干净 Git 提交和树；
- 覆盖政策、覆盖入口、执行适配器、冻结质量政策、原运行器和验证器的路径、字节数及完整摘要；
- 设计根清单和四份拆分清单的路径、字节数、文件摘要及规范自哈希；
- 固定尝试 1、固定输入根和唯一结果路径；

同一回执文件摘要对应唯一已消费路径 `.consumed.<sha256>.json`。已消费回执存在、待用回执缺失或结果路径已经存在时均禁止运行和重试。

## 4. 执行顺序

生产入口必须无参数，顺序固定为：

1. 验证覆盖政策、固定源码、设计根和拆分清单的非行级绑定；
2. 验证完整 Git 工作区干净并与回执提交和树一致；
3. 验证待用回执完整模式、自哈希和全部绑定；
4. 确认结果目录和临时结果均不存在；
5. 在读取首个设计视图、训练／开发标签或任何审核真值前，原子重命名并重新验证已消费回执；
6. 创建唯一结果目录，从已验证根钉和已消费能力构造不可变执行上下文；
7. 调用显式执行适配器；适配器使用冻结运行器的加载、结构和特征冻结实现以及冻结监督器的数值辅助函数，但根钉和执行授权只从独立上下文读取，冻结政策原样作为科学参数合同传入；
8. 将成功、数据无效或审计器故障统一写成不含行级标签和预测的规范小回执，经临时文件原子发布。

冻结审计体负责重新验证根与四拆分清单、物理文件路径全集，并对实际加载的四拆分 44 个标签无关输入逐字节核对摘要；完成标签无关结构与特征冻结后，只在监督器内部逐字节核对并打开训练和开发两份真值一次。其余 26 个文件只保持拆分清单摘要承诺，不得冒充本轮实际重哈希；其中审核甲乙两份标签及其他未进入冻结质量视图的私有证据继续封存。结果回执必须分别记录实际逐字节验证集合和仅清单钉住集合的数量、路径及绑定摘要；审核甲乙真值实际读取字节数必须为零。该区分只收紧证据表述，不改变冻结视图、探针、门槛或标签。

## 5. 失败与科研结论

一次性回执在审计体开始前即被消费。执行失败不得换根、换政策、换阈值、换结果路径或复用同一许可。覆盖入口从消费成功到正常结果发布之间的任何异常，都必须在同一唯一结果路径排他写入机器可读的终态小回执；只保存阶段、异常类型、异常消息摘要、已消费回执绑定和固定输入绑定，不得返回行级标签、预测或私有值。若结果路径已经存在，只有逐字节等于本次精确终态时才可接受；不同时必须明确失败，禁止静默返回一个只存在于内存的替代终态。该终态仍永久禁止重试；若连终态小回执也无法发布，进程必须失败并保留已消费回执，不能伪造成功或恢复运行。

质量回执通过只表示该设计根满足冻结质量门，仍不是正式数据或模型结果。质量回执失败表示该设计根不具备继续资格；先在权威文档记录运行标识、失败阶段、根因、关键摘要和不可复用边界，再按项目纪律删除失败的大载荷与临时文件。正式生成和 M0／M1／M2／M3 始终需要后续独立授权。
