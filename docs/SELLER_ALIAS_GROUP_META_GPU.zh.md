## 实际入口与核验

`scripts/step28_group_meta_gpu_check.py`使用既有`step28_group_meta.update`，不复制或修改元算法。保持FP32、eager attention、关闭activation checkpointing、文本microbatch=32，不缩减账号、关系或可训练参数。

1. 微型GPU模型先比较直接路径与`torch.autograd.graph.save_on_cpu(pin_memory=False)`路径：同一模型/Adam起点、同一四群与随机流，比较完整目标、所有参数梯度、更新后的模型与Adam状态，并与未适应query的一阶梯度区分。该检查不加载BGE。
2. 原生BGE按预设顺序尝试直接路径；仅在CUDA分配OOM时，允许在独立进程、新证据目录中尝试CPU暂存路径。CPU暂存不改变参数或张量精度、不重算前向、不detach内层梯度。其他错误停止并核查；同定义的实现修复仍计入总预算，最多一次修复后重试。
3. 四个手写群各28账号、99商品、198条标题/描述、378关系。标题/描述分别使用手写变化文本，补到含特殊符号的21/82 token；这是根据已公开生成清单19/80字符上限构造的压力样例。另从首轮已开放`reports/seller_alias_continual/20261001/bge_continual_result/returned/job/run/manifest.json`核对`initial.maximum_tokens=82`，没有重新读取正式文本。禁止截断；程序记录实际token长度和每群商品数。手写样例不认证所有内容/形状，正式准入还须在已授权范围核对实际输入，不能拿它保证任意256-token输入都可运行。
4. 每个原生尝试最多一次warm更新，再明确把Adam计数1置288；之后执行连续两次真实元更新。记录耗时、峰值显存/RSS、encoder/head梯度及探针参数变化。计数置换只是手写夹具，不冒充完成首域训练或288步。首步失败不做第二步。

CPU暂存依据[PyTorch官方说明](https://docs.pytorch.org/docs/2.14/autograd.html#torch.autograd.graph.save_on_cpu)：前向保存的张量放到CPU，反向需要时回到原设备。该文档说明不能代替本项目既有py310版本上的二阶数值核验；实际版本与运行结果一并留证。
