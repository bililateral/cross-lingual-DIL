# 中文卖家马甲识别：具体算子的可行性筛选

日期：2026-09-06。承接[保存模型诊断](SELLER_ALIAS_METHOD.zh.md)。本文件只记录文献对照、生成器定点阅读和三个可手算构造的筛选阶段，后续[字符基线诊断](SELLER_ALIAS_CHARACTER_BASELINE.zh.md)另记。这里记录具体排除理由，不把排除候选当作论文贡献，也不添加新的流程门；尚未找到足以晋级正式实验的新方法。

研究核心仍是中文暗网卖家同控关系，允许完整合成监督，不要求获得真实中文标签。既有四臂六预算的有效负结论、训练／开发结果和 Audit A/B 封存不变。本轮没有读取项目样本或标签、生成新数据集、训练模型或连接 Linux。

## 1. 商品与交易条件的联合关系

曾考虑比较账号内部“商品属性—交易约定”的对应关系，而非两个字段各自的均值。例如公开商品记录抽象成二元组 `(属性, 约定)`：

| 账号 | 两条记录 | 两字段的均值 | 两字段的协方差 |
| --- | --- | --- | --- |
| A | `(0,0), (1,1)` | `(1/2,1/2)` | `1/4` |
| B | `(0,0), (1,1)` | `(1/2,1/2)` | `1/4` |
| C | `(0,1), (1,0)` | `(1/2,1/2)` | `-1/4` |

联合关系确实能区别均值遗漏的输入差异。按 `(00,01,10,11)` 排列的普通联合直方图已经能做到：A、B 为 `(1/2,0,0,1/2)`，C 为 `(0,1/2,1/2,0)`；总变差距离分别是 0 和 1。因此这个例子不支持“必须增加新神经网络或新关系模块”。它也没有证明 Step23 的完整商品编码或已有非线性融合必然遗漏该关系。

更重要的反例是，设 D 属于另一控制者，但从供应商取得与 B 完全相同的两条记录。在这个构造里，`(A,B)` 与 `(A,D)` 的全部规定公开特征相同，潜在同控标签相反；账号 ID 仅作索引，不作打分特征。任何只接收这些特征的确定性打分器都必须给相同分数。该反例不证明现实账号总不可区分；它否定的是把联合关系一致直接当作充分同控依据。重复整组 A 十次仍有相同的归一化联合直方图，也不能据此把复制次数算作独立身份证据。

本地重新阅读 `scripts/step28_method_root_builder.py` 的 `assign_styles`、`render_base_item` 及其构造调用：商品、属性、配送、服务来自 `content` HMAC 的逐条选择；同控信息在另行配置的风格和身份机制中。当前实现没有以控制者的经营决策函数生成这些商业关系，公开商品行也没有价格字段。因而不能拿旧根直接验证新“经营规律”假设，更不能为新模型临时造一套必然有利的规律后宣称方法可迁移。代码 SHA-256 为 `5333dfdbbdbb86566d3d2bc660ddd6fc25d11aa63561a2fc13b501a66410623b`，本轮未执行生成器。

[DarkBIP-FW，2025，第 4.2.2—4.2.6 节](https://link.springer.com/article/10.1007/s42452-025-07217-5)已使用品类、价格、时间与文本行为特征。它限制了宽泛“经营行为指纹”的新颖性；不能从论文已有这些字段，进一步臆断其已实现上述条件关系算子，也不能据此认定该算子有新颖性。

**处理：不以这个宽泛关系假设启动新数据生成或训练。**若以后有新关系，需要先说清可观察增量及共享供应商反例，普通联合统计属于必要的同输入对照。

## 2. 两类线索是否支持同一商品对应

第二个具体构造是：内容和表达两类线索，各自都能找到相似商品，但它们指向的对应是否一致？定义两张 `2×2` 相似度矩阵 `C`、`S`，以及完整二部匹配的平均权重：

```text
F(M) = max over permutations p of (M[0,p(0)] + M[1,p(1)]) / 2
J(C,S) = F((C+S)/2)
G(C,S) = (F(C)+F(S))/2 - J(C,S)
```

这是本轮审查的简化算子，不是正式账号匹配器；没有引入固定真实商品一一对应的假设。实际账号记录数不同、没有相同商品时，它尚未定义，不能直接推入正式流水线。

令 `I=[[1,0],[0,1]]`，`P=[[0,1],[1,0]]`：

| 两张矩阵 | 分开最优后的平均 | 共同对应 J | 不一致差额 G |
| --- | ---: | ---: | ---: |
| `I,I` | 1 | 1 | 0 |
| `I,P` | 1 | 1/2 | 1/2 |
| 两张全 1 矩阵 | 1 | 1 | 0 |

这个例子说明分开聚合会丢失对应关系，却也直接暴露两点：

- `J` **恰好就是先逐商品融合相似度，再作普通匹配**，不能用它击败“先各自聚合再融合”后，就宣布超越了简单融合。
- 所有商品都同样相似时，`G=0` 并不代表有明确对应，更不证明同控。完整搬用目录的异控账号同样可能支持一致匹配。回执字段 `flat_no_information` 只指没有区分商品对应的信息，不表示这组相似度在任意先验下都没有账号层面的信息。

这不是已经验证的新匹配方法。多模态对齐的一致性约束已有直接近邻，例如 [PMF，ACL 2024](https://aclanthology.org/2024.acl-long.190.pdf)；图与最优传输对齐亦有 [Chen 等，ICML 2020](https://proceedings.mlr.press/v119/chen20e/chen20e.pdf)。本轮只据已读摘要／引言和明确算子关系限定新颖性，没有复现两文算法，也没有宣称它们使用了本例同一公式。

**处理：不把上述简单共同匹配包装成新算法，不新增图网络或最优传输实现。**若后继方法只超过弱聚合，未超过同输入的普通先融合后匹配，其算法增量仍不成立。

## 3. 保持身份标签不等于保持识别信息

第三个候选是用同控标签不变的多种改写，强制模型给出同样预测。这需要区分“表达变化”和“证据被删掉”，不能仅凭私有控制者没有变化，就对所有公开视图施加强概率一致性。

可手算反例：两个等概率情形的标签分别是 0、1，完整公开输入 `X` 各含一个可完美区分标签的符号。确定性变换 `g` 删除这唯一符号，两个输入都变成同一个 `Z`。此时完整视图的后验分别为 0、1；残缺视图的后验只能为 `1/2`。按二元 `(p-y)^2` 定义的最优期望 Brier 为 `1/4`，最优期望对数损失为 `ln(2)=0.6931471805599453`。若要求残缺输入同时精确复现两个不同的完整后验，约束不可同时满足。

在**同一个固定联合分布**中，当 `Z=g(X)` 时，正确的关系是：

```text
P(Y=1 | Z) = E[P(Y=1 | X) | Z]
```

这不是任意跨域效果保证，也不是现有真实数据的数值结论。有限权重的一致性正则在别的条件下可能有用，本例不把所有增强或一致性训练一并否定。它只说明必须核查具体变换是否保留所声称的信息。完整监督下，在规定变换分布上正常计算交叉熵，本来就以相应的条件后验为总体最优解；这里假定预测函数能够表达该后验，不保证有限样本训练达到它。单独重述上式或添加一个平均教师，并不足以成为新算法。常数预测可以满足精确一致性本身；不可同时满足的是精确一致性与保留两个完整视图各自的最优后验。

[MatchDG，ICML 2021，摘要及第 1 节](https://proceedings.mlr.press/v139/mahajan21b/mahajan21b.pdf)已研究同一底层对象的跨域表示约束，其论证明确区分稳定特征与域相关变化。本轮反例不是反驳该文定理，而是禁止未经核对就把它扩大到删除任务证据的操作。作者验证中也已有[内容控制训练，RepL4NLP 2022](https://aclanthology.org/2022.repl4nlp-1.26/)和[深度 Bayes 因子评分，PAN 2020](https://arxiv.org/abs/2008.10105)，不能用“条件化”“似然”“反事实”等名称代替具体增量。

**处理：保留完整监督作为基线，不实施尚未证明适用的信息删除强一致性。**这个反例只用于训练目标审查，不另立字段删失、背景删失或弃权主线。

## 本轮执行与下一步

三个构造使用标准库 `Fraction` 与两种排列穷举，在 Windows Python 3.10.11 中完成；精确有理数与手算一致，对数损失与 `ln(2)` 在 `1e-15` 内一致。代码在内存中执行，没有落地一次性脚本。实际计算回执及完整可重放代码保存在 [cases.json](../reports/seller_alias_feasibility/20260906/cases.json)。这不是 GPU smoke、模型性能测试或新数据集，不能报告成某方法获得了准确率优势。没有更改训练语义，所以不重跑八项旧诊断测试或全回归。

本轮得到的实质结果是：**联合统计、共同匹配、无条件改写一致性，这三种具体表述都尚不足以成为新主线。**前两种不能绕过复制／共同来源解释，且存在直接的简单统计或匹配对照；第三种需要信息保留条件，已有标准监督与泛化方法必须比较。不能把这三项分别否决扩大成对所有关系学习或泛化学习的否决。

接下来仍以中文卖家马甲识别为核心寻找具体证据关系。普通联合统计或同输入的简单融合能完全实现某个候选算子时，就将它作为基线，不能换名申报新算法。**新颖性不是运行合理基线的前置条件，也不要求在实验前证明一定成功。**只要公开关系已明确、现有数据确实承载该关系，就可先做最小同输入基线比较，再决定是否需要新方法。本轮未启动的具体理由是商业机制未建立、共同匹配尚无实际逐商品双通道输入与账号级接口、信息删除强一致性的目标不相容；不是“方法简单所以不做”。目前不为产生运行结果而修改旧合成根或安排 GPU 训练。需要 Linux 时仍先汇报具体用途、输入和范围，然后暂停。
