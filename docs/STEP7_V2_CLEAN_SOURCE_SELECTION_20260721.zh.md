# Step 7-v2：在当前英文数据上重新选择 Step 28 的冻结底座

## 结论先说清楚

Step 7-v2 的代码、无标签数据准备、标签隔离、模型文件固定和 Windows 侧契约测试已经完成；五个大模型的正式打分还没有在 Linux GPU 上运行，所以现在没有“E5 最强”或“某个候选胜出”的数值结论。

这一步只能回答：在固定的 734 对真实英文数据、固定的 512 token 输入预算和预先登记的 15 个候选中，哪个候选最适合冻结后进入 Step 28。它不能证明某个编码器在所有方案中普遍最强，也不能代替 Step 28 的跨语言实验。

## 数据边界

当前英文监督数据固定为 734 对：

- 训练集 401 对：116 正、285 负；
- 验证集 152 对：42 正、110 负；
- 历史内部测试集 181 对：51 正、130 负。

三份数据分别包含 229、28、38 个连通组件和 582、105、168 个卖家。卖家跨集合重叠为 0，组件跨集合重叠也为 0。

公开配对边界来自 `component_assignments.csv`。这个源文件本身确实含有 `review_label` 列，不能说它是天然无标签文件。公开准备代码在筛选数据集和集合名称后，立即只投影下面六列：数据集、配对编号、集合名称、左右卖家编号和重算组件编号；随后才构造 734 对公开配对。代码不读取或复制 `review_label`，测试还会把该列整体改写后确认公开产物不变。

训练、验证和历史测试标签在公开语料冻结后才分别挂载。上游标签文件包含三个集合，但物化某个集合时，代码先按公开的 `split_name` 投影行，再访问该行的标签、证据类型或直接身份计数。选择阶段只打开训练和验证私有文件；历史测试文件连哈希都不计算。

## 模型到底看见什么

每个卖家只保留五个字段，顺序固定为：

1. 类别汇总；
2. 代表性标题；
3. 常见标题；
4. 代表性描述；
5. 常见描述。

原始卖家名、原始市场名、联系方式汇总、结构快照和旧 `profile_text` 不会直接送进编码器。清洗分五层：

- 第一层是固定快照人工复核过的 137 个卖家或市场身份紧凑词。121 个在当前五字段语料中实际命中，另 16 个是根据固定源市场清单预先登记但本轮没有出现的防御写法。它们在任何其他规则之前删除，大小写以及空格、下划线、连字符等展示分隔不影响匹配；只有 3 个已经确认的联系方式允许点号分隔。完整清单固定在策略文件中。词表选择只看固定快照文本、源市场清单和身份语义，不看正负标签、证据类型或所属集合；
- 第二层是当前卖家的原始别名、标准化别名和不带分隔符的等价写法，只做带词边界的精确或分隔符等价删除，不能把 `master` 从 `mastercard` 中间切掉。紧凑身份词限制为 4–96 个 ASCII 字母数字；固定快照中一条长达 138 字符、实际是商品标题的伪“卖家名”不会进入分隔符身份词表。`darkmarket` 和 `unionstore` 已登记为分隔符正文碰撞，不会进入这一层的分隔符等价表。Step 3 的噪声身份信号不再被塞进当前卖家的无条件删除表；
- 第三层是固定快照中的混合字母数字账号，可以跨卖家删除。`250mg`、`25I-NBOMe`、`BET365` 经审计属于商品内容碰撞，明确禁止无条件删除。复数形式和 `shop`、`store`、`vendor`、`sales` 等身份后缀必须以已登记身份词为基础才能删除；
- 第四层处理其他纯英文卖家名和安全身份信号：只有在 `welcome to ...`、`... vendor`、`... is here again` 等明确身份语境中才跨卖家删除。词表来自固定英文快照的全部 7,522 个卖家档案和全部安全身份信号，不只来自进入配对集的 855 个卖家；排除两个分隔符正文碰撞后，共有 16,761 个紧凑别名和 104,720 个只允许在身份语境中使用的单字符缺失变体。它不读取标签，只用于删除，不能产生模型特征。`premium`、`private`、`master`、`pfizer`、`however`、`opportunity`、`fedex`、`quality`、`support`、`microsoft`、`applestore`、`prime`、`digital`、`yahoo` 被列为正文保护词；
- 第五层用独立规则删除邮箱、网址、聊天账号、电话号码、钱包、PGP，以及 `w.i.c.k.r`、`Wick ID`、截断邮箱、缺少 `@` 的邮箱和混淆电话号码等变体。碰撞身份 `darkmarket`、`unionstore` 只在连续账号拼写下由这一层删除；普通 `the dark market`、`dark-market store`、`darkmarkets` 和 `Western Union store` 不得被拼接成账号。明确的命名市场名单语境仍可由单独规则删除。

清洗后不会插入“这里原来有联系方式”之类的人工标记。发布门槛不只看生产清洗器自报：生产扫描器逐卖家检查最终序列化文本；测试代码再用独立实现的 NFKC、大小写折叠、字符级分隔符容忍正则扫描 137 个已审计身份及其登记后缀，同时用另一条独立正则检查两个只允许连续拼写的账号；第三道审计把每个卖家、换行字段和 `||` 值分开，对 16,761 个固定快照别名做最长优先的精确、复数和身份后缀全量普查；第四道审计专门寻找已审计身份嵌在更长英文单词中的情况。四套口径的计数、哈希和公开输入哈希都写入准备清单，避免清洗器拿同一函数自证成功。

当前重建结果为：

- 855 个卖家，清洗后空文本 0 个；
- 137 个已审计卖家或市场身份中有 121 个实际命中，形成 128 种表面形式，第一层删除 1,136 次；16 个未命中的源市场防御写法仍保留在词表中；
- 通用/混淆身份规则命中 9,234 次；
- 当前卖家字面别名命中 650 次，分隔符等价别名另命中 101 次；
- 混合字母数字全局身份表共有 5,605 个词，实际删除 33 种、327 次；实际删除词用哈希计数表和总哈希固定，输入哈希变化就必须重新审计；
- 身份语境中的固定快照别名命中 521 次；
- 全量 16,761 个已知别名普查在最终正文中命中 455 个词根、535 种表面形式、35,875 次。这些词根大多也是药名、普通词或正文片段；本轮恢复的正文会把 `dark-market store` 组合成已知别名 `marketstore`，也会让普通 `Western Union store` 与同名账号发生碰撞。逐项复核后，已确认身份残留为 0，保留的 455 个全部归入歧义词或正文碰撞。三张哈希计数表固定了词根、表面形式和涉及卖家数，输入变化必须重新人工复核；
- 更长英文单词的嵌入扫描得到 4 个词根、3 种表面形式、5 次候选命中，逐条核对后只有 `BioHazard` 工具/商品名、`wallstreetbet` 论坛语境，以及普通复数 `darkmarkets` 中包含短身份词 `darkm`；已确认身份残留仍为 0；
- 最终序列化语料中的当前卖家别名、已审计卖家或市场身份、预登记混合全局身份、身份语境别名、长号码、邮箱、网址和 PGP 的已确认残留均为 0；独立正则扫描同样没有未登记例外；
- 五个源字段合计 3,825,885 个字符，清洗模型文本保留 3,566,720 个字符，总体保留率 93.23%；
- 十四个正文保护词的最低保留率是 `yahoo` 的 88.89%，其次是 `private` 的 91.97%，均高于预登记的 80% 门槛；`250mg` 为 77/77、`25I-NBOMe` 为 3/3、`BET365` 为 5/5、`Amazon Prime Store` 为 2/2；新增碰撞门槛中，普通 `dark market` 保留 55/56，唯一删除的是明确市场名单语境，`dark-market store` 为 18/18、`darkmarkets` 为 1/1、`Western Union store` 为 3/3。

这些数字是按五个源字段实际执行清洗时的替换命中次数；同一广告在代表字段和常见字段重复出现会重复计数，因此不能解释成互不重叠的身份实体数量。

本轮审查多次证明，早期版本所谓“残留为 0”不可信：第一次独立扫描就找到 31 个明确身份别名、136 次残留；随后更广的全量别名和源市场审计又发现市场名、截断联系方式及更多身份写法；独立正则还发现删除 `PROGRAMMERS` 后新拼出的 `HI-TECH HACKERS` 没被生产分词器识别。最后一次提交前复审又发现相反方向的错误：旧词表把普通 `dark market`、`dark-market store` 和 `Western Union store` 当成账号删除。当前实现把 `darkmarket`、`unionstore` 从所有分隔符拼接词表撤出，只保留连续账号精确删除，并新增四类固定快照正文保留门槛。每次发现问题后旧准备产物都被撤销并从固定输入重建，不能把任何早期“通过”当作当前证据。

这里的清洗器是针对固定英文快照做的无标签、传导式去身份，不是一个已经证明能处理任意新卖家的归纳式身份识别器。“残留为 0”只覆盖预登记规则、当前卖家别名、高置信全局身份和有明确身份语境的固定快照别名；它不等于未知身份绝对为 0，也不把与正文词冲突的任意卖家名强行删掉。

## 五个编码器、一个共享重排器

五个编码器读取完全相同的清洗文本：

- GTE multilingual base；
- BGE-M3；
- multilingual-E5-large；
- LaBSE；
- paraphrase multilingual MPNet base v2。

调用方式由各自本地 Sentence Transformers 模块决定：GTE、BGE 和 LaBSE 使用 CLS，E5 和 MPNet 使用平均池化；LaBSE 保留自己的 Dense+Tanh 层。E5 是对称的卖家相似度任务，所以两边统一加 `query: `，不把一边伪装成检索文档。

所有编码器和共享重排器统一使用 512 token 上限。这是在同一计算预算下比较的预登记约束，不代表长文本已经被完整读取。Linux 会为每个 tokenizer 记录真实长度、截断行数和比例；若截断很多，只能把结论表述为“512 token 方案中的最优者”。当前按空格粗略统计已有 414/855 个卖家超过 512 个词，因此正式报告必须展示 tokenizer 的截断统计，不能隐去这个限制。

共享 GTE 重排器也只读相同的清洗文本。卖家对没有天然方向，所以分别计算左到右和右到左，最终取平均。配置必须证明它是自定义序列分类模型且只有一个相关性 logit，单 logit 经 sigmoid 转成分数。

五个编码器和重排器都固定了本地文件清单、总字节数和逐文件 SHA-256。同步、GPU 运行和结果回收会重复核对同一内容指纹。GPU 清单还固定代码、策略、公开配对、清洗语料和准备清单的哈希。

Linux 返回的每个编码器分数不能只靠 CSV 自报。Windows 会重新读取固定的单位化卖家向量矩阵，对全部 734 对重新计算点积，并要求与 CSV 的绝对误差不超过 0.000002；来源清单正确但数值不一致的结果会被拒绝。

## 15 个候选如何训练

每个编码器形成三档，共 15 个候选：

1. 只用该编码器的卖家文本余弦相似度；
2. 余弦相似度加 20 个非直接身份特征；
3. 再加同一个双向平均重排器分数。

20 个附加特征包括：同市场和同数据源布尔值、去身份后的类别重合、标题/描述精确克隆及训练集 IDF、商品规模和文本风格差值。原始市场字符串不会进入模型，模型只看到“两边市场是否相同”这一位。所有标题/描述文档频率、数值百分位参照都只由 582 个训练卖家计算。

联系方式、PGP、卖家名、候选生成规则、人工证据类型和标签不能进入 M0。直接身份规则分数只作为单独报告的上限语境对照，没有候选资格。

每个候选是一套标准化 L2 逻辑回归：

- 只用 401 对训练；
- 同一训练组件中的所有行合计权重相同，另做完全等权训练作为敏感性检查；
- 训练内部做五折组件分组交叉验证，同一组件绝不跨折；
- L2 从 0.1、1、10、100 中按与当前训练权重一致的训练折外加权平均精确率选择；
- 分类阈值只用所选 L2 的训练折外预测确定，并按相同权重优化平衡准确率；
- 选好 L2 后仍只用 401 对重训，再对 152 对验证集打分；
- 保存全部 15×401 条训练折外预测和 15×152 条验证预测，便于逐行复核。

人工证据类型不参与特征、训练权重或平均精确率排序。它用于验证集和历史测试集的难负样本误报率、直接证据正样本召回率切片；验证集上的这两个切片还参与“是否允许声称唯一胜者”的安全门槛，因此不能再描述成只报告、不影响选择结果。

## 如何决定是否存在唯一胜者

验证集平均精确率是第一排序指标，AUC-ROC 只负责同分排序。第一名必须同时满足：

- 验证平均精确率比第二名至少高 0.02；
- 对验证集连通组件做 5000 次分组自助抽样后，平均精确率差值的 95% 区间下界大于 0；
- 完全等权训练时仍在全部 15 个候选中排名第一，并优于等权排序中的最佳其他候选；
- 在验证集按组件等权重新计算平均精确率时仍保持第一，并且仍严格优于第二名；
- 相比第二名，难负样本误报率最多增加 0.01；
- 相比第二名，直接证据正样本召回率最多下降 0.05。

这些检查是开发集稳定性门槛，不是经过多重比较校正的确认性显著性检验。若任何一条不满足，就不声称“唯一最强”，而是携带“验证排名最高的 E5 档位”和“验证排名最高的非 E5 档位”进入 Step 28；不是固定携带 E5 完整档。

报告 AUC-ROC、平均精确率、精确率、召回率、F1、特异度、平衡准确率、准确率、Brier 和对数损失。另报告 MRR、Hits@1、Recall@1/3/5，但这些排序指标只在已经人工审核的候选对中计算，不是全库检索指标。
