# Step28-v13 v1.13 v9 可见文档容量修复合同

日期：2026-08-14
状态：`DESIGN_IMPLEMENTATION_ONLY_NO_REBUILD_OR_TRAINING`

## 1. 目的与权限边界

本合同只处理 v8 第五次设计构建在训练序号 283 暴露的可见文档容量缺陷。它不改变科研主问题、四拆分规模、控制者图、标签公式、身份机制、三十三维身份历史、历史排除集合、候选上限或 M0／M1／M2／M3 定义。

当前只允许实现、静态性质测试、已暴露训练序号 0 至 283 的内存因果回归和独立运行前审查。禁止再次构建 1,004 世界设计数据，禁止正式 500×4、正式种子、质量结论、真值解封、模型训练和指标报告。

## 2. 已确认根因

严格顺序重放训练序号 0 至 283 后，前 283 个世界正常接受；目标世界 32 个候选中，22 个只命中当前商品文档，10 个同时命中历史商品和当前商品文档，四类卖家或同世界碰撞均为零。全部候选共同命中的当前商品哈希只有：

`c53306118f9206926401318ec148e78f84c0dba0a1c0ea2690d6b33d548a9add`

其首次来源是训练序号 258。来源和目标商品均为标题“支持自选参数批量排版工具 通用款”、空描述。目标商品的模板没有 `{code}`，属性轨道只有一个状态，完整商品代码虽不同但只有倒数第二个符号影响“通用款”，所以该商品在 32 个候选中只有一个最终可见状态。增加候选数量、删除十次历史命中或追加一个局部词都不能构成全局修复。

## 3. 被拒绝的修复

- 不增加第 33 个候选，不换盐，不改变历史排除集合。
- 不写训练序号 283、商品标识、标题或碰撞哈希特例。
- 不在生产文本末尾直接拼接代码。内存反事实已经证明这种做法会被正式生产解析合同以“观察描述不是登记语法树实现”拒绝。
- 不继续把 40 位 HMAC 截断值未经证明地称为全局唯一。旧基础策略虽写明碰撞即失败，但旧科学构建链没有构造性唯一分配。
- 不只给第 32 个候选增加特殊格式。候选角色可见会制造不必要的合成域差异。

## 4. A：逐商品非空载体投影

基础卖家缺失率和原缺失提案算法不变。第一个满足“至少一个标题、至少两个描述”的卖家提案接受后，只处理其中原始状态为 `(title=False, description=False)` 的商品：

1. 使用既有 `document_variation_key`、固定新域和该商品标识作 HMAC；
2. 由固定一位决定投影为 title-only 或 description-only；
3. 不重抽整份卖家掩码，不改变其他三个缺失状态，也不读取登记表、候选、标签、控制者或模型结果；
4. 基础世界必须先完成覆盖端点资格化、噪声槽、身份槽和原始三十三维身份历史；投影只能发生在随后创建的 v9 候选可见文本父视图，禁止回流到基础求解器；
5. 原 joint-empty 商品在投影前必须证明没有身份槽、噪声槽或登记覆盖端点；否则整个世界失败，不得移动槽位或更换投影；
6. 私有回执记录原掩码、投影方向、前后结构承诺和逐字段零副作用证明，不保存新的选择自由度。

该投影不是训练序号 283 的直接处理，因为目标商品本来已有标题；它只关闭完全空商品无法承载任何可见见证的定义域缺口。

## 5. U：同格式、构造性唯一的商品代码

代码格式继续固定为 `Q[A-P]{10}`，不显示商品、卖家、控制者、拆分、候选或机制标识。每个 mode 内的唯一输入槽位定义为：

`x = mode_global_ordinal * 256 + seller_slot_ordinal * 8 + item_slot_ordinal`

其中：

- `seller_slot_ordinal` 是基础卖家标识构造器实际使用的创建槽位，恰为 0 至 27；禁止用卖家标识排序、输出行序或控制者内部次序替代；
- `item_slot_ordinal` 是基础商品标识构造器实际使用的创建槽位，恰为 0 至 `item_count-1`，且不超过 7；禁止用最终商品排序或候选输出位置替代；
- 256 是冻结世界步长，大于每世界最大 224 个商品槽；
- `mode_global_ordinal` 来自冻结世界记录，跨四拆分唯一，且必须满足 `0 <= mode_global_ordinal < 2^32`。

使用既有 `document_variation_key` 经固定新域派生唯一代码子键，对 40 位 `x` 执行六轮、左右各 20 位的 HMAC-SHA256 Feistel 双射；不执行额外末轮交换，按大端顺序把十个半字节一一映射为 A 至 P，并加前缀 Q。六轮不是安全性声明；本合同只使用每轮双射所提供的严格单射性质。实现必须提供独立逆变换，并逐商品验证逆变换恰好恢复原始三个创建槽位。因为输入槽位唯一且置换是双射，代码在 mode 内构造性唯一；构建器仍必须登记实际代码并要求 `item_count == unique_code_count`，任何不一致直接失败且不得换键或重抽。

每个世界还必须双向验证：由 `seller_slot_ordinal` 重建的卖家标识等于实际卖家标识，由 `item_slot_ordinal` 重建的商品标识等于实际商品标识；28 个卖家槽无重复无缺口，每个卖家的商品槽无重复无缺口。布尔值不得冒充整数。

代码生成不读取控制者、标签、身份机制、拆分名、候选编号、文档登记表或质量结果。它是商品级随机批次元数据，不在同控制者卖家之间共享。代码可见性、字符分布和 pair 级交集仍必须进入禁止捷径及 M0／M3 公平性敏感性审计。

## 6. B：描述优先的原生模板见证

所有 32 个候选执行同一规则，不设置特殊容量候选：

1. 候选模板的每个拆分保留原 8 个标题和 8 个描述模板；
2. 对每个原本不含 `{code}` 的模板，追加一个机器可逆验证的自然代码孪生版本；标题版本在原模板后加入“编号 `{code}`”，描述版本在固定的 noise／context／identity 后缀之前加入同风格分隔的“编号 `{code}`”；
3. 先按既有候选密钥完成原 8 个模板内的无标签映射；若描述非空，则描述使用对应的含代码版本，标题仍用原映射结果；若描述为空，则标题使用对应的含代码版本；
4. 代码子句始终位于噪声、上下文保护和身份子句之前，由正式语法树、渲染器、解析器和脱敏链共同重放，禁止最终字符串硬拼；
5. 原 8 个模板到“自身或其唯一含代码孪生模板”的映射必须为一一映射；两个原始标题模板索引不同，映射后仍然不同，禁止读取高语义负例登记后为某一对端点另选模板；
6. 简繁转换、标点、行模式、英语标签和身份区域规则继续由原生产模板控制。

因此每个最终商品文档至少保留一个自己的完整代码，且不存在某个候选角色专有的代码可见率。

## 7. 精确标题克隆闭包

精确克隆的卖家对、方向和商品端点资格不变。目标商品仍必须同时有标题和描述。候选先完成两侧原生渲染，再只复制 source title 到 target title：

- target 的自己的唯一代码保留在 target description；
- source 有描述时，source 自己的代码在 source description；
- source 为 title-only 时，其代码随标题复制给 target，但 target description 仍含 target 自己的代码；
- 两侧标题必须逐字相同，完整商品文档哈希必须不同；
- source code 出现在 target title 只允许由登记的 source→target 标题复制产生。

四个高语义负例的两个原始标题模板索引保持不同；含代码版本必须与原索引一一对应，不能把两个端点合并到同一模板。

## 8. P：固定候选 0 谱系锚

旧的无全覆盖代码 baseline 不再作为候选画像来源谱系锚，因为全局文本表示已经合法改变。基础世界完成后，先计算旧基准三十三维身份历史；再执行 A＋U，并由其结果计算新的 v9 结构父摘要；B 只能在该结构父之上改变登记的自然表达。新的来源谱系锚固定为同一世界的候选 0 实际生产得到的来源多重集：

1. 候选 0 的密钥仍由原冻结公式和索引 0 得到；
2. 先无条件构造候选 0 并冻结来源多重集；此步骤不读取碰撞、标签、控制者或模型结果；
3. 随后才检查候选 0 的六类碰撞；即使候选 0 被拒绝，其谱系锚也不改变；
4. 候选 1 至 31 的来源多重集必须与候选 0 完全一致，否则在碰撞判定前失败；
5. 候选 0 只能构造一次，锚形成前碰撞函数调用计数必须为零；若候选 0 生产、解析、脱敏、结构或身份历史失败，整个世界失败，禁止改用其他候选建锚；
6. A／U／B 前计算的三十三维身份历史为旧基准；全部候选必须逐字节等于该基准；A＋U 后的结构父摘要必须在候选循环前冻结，全部候选逐字节相等。

内存反事实已在一个旧小世界证明：使用原生含代码模板时，32 个候选只有一个来源多重集承诺，同时每个候选均有 125／125 个唯一商品文档和 28／28 个唯一卖家文档。该事实只是实现方向预检，不是数据质量结果。

## 9. 容量证明义务

同世界及当前数据商品文档的构造性证明必须同时具备：每件商品有载体、每个商品自己的代码唯一、代码在最终脱敏文档中完整存活、克隆外来代码例外闭合。

卖家五字段文档还必须证明：每个卖家至少两个非空描述；商品数最多 8，小于冻结 `description_top_k=12`；每个非空描述在 280 字符截断之前出现自己的代码；`description_concat_top` 至少保留一个本卖家独有代码；28 个卖家文档哈希两两不同。

历史商品和卖家文档不能仅靠唯一代码作逻辑推断。每个候选仍必须对冻结历史集合执行零交集证书，且候选只能因原六类精确碰撞推进。映射不能读取该证书并自适应改代码、模板或密钥。

## 10. 必须新增的测试与审计

- 训练序号 283 严格因果回归：钉住旧 32 候选共同哈希、来源序号 258、正式序列化字节、覆盖端点状态和登记表不变；新状态必须消除共同碰撞且六类碰撞闭合。
- A 隔离：非 joint-empty 商品逐字节不变；投影商品原本没有身份、噪声或覆盖端点；投影发生在基础世界与旧基准身份历史冻结之后；除两个非空布尔值和相应登记文本载体外，控制者、标签、身份、噪声、端点和数量逐字节不变；四拆分和简繁均覆盖。
- U 性质：Feistel 正逆互逆；所有允许槽位无重复；输入边界、创建槽位与标识双向重建、代码格式和实际登记数量闭合；拆分、候选、控制者或标签不进入消息。
- B 组合：四拆分、原 8 个标题和描述模板、三种行模式、简繁、噪声和零／一／多身份子句全部通过语法树重放、解析和脱敏；统一遮蔽代码后可恢复登记的非代码内容投影。
- 克隆：标题逐字相同、完整文档不同、target own-code 存活、外来代码只来自登记复制；高语义模板不同性不变。
- P 谱系：候选 0 锚在碰撞前形成，模拟碰撞结果改变不得改变锚；1 至 31 逐一相等；任何伪造来源变化必须先于碰撞失败。
- 卖家文档：每个正式五字段文档含本卖家独有码，28 个哈希唯一；降低描述压缩上限或删去代码载体时必须失败。
- 捷径：新增完整文本、统一字面代码遮蔽文本和代码通道完全中和文本三种视图；代码通道完全中和还必须固定代码载体模板、标题修饰词和英语标签等代码派生通道。审计代码数、可见率、distinct／foreign 数、pair 交集、Jaccard、字符相似度及克隆共享代码。训练／开发禁止元数据门槛不因本修复放宽。
- 代码与槽位硬门：固定逻辑回归和浅树分别运行 code-only 与私有 decoded-slot-only 探针；后者只能在私有审计中逆变换恢复三个槽位。两者使用既有禁止元数据阈值，失败后不得换 Feistel 域、密钥、轮数或模板重生成。
- M0／M3 敏感性：后续训练合同必须预先冻结完整、字面遮蔽和通道中和三种成对重放，分别解释 M2−M1、M2−M0 和 M2−M3-joint；不得用敏感性结果筛数据或改生成规则。

## 11. 失败和清理

任一设计测试、已授权因果回归或独立审查失败，先记录版本、阶段、根因、关键哈希、结论边界和不可复用承诺，再删除失败数据、缓存、临时目录及 v9 专用失败代码。只保留小型文档和未来关闭失败所需的哈希。不得保留未发布世界前缀，不得从失败前缀续跑。

本合同通过实现和独立审查之前，v9 不具有任何构建授权。
