# Step 7-v3.1：完整卖家文本的共享分块编码器复核

## 目的与结论边界

Step 7-v3 已在五个编码器之间使用统一的 512-token 单窗口。该合同形式公平，但约六成卖家发生截断，因此只能回答“统一 512-token 单向量条件下谁更好”，不能判断完整卖家历史下哪个编码器最强。

v3.1 是同一英文开发数据上的完整文本敏感性实验。它不修改标签、卖家、pair、split、脱敏文本或模型快照。旧 v3 的实现与结果产物已经删除，仅保留历史文档；v3.1 不在运行时读取任何 v3 文件，而是从固定输入独立重放数据，并用原产物哈希证明字节一致。由于 `valid=152` 已被 v3 消费，v3.1 仍是内部开发分析，不是新的独立确认。

## 固定数据与隔离

- 英文 pair 固定为 `734`：train `401`、valid `152`、历史 test `181`。
- 卖家固定为 `855`，跨 split 卖家与连通分量仍完全隔离。
- 五个清洗字段及顺序不变：类别、签名标题、标题、签名描述、描述。
- v3.1 从固定的 seller profile、身份信号和 component assignment 独立重放脱敏过程，再把各字段拼回完整文本；855 个卖家必须全部复现预注册的字段语料哈希 `7e9d0948…9655`。
- GPU 工作区只允许出现无标签 pair 清单、字段语料、代码、policy 和五个模型目录；训练/验证/历史测试标签及原始快照全部禁止出现。

## 共享分块合同

分块在任何标签读取之前完成。五个 tokenizer 共同决定唯一一套文本块：每块连同模型前缀和特殊 token 最多 `480` token，任意一个 tokenizer 超限就继续缩小。块之间不重叠、不抽样、不设块数上限；每个非空字段的全部字符必须按原顺序恰好出现一次。五个编码器读取完全相同的块字符串和块顺序。

480 而不是 512 是为不同模型的前缀和特殊符号保留空间。正式编码前后都重放每块的 tokenizer ID；若分块 tokenizer 与 SentenceTransformer 实际 tokenizer 不一致，实验立即停止。

## 固定聚合分数

每个模型对每块产生一个归一化向量，再固定计算六项 pair 分数：

1. 全部块的平均向量余弦；
2. 五个字段分别求平均向量余弦，再对双方都存在的字段等权平均；这是原始编码器排名唯一使用的分数；
3. 双向逐块 top-3：左侧每个块取右侧最高三个余弦后平均，再做右到左，最后两方向等权；
4. 类别块平均向量余弦；
5. 标题组块平均向量余弦；
6. 描述组块平均向量余弦。

逐块 top-3 不采用“所有块对的全局最高三个”，因为后者会让长文本仅凭块对数量更多获得极值优势。若某一字段组在任一卖家缺失，组分数复用该 pair 的字段等权分数，不写入 `0/-1` 之类可暴露缺失状态的哨兵值。块数、字符数、token 长度和字段缺失率只进入审计清单，禁止作为模型特征。

## 比较与训练

原始编码器比较不训练分类头，只比较五个模型的“字段等权”验证分数。完整管线统一训练标准化 LR/L2：

- 每个编码器的六项聚合分数；
- 六项聚合分数加 18 项原 v3 迁移特征。

因此共有 `5 × 2 = 10` 个可选编码器管线。另有仅截距、仅 18 项迁移特征两个匹配归因对照，以及一个只含市场/来源捷径的审计模型，共 `13` 个。共享重排器退出本轮，因为它不能遵守同一“卖家块向量—固定聚合”合同。

训练仍只用 401 条 train：五折 seller-component 隔离 OOF 选择 L2，阈值只由 train OOF 的分量等权平衡准确率确定，再在全部 train 上重拟合。valid 只用于本轮开发排序。主指标仍是市场/来源分层内的 component-equal AP 宏平均，同时报告 ROC-AUC、逐行 AP、Precision、Recall、F1、平衡准确率、MRR 和 Recall@K。

一个管线只有同时超过第二名、通过连通分量 bootstrap、在全局/逐行/均匀权重敏感性中保持一致、不过度伤害困难负例和直接正例，并显著超过完全匹配的无编码器对照，才能称为可归因赢家。否则只保留前两名开发候选，并明确报告未区分或归因失败。

## 执行顺序

Windows 生成字段语料和无标签同步清单：

```powershell
python scripts\step7_v3_1_prepare_source_data.py --stage public
python scripts\step7_v3_1_prepare_source_data.py --stage development-labels
python scripts\step7_v3_1_encode_chunked_models.py --validate-shared-chunking-only
python scripts\step7_v3_1_build_sync_manifest.py
```

当前 CPU tokenizer 预检固定得到 `855` 个卖家、`4198` 个非空字段、`5378` 个共享块；每个卖家块数最少/中位数/P95/最多为 `1/5/10/19`，五个 tokenizer 的超预算块均为 `0`，所有字段均逐字符完整重建。共享块规范哈希为 `da208349…aeca53`。

Linux 完整仓库只运行隔离启动器：

```bash
bash scripts/run_step7_v3_1_full_text_chunked_linux_20260722.sh
```

GPU 输出同步回 Windows 并通过逐文件 SHA-256 和数值重放后：

```powershell
python scripts\step7_v3_1_select_source_model.py --stage select
```

本轮选择器没有历史 test 执行入口，避免在代码仍处于完整文本开发阶段时再次消费旧测试标签。
