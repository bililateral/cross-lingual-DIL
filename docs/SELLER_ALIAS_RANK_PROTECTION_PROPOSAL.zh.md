# 下一步性能改进：排序保护方案待审

2026-10-07。**仅为可审议的方案，不是已批准算法或运行合同。** 用户最新原话：“继续按之前的要求修改，我允许你按你自己的想法来修改，可以修改算法核心，但必须经过我和外审审批。有问题就问”。这取代此前在新设计中不得改变关系目标记忆核心的限制；研究问题、性能目标、数据边界和历史事实保持。先开展具体方案讨论与外审，再将收敛后的变更和执行范围交用户审批，双审齐备后才实施科学变更／进入新增计算。

## 1. 要解决的问题与证据

仍研究有限历史信息下，新卖家群体分批到来时的旧分布未见卖家候选排序和基础识别；中文受控三域、每群28账号／每查询27候选，不转向身份追踪、作者分类或AI文本检测。用户优先级仍为旧域保持、兼顾整体排序提升，并完整披露新域及识别代价。

函数记忆20261006_231800已有效完成但五条件0/5：O MAP .425195对LOGIT0.1 .460800，最终整体.433623对.463530。共享首域完全一致，第二阶段新域已落后，最终遗忘更大；初始D约零仍失败。D接通、全部1728步裁剪、CAB第三阶段6A/0C但N96等均已核对，不能由此对单个模块定因。结果外审及主审已关闭，见[完整分析](SELLER_ALIAS_FUNCTION_MEMORY_RESULT.zh.md)和[主审](../reports/seller_alias_continual/20261007/function_memory_result/review/report.zh.md)。

本次设计判断：不以继续修补统计运输或调整D系数作为默认下一步。小缓存到全部历史的函数近似没有兑现收益；更可解释的下一步是保留已验证较强的LOGIT0.1路径，单独改变旧查询排序保护方式。这个判断是候选选择理由，不是“运输已被证明是唯一病因”。

## 2. 首选待审候选：在完整LOGIT0.1上增加选择性次序保护

科学起点改为既有完整LOGIT0.1：J0=B当前+0.1B历史+0.5 MSE历史分数。完整B仍为BCE+query-rank+0.5 top5-hard。保留baseline头、共享首域model/Adam/RNG、当前和历史两次随机训练前向、历史来源阶段的FP32分数、同一Algorithm R六群与历史抽样、同一裁剪和AdamW；不沿用函数记忆的确定性历史模式、H/b/c运输、FP16坐标及直通估计。

**新增机制只针对缓存里真实可计算的旧排序。** 对历史群中查询q，正候选集合Pq、负候选集合Nq均来自该群已允许的拟合监督。来源阶段冻结教师分数为t，当前同一次历史前向分数为s。记教师间隔a(q,p,n)=t(q,p)-t(q,n)，当前间隔m(q,p,n)=s(q,p)-s(q,n)。只保护a>0的正负比较，目标间隔b=min(a,1)。定义：

R = (1/28) Σq (1/|Pq|) Σp max({[b(q,p,n)-m(q,p,n)]_+² : n∈Nq且a(q,p,n)>0} ∪ {0})。

待审单点总目标J=J0+βR，**初始讨论值β=0.1、间隔上限1**，这两个值是未经效果验证的启发式，均未获执行批准。外审应审查其尺度和必要性；若更改，须在任何新运行前明确最终值，不能根据新valid调节。本轮不先列一个大候选网格。

- 每查询及每正候选等权；对教师原先排对的比较，抓取当前最严重的违反，不让大量安全负例稀释该比较。
- R在当前满足全部受保护下界时为0，梯度也为0；改进已有间隔不受R惩罚。这里仅描述新增R，J0的MSE仍对任何分数偏移施加双向约束，不能声称整个新算法不限制改进。
- 教师原先排错或相等的比较不进入R，仍由现有监督B学习；不是从teacher读真值。不能宣称解决所有教师错误，因为保留MSE也保留了其相应拉回作用。
- teacher固定且不反传；max并列采用固定候选索引顺序，正负候选由既有对称378边映射，不混用当前群标签。共享边同时影响两端查询，实际反传须保留该累积。
- 只保护缓存中教师已经排对的比较，不保证未见旧群MAP，也不保证群AP、概率校准或全体查询改善。当前历史训练Dropout与阶段末确定教师不同，不能要求每个阶段起点的随机R精确为0。
- 不新增历史教师模型、持久表示或全历史统计；教师分数与原始六群均沿用LOGIT内存。该候选放弃原累计统计核心，不能沿用“保存了全部淘汰群知识”的主张。

预期优点是直接面向查询内正负次序、改动较少、没有额外encoder前向；预期风险是与已有query-rank/top5-hard及MSE高度重叠，单个最坏比较可能放大噪声，六群代表性依旧有限，附加梯度仍可能伤害新域。无性能保证。

## 3. 为什么不能马上宣称创新或马上训练

FDR已有边界样本输出保持，DER/DER++已有历史输出重放，DarkRank已有排序知识迁移，L²R已有持续检索记忆与排序对齐。本候选中的hinge、困难负例、teacher正确筛选和截断间隔均不能单独称为原创。**目前只达到有明确公式、可被否证的性能候选；尚未建立足以支撑论文的方法贡献。**

还需外审正面回答：R相对于已有top5-hard与MSE是否只有常规重加权；其teacher依赖和单向截断是否提供实质新增约束；在同预算下是否存在更有依据、同样简洁的机制。若只是弱增量，不应为了试出好分数就把它包装成最终算法。外审可以否决首选并提出一个更有价值的替代，但须给完整输入、记忆、目标、梯度、时序、成本和失败反例，不只罗列名称。

比较过但暂不执行的方向：

|方向|本轮判断|
|---|---|
|继续H/b/c迁移，换D系数或ridge|现有证据未定位原因；单凭标量大小调参缺乏依据。暂不首选，不认定整个方法家族无效。|
|改成按查询／账号压缩保存或学习选择记忆|可能提高1MiB利用率，但会改变六完整群及选择权，需同预算的合格对照和新的明确用户授权；不能偷偷作为首选实现细节。|
|多教师、参数隔离、额外adapter或元梯度|模型状态和计算预算的公平性需另论，不绕过已关闭group-meta路线，不作为这次默认扩展。|

## 4. 若方案被双审认可，下一份合同应固定的最小范围

以下是待审批建议，不是已授予计算额度。先收敛机制，再编制冻结合同，避免先实现一个尚不成立的创新主张。

1. **独立实现与手写核验。** 不修改冻结原件及原版；新入口只增加被批准的机制。β=0分支须真正调用未变baseline更新，不额外前向／随机数／零损失图；与baseline在微型完整Adam状态下严格对应。新增R用独立字面枚举、梯度参考和故障反例证明漏R、断梯度、错teacher/标签、对称索引、query不等权不能通过；检验保护、无保护、越界、改进和教师错误情形。无需重跑不受影响的历史测试。
2. **建议新增手写CPU额度：** Linux现有py310，单空闲CPU、累计10分钟、RSS2GiB、证据16MiB；不载BGE、不用GPU、不读正式数据。失败留证停止，不自动重试。须用户批准该新增范围后才运行。
3. **建议新增BGE原生额度：** 实现外审／主审通过后，一次手写完整步，GPU0、单CPU、10分钟、reserved28GiB、RSS64GiB、证据128MiB；当前／历史各448×256，首次Adam分配、R独立encoder/head梯度及总更新，验证无额外encoder前向。无正式数据，失败停止。
4. **建议正式单候选：** 用户及外审确认最终公式／参数、核验与接入通过后，从共享首域完整状态开始；s0、ABC/BCA/CAB、1728新更新、9逻辑端点，墙钟24小时、产物24GiB、reserved28GiB、RSS64GiB。仅一个候选，β=0不新增正式训练，复用LOGIT0.1已保存结果。共享首域只合法构建本候选允许的六群及来源分数，不加载已删除训练权重，不恢复淘汰样本。
5. **建议访问与停止：** train、valid标签各一次新尝试；所有训练、校准、盲评分及完整门后一次开valid；test/owners/Audit为0。无中途结果选择、自动重启、调参或第二候选。新许可不会使开发valid成为独立留出。
6. **建议效果门：** 继续以ΔO MAP条件95%区间下端>0、Δfinal_all MAP观察值>0作为收益；A2 MAP、Z MAP、O AP区间下端各≥−.01作为代价门，全部22指标照报。此前用户接受的1个百分点只是旧合同许可；此处请求未来重新确认，不因旧结果难看放宽，也不把五条件称同时95%保证。

当前完成条件是：提交完整背景的方案外审，独立处置后拿出一个最终方案供用户审批。新执行合同尚未批准，生产算法尚未改动，不启动CPU/GPU或标签读取。用户批准与外审意见任何一项缺失，都不能视作已有双审准入。
