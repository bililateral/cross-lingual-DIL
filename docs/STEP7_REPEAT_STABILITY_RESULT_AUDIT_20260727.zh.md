# Step 7-v4.2：Windows 新折分种子稳定性复跑审计

更新时间：2026-07-27

## 结论

本轮没有确认原 operational M0-primary 仍是最强模型，也没有选出新的稳定 M0。

原候选 `LightGBM + legacy18 + LaBSE` 在五个全新外层种子的完整 train 汇总中由第 1 降至第 2；第 1 改为 `LightGBM + legacy18 + E5 + LaBSE`。两者分量等权 AP 只差 `0.002655`，95% 分量 bootstrap 区间为 `[-0.012854, 0.019984]`，跨过 0。新冠军只赢得 `2/5` 个种子，同时严格超过全部 22 个候选的 bootstrap 概率仅 `0.4876`。

去精确文本克隆后，原候选排第 10，汇总第 1 变为 `L2 + legacy18`，但后者的 pair AUC 仅 `0.351780`。分量等权与 pair 等权发生严重反转，不能挑选较高口径宣布成功。正式状态应保持：

```text
no_stable_unique_current_best_style_free_pipeline
formal_m0_certified = false
```

## 实验边界

- 数据仍是同一批真实英文 train：`401 = 116 正 + 285 负`，229 个 seller components。
- 去克隆集：`286 = 27 正 + 259 负`，174 个 components。
- 候选、特征、分类器、调参网格、权重、阈值和指标全部复用冻结 Step 7-v4.1。
- 只更换五个预先冻结的新外层种子：`2026072701…2026072705`；旧种子为 `2026072201…2026072205`，两者无交集。
- 旧 valid 和历史 test 标签均未读取。
- Windows CPU 环境：Python `3.10.11`、NumPy `2.2.6`、SciPy `1.15.3`、scikit-learn `1.7.2`、LightGBM `4.6.0`。
- 本轮是同数据换折分稳定性诊断，不是新独立英文数据确认。

五个种子冠军依次为：

1. LightGBM：legacy18+LaBSE
2. LightGBM：legacy18+E5+LaBSE
3. LightGBM：legacy18+E5+LaBSE

因此 LightGBM 家族在克隆丰富的完整集上较强，但具体特征组合不稳定。相对旧 v4.1，原 primary 的分量 AP 从 `0.944873` 变为 `0.934114`；变化来自折分，不是模型或数据合同变化。

## 去克隆结果与根因

| 候选 | 分量 AP | pair AP | 分量 AUC | pair AUC | pair PR-AUC | pair F1 | pair Recall |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| L2：legacy18（分量口径第 1） | 0.813458 | 0.245831 | 0.929807 | 0.351780 | 0.239795 | 0.311111 | 0.259259 |
| LightGBM：legacy18+LaBSE（原 primary，第 10） | 0.442091 | 0.366343 | 0.924976 | 0.830759 | 0.352964 | 0.354167 | 0.629630 |

去克隆删除的 115 条 pair 中有 `89` 个正例和 `26` 个负例，即删除全部正例的 `76.7%`，但只删除负例的 `9.1%`。完整集高分明显受精确文本重合捷径抬高。

剩余正例只有 27 个，并且仅 8 个连通分量含正例；其中 20 个正例集中在一个 40-row 巨型分量。分量等权会把该巨型分量整体压到权重 1，同时大幅放大小正向分量；pair 等权则相反。这解释了 L2 模型“分量 AUC 0.930、pair AUC 0.352”的表面矛盾，也说明当前去克隆数据无法可靠决定哪一种口径代表真实部署分布。

去克隆五个单种子冠军互不稳定，且汇总冠军 `L2 + legacy18` 在 `0/5` 个种子中单独夺冠。不能把排名反转解释为“L2 已被证明最好”。

## 检索指标边界

完整集只有 10 个查询卖家同时拥有至少一个已标正候选和一个已标负候选；原 primary 的 MRR/MAP 为 `0.900000/0.862900`。去克隆后仅剩 3 个可评查询，原 primary 的 MRR/MAP 为 `0.361111/0.383333`。MAP、MRR、Hits@K、Precision@K 和 Recall@K 均已报告，但标签候选图不完整，只能作诊断，不能参与 M0 选择。

## 后续边界

当前可以把某一候选预先固定为“下游工程用 operational baseline”，但不能称为已经选定或独立证明最强的 M0。正式选定 M0 仍需要冻结少量完整流水线候选后，新收集互不连通、无精确文本克隆的真实英文正向身份分量，并一次性确认。
