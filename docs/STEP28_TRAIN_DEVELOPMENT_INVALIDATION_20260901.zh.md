# Step28-v13 V9.4.1 训练与开发执行 V1 失效记录

## 终态

V1 运行目录为 `reports/step28_model_experiment/v9_4_1_train_development_v1_20260901/`。训练和开发计算正常结束，但发布后的独立重载检查发现两份 LightGBM（轻量梯度提升树）文本模型不能由 `model_file` 接口重新载入。因此本轮属于发布序列化机械失败，不具备正式模型产物资格，整个 V1 目录必须删除且不得复用。

## 失败阶段与根因

失败发生在模型训练和开发指标计算之后、正式产物重放检查阶段。Windows 上的 `Path.write_text()` 把 LightGBM 模型字符串的换行从单字节换行改写为回车加换行：

- M3-base：192,679 字节，3,957 个回车加换行，SHA-256 为 `3e72c2d8e1b24376b1ed418a42a85967bca0330fe3d87f024ad42164fd595469`；
- M3-joint：195,834 字节，3,963 个回车加换行，SHA-256 为 `ab74e492d8b2337792c7cf6bdb9361755ad6b46f8b6612787cb79d917d5aa9de`。

LightGBM 4.6.0 从文件读取这些字节时报模型格式错误；把相同文本在内存中恢复为单字节换行后可以载入 200 棵树，证明根因是保存层换行改写，而不是训练器或模型参数损坏。

## 结论边界

V1 的训练、开发标签和开发检索真值各读取一次，训练集检索真值及审核 A／B 真值读取均为零；没有生成审核预测。内存模型产生的开发预测和指标可用于定位问题，但不得作为正式科研结果引用，`PASSED_DEVELOPMENT_M1_M0_EQUIVALENCE_GATE` 也随本轮产物一起失效。

V1 清单规范自哈希为 `759735c797f3f0dc9a2cada1ee91fd376fe251c95ba18974a667cb99b3009b1e`。该哈希只用于永久排除误复用，不授予任何模型或结论资格。

## 最小后继修复

后继版本只作三项改动：以 UTF-8 原始字节保存模型字符串；发布前从磁盘重新载入两份模型；要求重载模型的开发概率向量与训练进程内概率逐字节一致。科研数据、拆分、模型、超参数、指标和开发门均不改变。V1 的失败载荷在本记录写入后删除。
