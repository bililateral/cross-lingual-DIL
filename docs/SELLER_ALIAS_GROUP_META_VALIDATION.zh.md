## 研究问题和两步验证

新卖家群体持续到来，历史训练数据只能保留很少时，如何学习新群体，同时保持旧分布中未见卖家的马甲候选排序和基础识别能力？

第一步回答“当前候选在一个预先固定的配置下，是否出现值得继续研究的效果”；第二步回答“如果有效，收益究竟来自更多监督、元更新，还是完整群隔离”。第一步可以先于完整机制对照；第一步结果不能代替第二步的归因，也不自动证明论文创新。

## 第一步：先运行候选看实际效果

优先准备一轮范围明确的开发性先导运行，只新增当前完整群隔离元更新候选，不自动同时启动其余对照。固定点不等于随意缩短成只学一个群或一个阶段；具体顺序、阶段及终点须在运行前写清，保证确实评价新群学习和旧域未见卖家保持。

- 使用已有LOGIT0.1结果作初步参照；先核对数据、起点、评价和输出口径。可以复用保存的合法开放结果，不为得到参考分数默认重训旧基线。
- 如精度、checkpoint、microbatch、训练呈现数或其他执行条件不同，报告这些差异。即使候选优于旧保存结果，也只作为整体候选的开发信号，不能称为“只由元机制造成的提升”。有必要作因果比较时再补匹配对照。
- 关注最终旧域排序，同时报告新域刚学完及最终最新域表现、基础识别取舍与逐域结果。沿用已有O/N/Z及指标定义，不只挑一个好看的数，不把缓存训练损失当未见卖家效果。
- 在结果开放前固定值得继续的条件、可接受取舍及停止规则，保留有效负结果。当前没有数值门槛，不能看完结果再制定本次“通过”标准。
- 先导用来决定是否值得继续投入，不作为独立最终确认。已经开发过的valid或用过的test不能通过改名恢复独立性。

### 启动前仍需明确的实际事项

| 事项 | 需要确定什么 |
|---|---|
| 一个固定候选点 | 编码器/头内层学习率、rho、beta及选取依据；手写核验夹具数值不自动成为正式配置 |
| GPU可行性 | 在单独明确预算的手写输入上核对实际二阶步骤、显存和耗时；CPU成功峰值45.90GiB不能直接推定32GiB GPU能否运行 |
| 正式运行接入 | 共同首域完整状态如何恢复、当前群/记忆如何供给、阶段末参考如何保存、校准与评价如何接入；当前train_stage API不是已经完成的正式runner |
| 运行与读取范围 | 运行哪些顺序/阶段、数据和标签可读范围、结果何时开放，以及失败与恢复如何计入预算 |
| 判断与资源 | 主要观察量、允许的取舍、是否继续的前瞻规则，总时间/显存/产物上限和预计完成区间 |

这些事项决定首轮到底跑什么、花多少资源、结果能说明什么；不是要求先完成下面所有对照。现有手写CPU授权不自动覆盖正式GPU与数据访问。后续将上述内容收敛为可执行合同，复用已通过且未变的实现审查与核验证据，只审查和核验新增正式接入部分。

## 第二步：有信号后，按问题选择机制对照

以下四个条件构成验证路线，而不是四个新算法。当前候选的精确公式沿用实现定义：Ls是当前基础监督+0.1历史基础监督+0.5历史logit MSE；Lq是当前query基础监督+rho历史query基础监督；临时参数theta'=theta-A grad Ls。

| 条件 | 具体计算或供给 | 要回答的问题 |
|---|---|---|
| 两群LOGIT0.1 | 原当前群监督、历史群监督和历史分数保持 | 整体候选相对强基线是否有实际价值？先导可先参考旧合法开放结果，严格归因时再处理执行条件差异 |
| 四群普通联合训练 | 与候选同四群、同权重，在原theta上计算J0=Ls(theta)+beta Lq(theta)；没有临时更新 | 额外群呈现与监督重加权是否已足够解释收益？ |
| 完整群隔离元更新 | 当前实现：J=Ls(theta)+beta Lq(theta-A grad Ls)，四群身份互斥 | 相对四群普通训练，虚拟更新及元梯度是否有额外作用？ |
| 身份复用元更新 | 保留元更新，每一步support/query复用完整群；按事先固定区块匹配群边际呈现次数 | 使用“另外一群”检查更新是否具有必要作用？ |

身份复用对照的一种待定构造：隔离条件两步分别(C1,H1)→(C2,H2)、(C2,H2)→(C1,H1)；复用条件两步分别(C1,H1)→自身、(C2,H2)→自身。两步内每群support/query各一次，完整候选不拆分。此构造须在正式比较前统一相关条件的调度，不能把当前循环移位日程与另一套区块日程的全部差异都归于隔离。

四群普通训练与元更新匹配群呈现，但仍不等总计算；隔离与复用改变当步群多样性和配对时序。固定共同起点、记忆流、合法数据、外层优化和评价口径，记录更新数、群呈现、时间及峰值内存，明确仍未消除的差异。beta=0只剩两群目标，不能代替四群J0。

按信息需求逐步推进：若先导没有值得继续的信号，不自动补齐所有对照；若有信号，优先用四群普通训练检查额外监督解释，再根据结果与已批准选择规则决定身份复用对照。若先导暴露的是实现/资源问题，先处理该问题，不把技术失败判成有效负结果。若要改算法或继续搜索参数，须明确新增候选和总预算，不凭一次负结果无限重试。

## 结果如何影响后续判断

| 观察 | 可以支持什么 | 不能据此宣称什么 |
|---|---|---|
| 候选先导相对旧LOGIT表现有利 | 整体候选有继续研究的价值，条件差异仍需交代 | 元机制或整群隔离已被独立证明有效 |
| 四群普通训练也取得相近收益 | 更多呈现/监督重加权可能已解释主要提升 | 必须保留复杂元更新或把提升归给二阶机制 |
| 元更新优于四群普通训练，隔离与复用相近 | 元更新在该任务下可能有作用 | 完整群隔离已经是关键贡献 |
| 隔离候选相对两类对照都有稳定优势，且新学习/基础识别满足前瞻要求 | 对完整群任务构造的作用有更强证据，可继续研究其适用边界 | 自动获得原创性或所有分布上的泛化保证 |
| 候选固定点未达到预设继续条件 | 该点没有足够推进依据，保留负结果并分析 | 整个元学习家族无效，或有权继续任意调参 |

当前元目标采用已有MLDG型骨架，MER/La-MAML等有直接近邻；已有外审结论保持。论文贡献若成立，应落在经过验证且未被近邻覆盖的任务构造、必要限制与发现上。四群query仍是训练群，六群历史总预算不保证逐域覆盖；CAB首域零存活事实保留，不事后重抽。
