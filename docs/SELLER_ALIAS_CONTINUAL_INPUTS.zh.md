## 最小训练核心实现及实际核验

[训练核心](../scripts/step28_continual_core.py)只提供预处理、二分类头、单阶段继续训练／ER、共享权重与 Adam 状态复制、评分及真实数值核验命令。**目前不是完整四臂执行器**，不接受项目监督路径，不启动正式比较。冻结臂的状态固定可在数值例中检查；累计重训的实际数据调度、完整模型／分数落盘及独立评价仍须在正式运行器中实现核验。

本次已经落实的语义：

- 头为 57→32→1、ReLU，CPU float32；同控 logit 排序，未来概率评价用 sigmoid。无编码器训练、dropout 或动态统计层。
- 首批 float64 逐列有限值中位数填补，再在填补后的首批求均值和总体标准差；全缺失回退 0、零标准差回退 1。后续仅 transform，结果为 float32。固定预处理属于共同模型状态，单列成本。
- Adam 学习率 0.001、betas=(0.9,0.999)、epsilon=1e-8，无权重衰减，关闭 foreach。继续训练／ER 共用首阶段权重及 Adam 一／二阶矩；各顺序各自形成首阶段。
- 单阶段默认当前数据 5 遍、batch 256，保留不足一批的尾部。第 1 阶段仅当前 BCE 均值；以后 ER 为当前 BCE 均值＋历史 BCE 均值，各权重 1。每次从旧缓存无放回抽至多 256 条；缓存短时用全部旧边。更新次数相同不等于计算相同，分别记录新／旧呈现次数。
- 当前阶段训练完毕才让每条唯一新边获得一次 reservoir 入库机会，不能每遍重复入库。核心的训练循环不插入记忆；未来运行器仍须核对唯一到达和恰好一次调用。当前数据保留到本阶段结束符合多遍分批设定，不称单遍在线算法。
- ER 只保存训练可用的 57 个 float32 特征和一个 uint8 标签，每边 229 字节；没有用行号回查历史矩阵。NPY 未压缩字节与 JSON 中 seen、容量和选择／重放 RNG 状态均计费；预算预留至多 1,024 字节给文件头和状态，512 KiB 可容纳 2,284 边，实际序列化须不超总预算。临时当前批、模型／Adam、固定预处理与总进程内存另报。
- 新样本排列、记忆入库、重放使用独立随机流。恢复缓存应重放下一次抽样及入库，而非只恢复选中边。

本地已通过 5 项输入合同与 8 项核心合同：完整 K28、错拆分／行序拒绝、随机到达覆盖与重放、手算方差分解、首批预处理、缓存分块入库一致性、实际字节预算、缓存状态恢复、短缓存无放回、随机流隔离，以及 NumPy BCE 全参数有限差分。四个新 Python 文件语法有效，两个入口的 `--help` 正常。以上没有执行 PyTorch；它们不能证明真实训练正确。

`check` 命令已包含需要实际执行的 CPU 证据：NumPy 与 PyTorch 全参数梯度比较、有限差分、独立首步 Adam 公式、不同大小新／旧批的实际 ER 损失／梯度／更新、两层参数实际位移、共享 Adam 状态、尾批计数、新数据配对顺序、冻结模型不变，以及磁盘重载后的完整核验样例分数与下一次参数更新。仅用手工数值样例，不读取项目标签。这是新训练语义缺少实际运行证据所需的最小核验，不是重复旧迁移 smoke。
