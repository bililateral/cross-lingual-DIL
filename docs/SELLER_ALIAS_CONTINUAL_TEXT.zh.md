# 持续马甲识别的文本训练复用审查

日期：2026-09-07。范围：用户要求“先审查”后的 Windows 本地可行性审查。没有训练新模型、解析新的训练／开发标签、读取 qrels 或 Audit A/B、连接 Linux。旧四臂与旧迁移结果保持不变。

**结论：可复用文本与聚合组件，但不能直接启动旧脚本作为持续学习实验。下一步优先细化“保留 51 项公开数值特征，重新编码文本得到 6 项特征，再接原结构的 57→32→1 头”的最小方案。**这只是同一持续马甲识别主线中的表示更新探索，不是已证实的遗忘问题、方法贡献或运行合同。先补清缓存和阶段训练语义，不直接开 GPU 四臂。

## 纠正此前描述

项目有两条不同的文本路径，不能混为一谈：

| 路径 | 实际输入与输出 | 本轮用途 |
| --- | --- | --- |
| 刚完成的固定 57 维持续实验 | `legacy18 + LaBSE6 + identity33`；LaBSE6 原先由脱敏中文标题／描述编码得到；只更新 57→32→1 小头 | 保留有效结果。它没有测量持续更新文本编码器的效果。 |
| 已关闭的风格迁移 V2 | 脱敏标题／描述再转为 W/N 占位符风格流；每账号得到 768 维向量，账号对余弦接正缩放标量头；不含 51 项数值特征 | 可复用局部训练经验，不能称为“完整中文原文微调”，也不能拿其 AP 与 57 维模型直接解释编码器更新效应。 |
| 更早的直接中文微调组件 | 脱敏标题／描述分字段、按账号去重并完整分块，动态计算六项 LaBSE 聚合；另接 legacy18、可选 identity33 和线性头 | 六项聚合更接近当前特征定义；只作为局部复用候选，旧训练入口、头、预处理和结果不直接沿用。 |

这里的“文本”只指正式 `observed/redacted_items.jsonl` 的标题／描述，保留词汇内容但已去除身份子句，不是 `raw_items`、身份控制者文件或真实市场新增数据。生成代码向 raw description 附加身份子句，redacted description 则取未附加子句的 base description；本轮检查这条代码路径及已发布训练文件，不重放私有生成器。

仅把全部输入改成风格流，会同时删去现有身份与其他公开证据、改变模型结构，不能据更低分数或后来退化解释成“解冻编码器造成遗忘”。因此本地优先保留现有证据类型，不默认采用风格流替换方案。该选择不保证有收益；强规则仍可能主导结果。

## 实际代码核对与复用边界

审查文件、函数与散列及只读统计见 [diagnostic.json](../reports/seller_alias_continual/20260907/text_audit/diagnostic.json)。没有把整份旧运行器或全部数据生成链宣布为已重新验证。

1. **输入和列序。**当前持续供数拼接 `[legacy18, LaBSE6, identity33]`；旧直接微调的联合输入是 `[legacy18, identity33, LaBSE6]`，还使用了另一套 identity 变换和线性头。维数同为 57 不代表位置、缩放或模型相同。新实现应保留明确列序及同结构小头。动态六维的首批缩放需绑定共同原始 LaBSE、评价模式、最终分块及数值路径，在任何更新前只用第一批可见训练输入拟合后固定；不能无说明地拿旧发表六维的统计替代新路径的统计。动态六维必须通过可微的固定缩放进入头，不能转 NumPy 后切断梯度。
2. **文本聚合。**直接微调的 NumPy／Torch 六维公式均为标题与描述各自的质心余弦、双向 top-3 均值，再形成两项字段等权均值；同字段按唯一文本等权。NumPy 公式与旧 Step7 定义可以在给定向量上比对。它不等于已证明实际重新编码后逐元素复现旧 LaBSE6：公开投影使用四分词器共同分块、旧浮点与序列化路径，直接微调使用单 LaBSE 分块及 bfloat16 前向。新四臂须共同使用一套文本／分块规则；不把输出变化全部归因于解冻，也不为凑旧分数改预测。若要主张只有解冻不同，另需同输入、同数值路径的冻结编码器对照。

   `differentiable_world_semantics` 目前硬编码恰好 378 对，并读取所传世界的全部账号文本。历史缓存通常只是跨世界的稀疏边，故不能直接调用该入口或用额外边填满 378；需仅对保留边的实际端点编码，按相同公式逐边聚合。账号→字段→唯一文本→分块的归属须完整保留／确定性恢复，不能把一堆 token IDs 平均后当作原六维。风格编码函数还会内部排序账号，若另行复用该路径，端点索引必须使用相同排序。
3. **梯度。**两条可微编码路径都调用 `encoder(features)` 并保留图，池化和相似度未主动 detach。旧风格目标每世界 378 对的均值 BCE、编码器／头 AdamW、共同裁剪和实际首步位移记录有完整历史运行证据。旧直接微调线性头初始权重为零，第一步从损失回到编码器的梯度因此为零；AdamW 的权重衰减仍可能移动编码器参数。不能只看位移声称文本监督已生效，也不能据首步零梯度判整个旧训练无效。新的头结构与真实训练链需单独核验。
4. **持续状态。**旧 `train_target` 每个调用都重新加载编码器、创建头和优化器；旧直接微调也重新创建全部状态。它们不能直接充当下一阶段。新方案须共享首批训练后的模型、头与非空优化器状态；继续／ER 跨阶段延续，冻结臂保持首批状态，累计臂按明示合同从共同原始初始化训练已到达前缀。阶段评价后继续训练须恢复规定的训练模式，保存重载也须恢复后续更新所需的随机状态。
5. **历史缓存。**旧缓存每条只存 57 个 float32 和二值标签，没有端点或文本，不能用于重新编码。新缓存须足以在不回查旧数据文件的情况下恢复关系两端的完整模型输入：账号内分字段的文本／分块或等价 token IDs、边端点映射、该边已获标签、所需 51 维数值，以及影响后续选择／重放的状态。可共用端点文本，但实际保留的索引、文本、标签和元数据都计费；不保存私有控制者。缓存不是全部世界的标签图，不能由保留正边自动补出未保留标签。临时前向向量可在同一步复用，不能把旧参数下的向量当作可训练历史输入。
6. **字节与抽样。**原 512 KiB 下 2,284 条记录来自固定 229 字节结构，不能沿用到变长文本。变长记录上“满了就踢到放得下”不再自动具有固定容量 reservoir 的均匀入选性质。下一步先确定一种简单、明确的计费及随机基线；只报告实际实现的抽样语义，不预设新选择器。预算指持久历史记忆，当前批、模型／优化器与峰值 RAM／显存另报，不用隐藏历史文本缓存规避预算。
7. **显存和随机性。**`chunk_batch_size` 只限制前向微批次；向量列表保留图直到反传，不能宣称显存只与一个微批次有关。旧单世界／小样例成功不覆盖“新世界＋历史若干账号”的新形状。ER 多一次含 dropout 的前向会消耗随机状态；相同起始种子不足以证明后续当前样本使用同一随机失活。配对对象是继续与 ER 两臂对应的当前输入，不要求当前／历史输入共用掩码；加入历史不能悄悄改变当前分支的去重、排序和微批次形状。新实现须明确相应随机流；不默认搬用来源关闭 dropout 的两遍 VJP。
8. **标签和评价。**旧风格 `run/evaluate_target` 提前解析开发标签及 qrels，这在其旧合同下合法，但不符合本主线新的先预测后评价顺序。新 Linux 运行仅接收获准训练监督与公开开发输入，保存、重载核对完整分数后，在 Windows 唯一解析开发二值标签并计算全指标；检索相关性从完整开发成对标签形成，qrels 与 Audit A/B 保持不读。每个不同编码器检查点都要用同一参数版本重新编码开发关系两端，不能把新查询向量与旧图库向量混用；完全相同的冻结检查点仍可复用原分数。拟议融合头用原始 logit 排序、sigmoid 概率评价；不能照搬旧直接微调只返回概率的输出。若未来采用余弦标量头，则排名用原始余弦，须另写明。

上述是**新用途的适配要求**，不追认成已完成旧实验的八个错误。涉及模型输入、梯度、阶段可见范围及评价的建议归 `SCIENTIFIC_BLOCKER`；涉及文件／列序、状态复现和计费不符的建议归 `REPRODUCIBILITY_DEFECT`。它们在新实现真正具备相应缺陷时才称已证实缺陷。额外教师、大型生成机制、OS／网络措施、重复旧回归及无依据的多轮 smoke 属于当前不实施的 `OUT_OF_SCOPE_OVERDESIGN`。

## 已有证据与本次只读核验

旧风格 generic 的中文开发世界等权 AP：零样本 0.085087；1／5／10／25／100／500 世界微调分别为 0.073313／0.085280／0.096459／0.111634／0.110646／0.114839（每档三个目标种子的均值）。结果文件与原清单大小及 SHA-256 一致。这说明该表示有已观察到的学习变化；不证明持续遗忘、缓存有效、相对于固定 57 维的优势或当前拟议融合模型效果。500 世界另有更多更新，曲线不能解释为纯数据量效应。旧 25 世界迁移主端点失败保持原结论。

本次只解析训练公开脱敏文本：500 世界、14,000 账号。按旧直接微调的账号／字段去重口径共有 99,000 条文本，UTF-8 内容共 27,389,406 字节，每账号最小／中位／最大为 1,001／1,146／4,720 字节。相同训练账号的风格流共 3,903,507 字节，对应 120／172／740 字节。这里只统计文本内容，不含索引、边、标签、JSON 开销，也未实施缓存或估计其最终容量；旧风格分词统计直接沿用已保存记录，不重复全量分词。

旧风格两端实际 GPU 检查及 72 配置训练结果沿用，未重复 smoke。局部 NumPy 聚合手算／独立公式核对记录在回执；本机缺 PyTorch，本次没有执行新 Torch 反传、编码器重载或新批量容量检查，也没有把阅读代码作为运行通过。

## 下一步的最小范围

保留原中文数据、完整世界、三个到达顺序和四臂问题；优先将 51 项数值证据与可训练六项文本聚合的输入、缓存、首批预处理、损失比例、更新次数和阶段状态写成一个明确的小合同，再实现必要部分。不同时追加新数据、分布变化或复杂选择器，不把 57 维旧政策改写成此次新方案。当前只计划新融合表示内部的持续／重放比较，不提出新旧结果差异完全由解冻造成的因果主张，也不因此新增冻结编码器实验臂。训练预算尚未冻结，不直接搬用旧单世界 200 步或小头的 51,015 次物理更新。

随机五批仍是同源到达，没有建立五个独立域；开发集也已经消费。新的探索只能检查同源分批更新与有限历史重放，不能预先承诺遗忘、域后向迁移或论文创新。若仍没有可重复的更新困难／历史效用证据，继续保留负结果并停止为此堆复杂缓存。
