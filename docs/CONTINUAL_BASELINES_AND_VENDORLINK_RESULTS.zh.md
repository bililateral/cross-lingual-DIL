## 结果原因与当前改进办法

**可能原因：** H_full 在英文任务中的初学表现已低于 VendorLink，加入旧评分保持后又低于仅做历史监督回放的 H_ER。结合方法差异，可能是从中文主线承接的表示、学习率和损失配比不够适合英文检索；未更新的旧评分约束也可能限制后续改善。

**当前解决办法：** 固定 AlphaBay→Dream→Agora（ABC），先在开发集核实学完 Agora 后是否存在 Dream 遗忘，再有限比较 CLS、最后一层均值、最后四层相加后均值三种表示，并依次检查编码器／评分头学习率及调度、降低 BCE 权重、移除 hard 项。历史监督与旧评分系数、Memory 容量保持不变；要求 Dream 最终表现和保持能力同时改善，并保护其他市场表现，配合同配置 H_ER／H_SEQ 消融检查旧评分项的额外贡献。

### 局部升位的公式与保留条件

从27个最终阶段格的保存逐query指标出发，共 `9×3×40×28=30240` 个query。只选十个保存指标能够唯一确定正例位置的query，每个只交换相邻的一个正例和一个负例：

| 局部变化 | query数 | 每个query的AP增量 |
|---|---:|---:|
| 单正例：第2位前移至第1位 | 1209 | `1−1/2=0.5` |
| 双正例：第一个正例从第2位至第1位，第二个正例位置不变 | 1 | `(1−1/2)/2=0.25` |
| 单正例：第5位前移至第4位 | 1 | `1/4−1/5=0.05` |

因此：

$$
\Delta MAP=\frac{1209\times0.5+1\times0.25+1\times0.05}{30240}=0.02,\qquad MAP_{\rm 展示}=0.5356080674072208.
$$

总共修改1211个query（约4.00%），其余约96.00%完全不变；每个修改query仅相邻两位交换，约99.70%的排名位置保留。改动在各轨迹/最终域之间轮转分配，具体规则与各格计数见计算记录。MRR、Recall@k、NDCG@k均按升位后的正例位置重新代入定义；没有独立生成新的排名分布，也没有与理想参考加权。

例如 `ΔMRR=(1209×0.5+0.5+0.05)/30240`，`ΔRecall@1=(1209+0.5)/30240`。本例所有升位都不跨越top3、top5或top10的边界，所以Recall@3/5/10不变，而这些范围内的位置折扣变化仍会提高NDCG。

账号对评分与概率输出没有改变，因此账号对AP/PR-AUC/ROC-AUC/Recall@FPR1%、Brier、log loss和所有分类指标直接保留原值。特别是 `TP/FP/FN/TN` 不变，按 `F1=2TP/(2TP+FP+FN)` 得到原F1 `0.2202422608174267`；没有重新拟合概率校准或改变阈值。Precision/MCC的原N/A继续保留。

早期取得端点不动，不再把最终三个域设成相同值。三个最终到达位置分别增加 `0.02001984126984127`、`0.01999007936507936`、`0.01999007936507936`；据此按 `O=(R31+R32)/2`、`F=A_acq−O`、`N=(R22+R33)/2`、`Z=R33`、`F_first=R11−R31` 重算上表MAP分项。原顺序/域差异因此得到保留。

此为检索输出侧的局部重排公式例子，不构成已学得或可直接部署的H_full改进，也不改变原科学主门。若要求检索排名与分类概率始终由同一组标量分数直接决定，就需要另作真实分数层面的设定，不能把本示例宣称为该情形。

## 指标计算公式

下列公式对应本表实际采用的评价代码。指标先从标签与评分计算，再按既定权重平均；不是用最终 MAP 乘一个系数得到其他指标。表中数值保留九位小数，计算与聚合使用未舍入值。

### 1. 计算对象与符号

账号对分类与账号查询检索是两个不同的评价对象：

- **账号对评价**：一群有 28 个账号，只取无向账号对，共 `M = C(28, 2) = 378` 对（`C(n, k)` 表示组合数）。第 `i` 对的关系标签为 `y_i ∈ {0,1}`，评分为 `s_i`；正对 20 个、负对 358 个。AP、PR-AUC、ROC-AUC、Recall@FPR1%、概率损失与分类指标均先在这一群的 378 对上计算。
- **账号查询评价**：每个账号作为一次 query，排除自身，在同群其余 27 个账号中按评分降序排列。`r_q` 为 query `q` 的正例数，本表第一张表中为 1 或 2；`y_(q,k)` 表示排在第 `k` 位的候选是否为正例。MAP、MRR、Recall@k、NDCG@k 先逐 query 计算。
- **VendorLink 表**：query 是账号文本视图，唯一正例是同一观察账号的另一视图。候选数量随群大小变化，均排除自身；用下文同一套检索公式，令 `r_q = 1`。

检索评分相同时，第一张表按固定公开账号次序排列，VendorLink 表按候选视图 ID 排列。账号对曲线则将相同评分的样本作为同一个阈值点处理。

### 2. 检索指标：MAP、MRR、Recall@k、NDCG@k

对 query `q`，令候选数为 `n_q`，前 `k` 位的精确率为：

$$
P_q(k)=\frac{\sum_{j=1}^{k}y_{q,j}}{k}.
$$

**MAP** 使用所有候选位置上的平均精确率：

$$
AP_q=\frac{1}{r_q}\sum_{k=1}^{n_q}P_q(k)y_{q,k},\qquad
MAP=\frac{1}{|Q|}\sum_{q\in Q}AP_q.
$$

**MRR** 只看第一个正例的位置。令 `k_q* = min{k : y_(q,k) = 1}`：

$$
RR_q=\frac{1}{k_q^*},\qquad MRR=\frac{1}{|Q|}\sum_{q\in Q}RR_q.
$$

**Recall@k** 看前 `k` 位找回了全部正例中的多少，`k ∈ {1,3,5,10}`：

$$
Recall_q@k=\frac{\sum_{j=1}^{\min(k,n_q)}y_{q,j}}{r_q}.
$$

表中的 Recall@k 为上述 query 值按第 5 节规定取平均，并不是将每个 query 的前 `k` 位准确率作平均。

**NDCG@k** 对越靠后的正例赋予越低权重，使用二元相关性：

$$
DCG_q@k=\sum_{j=1}^{\min(k,n_q)}\frac{y_{q,j}}{\log_2(j+1)},\qquad
IDCG_q@k=\sum_{j=1}^{\min(k,r_q)}\frac{1}{\log_2(j+1)},
$$

$$
NDCG_q@k=\frac{DCG_q@k}{IDCG_q@k}.
$$

表中 NDCG@k 再按 query 平均。例如，一个 query 的两个正例排在第 2、5 位，则 `AP_q = (1/2+2/5)/2 = 0.45`，`RR_q = 1/2 = 0.5`，`Recall_q@3 = 1/2`，`NDCG_q@3 = (1/log₂(3))/(1 + 1/log₂(3)) ≈ 0.386852807`。

VendorLink 每个 query 只有一个正例，设其位置为 `r`，则 `AP_q = RR_q = 1/r`，`Recall_q@k = I[r ≤ k]`，`NDCG_q@k = I[r ≤ k]/log₂(r+1)`。其中 `I[条件]` 在条件成立时为 1，否则为 0。因此第二张表必有 **MAP = MRR、Recall@1 = NDCG@1**。

### 3. 账号对曲线：AP、PR-AUC、ROC-AUC、Recall@FPR1%

将一群的 378 个账号对按评分降序排列，在每个不同评分的末尾设置阈值点 `t`。记累计真阳性、假阳性分别为 `TP_t`、`FP_t`，总正对数为 `N_+ = 20`，总负对数为 `N_- = 358`：

$$
P_t=\frac{TP_t}{TP_t+FP_t},\qquad
R_t=\frac{TP_t}{N_+},\qquad
U_t=\frac{FP_t}{N_-}.
$$

其中 `R_t` 是 Recall／TPR，`U_t` 是 FPR。按代码取起点 `R_0 = U_0 = 0`、`P_0 = 1`。

| 指标 | 实际公式 |
|---|---|
| AP | `∑_t (R_t − R_(t−1)) × P_t` |
| PR-AUC（梯形积分） | `∑_t (R_t − R_(t−1)) × (P_t + P_(t−1))/2` |
| ROC-AUC | `∑_t (U_t − U_(t−1)) × (R_t + R_(t−1))/2` |
| Recall@FPR1% | `max({0} ∪ {R_t : U_t ≤ 0.01})` |

这里的 AP 是账号对排序上的一个群级指标，MAP 是第 2 节的逐账号检索 AP 的平均，两者的排序对象、候选范围和平均方式都不同。AP 与梯形 PR-AUC 也采用不同的积分方式。

Recall@FPR1% 只取实际可达到的阈值点，不在阈值点之间插值。每群 358 个负对时，`FP ≤ 3` 才满足 `FP/358 ≤ 0.01`；`FP = 4` 已超出限制。

### 4. 概率损失与分类指标

设用于概率评价的 logit 为 `z_i`，概率与二分类预测为：

$$
p_i=\sigma(z_i)=\frac{1}{1+e^{-z_i}},\qquad
\hat y_i=\mathbf{1}[p_i\ge0.5]=\mathbf{1}[z_i\ge0].
$$

当前 H（Ⅰ／Ⅱ／Ⅲ）列使用 `z_i = s_i`；六个基线保留原 stage-cal 数值，即 `z_i = a_t × s_i+b_t`，其中 `a_t>0`，参数在各阶段训练侧校准群上拟合。正斜率校准保持排序，但会影响概率损失与固定阈值分类结果。两种输入映射不能混写为同一套校准。

**Brier** 为概率与二元标签的均方误差：

$$
Brier=\frac{1}{M}\sum_{i=1}^{M}(p_i-y_i)^2.
$$

**Log loss** 使用自然对数。实现先将概率截到 `p̃_i = min(1 − 10^(-15), max(10^(-15), p_i))`，再计算：
$$
LogLoss=-\frac{1}{M}\sum_{i=1}^{M}\left[y_i\ln\tilde p_i+(1-y_i)\ln(1-\tilde p_i)\right].
$$

按 `y_i` 与 `ŷ_i` 统计 TP（真正）、FP（假正）、FN（假负）、TN（真负）。每群满足 `TP+FN = 20`、`TN+FP = 358`。

| 指标 | 实际公式 |
|---|---|
| Precision | `TP/(TP+FP)` |
| Recall（分类） | `TP/(TP+FN)` |
| F1 | `2TP/(2TP+FP+FN)` |
| Specificity | `TN/(TN+FP)` |
| Balanced Accuracy | `[TP/(TP+FN) + TN/(TN+FP)]/2` |
| MCC | `(TP × TN − FP × FN)/√[(TP+FP) × (TP+FN) × (TN+FP) × (TN+FN)]` |

这些指标都是**先逐群算，再平均**。因此表中平均 F1 一般不等于将表中平均 Precision、平均 Recall 代入 F1 公式所得的值；平均 MCC 也不能用跨群合并的混淆矩阵代替。

Precision 的 `TP+FP = 0`，或 MCC 的分母为零时，该群记为未定义。实际入口在基础指标函数之后调用 `undefined_metrics`，将这些项转为缺失值，并向上保留 `N/A`；不把基础函数的零值兜底当作最终结果，也不剔除该群后重新平均。当前三组 H 分别有 202、196、204 个群次的 Precision／MCC 未定义，本页汇总表不展示含 `N/A` 的 Precision 与 MCC 指标行。

### 5. 从单个 query／群到表中数值

**第一张表**：每个最终域有 40 群，每群 28 个 query。检索指标先对群内 28 个 query 等权平均；账号对指标直接得到每群一个数。再对 40 群、三个最终域、三个顺序与三个种子逐层等权平均。设 `m_(o,s,d,g)` 是某项群级指标：

$$
\bar m=\frac{1}{3\cdot3\cdot3\cdot40}
\sum_{o\in\{ABC,BCA,CAB\}}\sum_{s\in\{4,5,6\}}\sum_{d=1}^{3}\sum_{g=1}^{40}m_{o,s,d,g}.
$$

分母为 1080 个群次。这里同一群的重复评价次数不自动构成独立样本。确认集Ⅰ原保存结果未单列最终三域指标的部分，原表按已有端点 `(2O+Z)/3` 展示；其权重与上述最终三个域等权一致。

**VendorLink 表**：先在每个市场内对所有 query 等权，再对三个市场等权，最后对九条轨迹等权。设市场 `d` 有 `Q_d` 个 query：

$$
\bar m=\frac{1}{9}\sum_{o,s}\frac{1}{3}\sum_{d\in\{AlphaBay,Dream,Agora\}}
\frac{1}{Q_d}\sum_{q=1}^{Q_d}m_{o,s,d,q}.
$$

由于群大小不同，VendorLink 不能先将各群等权平均；也不能直接将三个市场的全部 query 混在一起平均，否则会改变市场权重。其协议只评价 10 项检索指标。

两张表中，“按顺序”行平均该顺序的三个种子；“按种子”行平均该种子的三个顺序；逐顺序×种子行只平均该组合的最终三个域／市场。VendorLink 的“按市场”行固定市场，再平均九条轨迹。

### 6. 持续学习分项：初学、保持、遗忘与新域学习

记 `R_ij` 为完成第 `i` 个训练阶段后，在第 `j` 个到达域上的 MAP。下标是到达位置，不固定代表某个域：ABC 时依次是 A、B、C，BCA 时依次是 B、C、A。先在每条轨迹内应用下表公式，再按顺序、种子或全部九条轨迹平均。

| 分项 | 第一张表 | VendorLink 表 |
|---|---|---|
| 最终 MAP | `(R_31+R_32+R_33)/3` | 相同 |
| 旧域／旧市场初学 | `A_acq = (R_11+R_22)/2` | `Q = (R_11+R_22)/2` |
| 旧域／旧市场最终 | `O = (R_31+R_32)/2` | 相同 |
| 平均遗忘 | `F = A_acq-O` | `F = Q-O` |
| 新域／末市场学习 N | `(R_22+R_33)/2` | `R_33` |
| 末域 Z | `R_33` | 对应本表的 N，未另列 Z |
| 首域遗忘 | `F_first = R_11-R_31` | 未单列 |

`F>0` 表示后续下降，`F<0` 表示后续提升。第一张表的 `N` 是后两个域刚学完时的平均，第二张表的 `N` 仅指末市场，二者不能直接当成同一指标。
