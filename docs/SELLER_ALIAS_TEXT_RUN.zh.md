## 供数和训练边界

训练／开发仍各 500 个完整 K28 世界，每世界 28 账号、99 商品、378 对；训练到达种子 11／23／37，每次按原到达表划成五批各 100 世界。所有世界的类别混合仍来自同一生成机制，不能称五个独立域、真实时间线或同一卖家跨阶段新增账号。

离线基准层允许为索引解析完整公开行键／文本，并在正式训练入口中将完整训练二值 CSV **对齐、解析一次**到临时 uint8 NPY。这个包装层不等于学习方法，不能宣称整个程序从未看过未来行。`WorldArchive` 只常驻世界／端点 ID 和文本字节范围，不保留整库数值、文本或标签数组；方法调用只取得当前批的完整世界。累计臂单独取得已到达前缀，ER 历史只能来自其自含 `ByteMemory`。完整监督临时文件和其他臂的工作状态不作为 ER 的历史来源。

每次实际读取完整世界时，重新核对文本账号集合与原数值行的端点集合，保留全部唯一标题／描述和字段归属；数值仅取原 base24 的前 18 列和原 identity33，不使用六列旧文本向量，不应用旧直接微调入口的额外变换。数值为 float64，文本分块／动态聚合沿用已实测核心。公开 ID 只用于对齐和确定性顺序，不进入预测头。

首批缩放只从共同原始 LaBSE 的首批公开输入得到。保存 medians／means／scales 快照并逐数组验证，后续所有臂沿用；每次从原始或共享工作状态恢复时再次对照这份小快照，不将开发数据用于缩放。

## 四臂调度与计算

同一张 GPU 上仅保留一个活跃 LaBSE／头／Adam；每个到达顺序按“初始→共享首批→继续臂全部后续阶段→ER 全部后续阶段→累计臂全部后续阶段”执行。各臂独立按自己的到达阶段推进，改变的是物理执行顺序，不是任何臂能获得的数据。当前世界次序和 dropout 坐标种子由原核心重建，ER 不改变对应当前分支的文本去重或微批次。

| 部分 | 输入与状态 | 每顺序物理更新 |
| --- | --- | --- |
| 共享首批 | 原编码器／头、空 AdamW，100 世界各两遍；只实际训练一次。 | 200 |
| 冻结 | 各后续阶段引用共享首批的同一完整分数和推理模型；没有新的优化调用。 | 0 |
| 继续 | 精确恢复共享编码器／头／非空 Adam／首批缩放，随后仅各当前批两遍。 | 800 |
| ER | 从相同共享训练状态出发，首批结束后的同一随机字节缓存开始；各当前批两遍加至多 16 条历史边。 | 800 |
| 累计 | 第二至第五阶段每次恢复原始编码器／头、空 Adam 和相同首批缩放，分别训练 200／300／400／500 已到达世界两遍。 | 2,800 |

合计每顺序 4,600 次，三个顺序 **13,800 次物理更新**。当前均值 BCE 和历史均值 BCE 各权重 1；累计臂额外计算单报，不称同计算对照或理论上界。记录实际更新、当前／历史呈现、新到达／过去到达呈现、训练平均更新损失和耗时，不据开发结果调日程或早停。

首批缓存仅阶段末插入一次，ER 后续每阶段训练完成后再插入当前唯一边一次。缓存仍为 512 KiB 的随机优先级最长可容纳前缀，成本影响入选概率，不叫均匀 reservoir。持久历史状态包括完整端点文本、51 数值、标签、优先级和两个 RNG；每次发布报告实际边数、正例数、覆盖账号数、真实字节和状态摘要。首批缓存的编排临时副本在 ER 开始时读取后删除；ER 训练不保留一份可回查的额外首批历史备份。用于磁盘核验的瞬时复制不进入方法重放供数。

## 分数与存储

每顺序有“初始＋共享首阶段＋三更新臂各四阶段”共 14 个评分点，三个顺序共 42 个。每个点：先用当前模型完整重编码 500 个开发世界的两端，再保存包含非空 Adam（初始点为空）、三组缩放、进度及当期 ER 缓存的临时完整状态；在同一个模型对象中重载、逐项核对，重新编码全部开发世界，要求全部原 logit 精确一致，再保存和回读分数 NPY。ER 还比较重载后的下一次抽样，比较使用副本，不消耗正式采样 RNG。

长期保留每顺序的共享模型和继续／ER／累计最终模型，共 **12 份推理模型**。它们只有编码器、头、缩放与数值政策摘要，不含训练标签缓存或 Adam；落盘后实际载入，再完成该点第二次全部开发评分。所有 42 点的完整分数、临时状态字节数／哈希、模型和优化器摘要、逐点回执、训练及访问记录均保留；其余中间大状态在核验后清理。若后来需要中间模型，需要按记录重算该训练路径，不能假称每个中间模型仍在磁盘。

这避免长期保存 42 份完整大模型＋Adam。按当前参数量估算，12 份 float32 推理模型约 22.6 GB，42 个分数 NPY 共 31,757,376 字节；原始／共享／当前发布临时状态同时约需 13.2 GB，整个运行的实际峰值还要加已经发布的模型和普通开销。这是计划估算，实际大小、CPU／GPU 峰值和耗时以运行回执为准。核验状态与离线监督临时文件自动清理，不新增打包压缩或增量权重格式。

上轮一个 ER 更新为 7.027 秒，只是单个公开形状；机械乘以 13,800 约 26.9 小时，不能当本轮总工时预测。不同臂、文本长度、84 次完整评分遍历、完整状态 I/O 的开销不同；正式任务须留出完整资源窗口，不因估时改动训练预算。

源码／政策在检查或运行期间若变化，最终记录拒绝使用变化后的文件哈希认领先前计算。新检查同时登记复用的小型测试夹具源码；正式入口核对 PyTorch、NumPy、Transformers、Sentence Transformers、CUDA／cuDNN 与已通过的组件实测一致，防止环境变化后仍沿用旧实现证据。这个核对只防止普通文件、数值环境与结果错配，不增加签名、权限隔离或状态审批机制。
