# Step28-v13 V9.4.1 迁移主张修复 V4 合同

## 1. 科研问题

现有 V3 的主要比较 `M2-五个M1均值` 只证明正确对齐的中文合成身份历史可学习。由于 M0、M1 和 M2 共用同一冻结英文基础概率，该比较不能证明英文 M0 对中文判断提供了不可替代的增量。本版本不得改写 V3 结果，也不得打开审核甲或审核乙真值。

本版本依次回答两个问题：

1. 在相同中文身份特征、训练行、正则化和截距条件下，加入冻结英文 M0 是否优于完全不使用 M0；
2. 在相同中文训练世界预算下，结构化身份适配是否优于直接微调 LaBSE（语言无关句向量模型）。

## 2. 第一阶段：英文来源贡献对照

第一阶段只使用已经打开过的训练、开发标签和现有公开投影，不重新读取审核真值。

- `I0-identity-only`：`截距 + 33项身份历史`；
- `T1-m0-plus-identity`：`截距 + 冻结M0对数几率 + 33项身份历史`；
- `M2-v3-reference`：只读复用已冻结 V3 开发概率，不重新拟合。

I0 与 T1 使用同一无标签身份变换、同一训练行、同一二范数惩罚 `0.01`。截距不惩罚，33项系数惩罚；T1 的 M0 系数固定为 1。禁止把 I0 的基础概率简单设为 0.5 且不拟合截距，因为这会人为忽略每世界 `20/378` 的正例基准率。

主要开发诊断为 `AP(T1)-AP(I0)`，并使用冻结的 9,999 次按世界重抽样计算百分位区间。只有点差严格大于 `0.01` 且百分之九十五区间下界严格大于零，才允许在后续盲审核中提出“英文 M0 有实际增量”的假设。开发通过不是审核结论。

第一阶段必须分别报告平均精确率、梯形精确率召回率曲线下面积、受试者工作特征曲线下面积、精确率、召回率、F1、平衡准确率、马修斯相关系数、平均倒数排名、平均准确率均值、召回率@1/3/5/10、归一化折损累计增益@1/3/5/10，以及现有合同的其余指标。

## 3. 第二阶段：直接微调对照

第一阶段完成后再实现 GPU（图形处理器）训练。直接微调必须从冻结的原始 LaBSE 权重开始，使用训练拆分的中文合成卖家完整商品标题和描述；标题与描述分别无损分块，不允许整段截断。模型使用与 M0 相同的六项块聚合语义关系，编码器参数参与反向传播。

至少比较：

- `FT-base`：微调 LaBSE，加18项基础关系特征；
- `FT-joint`：与 FT-base 相同，再加入33项正确身份历史；
- `T1-m0-plus-identity`：冻结英文 M0 的结构化适配对照；
- `M3-joint`：现有中文结构化直接训练对照。

训练预算按世界固定为 `1%/5%/10%/25%/100%`，使用按世界标识哈希排序得到的嵌套子集，禁止按标签或结果选世界。所有方法使用相同世界预算。审核甲真值打开前，必须先冻结新增模型、开发阈值和审核甲盲预测。

## 4. 结论边界

- 第一阶段通过：只说明英文 M0 在中文合成开发集上提供可测增量；
- 第二阶段若仅在小预算下优于微调：可以研究低资源适配价值；
- 若直接微调在全部预算上更好：停止把身份适配器作为主要方法贡献；
- 即使审核甲、审核乙通过，也只能证明合成机制内泛化；真实中文地下市场结论仍需要新的独立真实标签。

## 5. 版本与产物纪律

V3 训练、开发结果和审核甲 V1 盲预测保持逐字节不变。V1 审核甲真值评价合同暂不执行。V4 使用新策略、新脚本和新结果目录；失败时记录科学边界并删除不完整模型、缓存和临时目录。

## 6. 直接微调执行纪律

Linux 只接收 Windows 复制的文件，不要求 Git。先运行不读取任何正式监督的图形处理器冒烟：

```bash
bash scripts/run_step28_v13_v1_13_v9_4_1_labse_direct_finetune_v1_linux_20260901.sh smoke
```

冒烟必须证明完整文本分块、LaBSE 前向和反向传播可运行，并报告训练、开发、审核甲、审核乙真值读取均为零。通过后才运行一次正式开发比较：

```bash
bash scripts/run_step28_v13_v1_13_v9_4_1_labse_direct_finetune_v1_linux_20260901.sh run
```

正式运行只读取训练标签、开发标签和开发检索真值；不得读取审核拆分。失败时程序删除 `.building` 和不完整检查点。成功时仅保存五档开发概率、完整指标、训练日志，以及全量预算的 FT-base／FT-joint 两个最终模型；不为低预算重复保存大型编码器。
