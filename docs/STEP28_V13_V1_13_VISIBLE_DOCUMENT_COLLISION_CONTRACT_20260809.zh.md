# Step28-v13 v1.13 可见文档碰撞防线合同

## 一、状态与目的

本文件是 v1.13 的设计合同，不是运行结果。当前没有 v1.13 正式主种子、生成能力、正式数据行、质量回执、模型或效果指标。v1.12 已因完整商品文档碰撞永久失败；v1.13 只能作为事后工程修复重新开始，不能追认、修补或重放 v1.12。

唯一直接目标是：在不读取标签、控制者、身份特征、M0 分数或审核结果的前提下，使每个新生成的完整商品文档和卖家五字段文档都不命中历史或本轮已有文档，并把该约束同时放在生成、封存和独立质量审计三层。

## 二、冻结文档定义

商品文档严格定义为规范 JSON：

```json
{"description":"<脱敏后的完整描述>","title":"<脱敏后的完整标题>"}
```

商品标题和描述使用生产脱敏器的原始输出，不再额外执行 `strip`、Unicode 规范化或大小写折叠。规范字节必须机械地等价于：

```python
json.dumps(
    {"description": description, "title": title},
    ensure_ascii=False,
    sort_keys=True,
    separators=(",", ":"),
    allow_nan=False,
).encode("utf-8")
```

再计算 SHA-256（安全哈希算法）。每一行商品都必须对应一个唯一哈希；不能只对集合去重后比较。

卖家文档严格按以下五个 M0 可见字段顺序构造，去掉各字段首尾空白，忽略空字段，并以单个换行连接：

1. `category_concat_top`（主要类别拼接）；
2. `signature_title_concat`（特征标题拼接）；
3. `title_concat_top`（主要标题拼接）；
4. `signature_description_concat`（特征描述拼接）；
5. `description_concat_top`（主要描述拼接）。

卖家文档直接对 UTF-8 字节计算 SHA-256。生成器、封存器和独立审计器必须调用同一小型纯函数，并用黄金向量锁死字节定义。每个拆分在生成、封存和独立审计三层都必须满足：

```text
商品行数 == 商品哈希行数 == 商品唯一哈希数 == 注册表商品哈希数
卖家行数 == 卖家哈希行数 == 卖家唯一哈希数 == 注册表卖家哈希数
```

拆分内部重复由上述行级基数门判断；历史和跨拆分碰撞才使用集合交集。二者不能互相替代。

每个候选世界必须同时避开：

- 经固定发布清单重算的 v1.2 全部商品和卖家文档哈希；
- v1.12 终止排除归档中的 100,936 个商品文档哈希和 28,000 个卖家文档哈希；

拆分顺序固定为训练、开发、审核甲、审核乙。开发必须先验证并消费已封存训练拆分的文档注册表；审核甲消费训练和开发；审核乙再消费审核甲。任何前序注册表缺失、未封存、哈希不一致或被改写都立即失败。

历史集合只保存或读取哈希，不读取历史标签、审核真值或原始私密身份值。v1.13 还必须继续消费累计 999,996 个失败身份值哈希、六类 v1.12 编号哈希和全部已消费能力承诺，不能只修文本而放松既有新鲜度门。

## 四、无标签自然候选机制

### 4.1 能力隔离

每个拆分仍只抽取一个 32 字节主种子。主种子派生一个新的 `document_variation`（文档表述变化）能力；它与结构、编号、身份、基础文本、查询和五个训练错配能力逐项不同。主种子不挂载到生成器或模型。候选键禁止写回或替换 `policy["randomness"][mode]["text_key_hex"]`；它只能作为新的显式参数进入白名单表述函数。原 `text` 能力继续负责并唯一决定风格、商品数、缺失模式、时间、自然代码和下述候选无关父结构。

基础文本能力继续固定以下量，所有候选尝试都不得改变：

- 世界、卖家、商品、配对、查询和控制者编号；
- 市场、控制者成员关系、正负标签和机制分配；
- 卖家控制者风格与六项有效风格因子；
- 每卖家商品数、标题/描述缺失模式、时间桶和既有自然商品代码；
- 身份资产值、类型、角色、槽位编号和 identity33（33 项身份历史特征）。

在任何候选前，先生成一份不含文档表述变化的候选无关父结构，并形成规范指纹。所有候选必须与该父结构比较，不能只与候选 0 比较。文档表述变化能力只允许改变：类别/商品词、属性、交付与服务自然短语、标题和描述的白名单表述选择、登记高语义负例的可见商品词，以及“必须忽略”噪声的自然表述。它不得生成、拼接或显示世界编号、卖家编号、商品编号、重试次数、标签、控制者或身份特征。

以下选择来源必须在候选无关父结构中固定，并进入指纹：

- 每个登记覆盖的 `override_kind`、`asset_index`、`canonical_pair_uid`、左右卖家和左右商品编号；
- 每个“必须忽略”噪声的卖家编号、商品编号和噪声槽编号；
- 五个 M0 可见资料字段的贡献商品编号或描述片段来源、支持商品编号集合、排序和聚合角色；
- 资料聚合器、解析器、脱敏器的源码 pin、输入商品编号顺序及全部非文本输入。

v1.13 必须扩展一个只在私有审计中存在的资料贡献血缘记录；它不得改变 Step3 的公开聚合算法或最终资料字节。每个普通贡献值至少记录来源商品编号集合、首次出现位置、聚合角色和输出名次；每个描述签名片段还必须记录 `item_uid`、`extracted_segment_ordinal`、支持商品编号集合、聚合角色、输出名次和 `seller_df`，并记录产生该文档频率的卖家编号集合摘要。候选可以替换已固定贡献位置上的允许自然表述，但不能重新选择贡献对象。上述血缘、登记覆盖或噪声目标发生任何变化都是版本级失败，不得通过换候选恢复。

### 4.2 候选派生与整世界接受

候选编号固定为 0 至 31。每个候选键按以下字节合同派生：

```text
HMAC-SHA256(
  document_variation能力,
  "step28-v13-v1.13-document-candidate" || 0x1f ||
  split || 0x1f || world_uid || 0x1f || uint64_be(candidate_index)
)
```

每个世界先从已提交世界重建身份父集合，在其副本上只执行一次身份值重映射，冻结该世界的身份资产、身份值哈希、身份槽和 identity33 父状态。候选 0 至 31 全部复用同一份身份父状态；候选循环不得持有或修改拆分的实时身份集合，也不得重新选择身份值。

每个候选完整重绘允许的可见自然表述，再运行生产解析、身份脱敏、资料聚合和 378 对闭包验证。`candidate_index` 只允许因以下三类精确文档碰撞递增：

1. 候选世界内部商品文档哈希重复；
2. 候选世界内部卖家五字段文档哈希重复；
3. 商品或卖家文档命中 v1.2、v1.12、当前拆分先前已提交世界或前序已封存拆分注册表。

结构指纹不一致，登记覆盖、噪声或资料贡献血缘改变，固定身份值与候选自然文本冲突，解析、脱敏、资料、标签、identity33 或身份槽闭包失败，文件、锁或注册表不一致，均属于版本级实现失败：立即停止整个版本，禁止查看下一候选。所有版本级不变量必须在决定是否按碰撞重试前完成验证；同一候选同时出现精确碰撞和任一版本级错误时，版本级错误优先，`candidate_index` 不递增，也不得查看下一候选。只有“通过全部版本级不变量验证、但命中文档碰撞白名单”的候选可以丢弃并继续。

首个没有上述精确碰撞的候选还必须满足以下条件，才可提交整个世界：

- 每行商品文档在候选内唯一；
- 28 个卖家文档在候选内唯一；
- 商品和卖家文档均不命中冻结历史集合及先前接受集合；
- 冻结结构量、选择血缘和身份量与候选无关父结构逐字节一致；
- 生产解析、脱敏、资料和身份特征验证全部通过。

拒绝一个碰撞候选只丢弃该候选的内存对象，不写原文、不占用身份哈希、不推进公开或私有表。首个无碰撞且闭包正确的候选连同该世界唯一一次身份分配增量一起提交。32 个候选全部碰撞时，整个版本失败；不得换主种子、放宽门槛或原地增加模板。

### 4.3 标题克隆的可解边界

登记的“精确标题克隆”仍只复制标题，不得复制完整商品文档。缺失模式合同从“至少一个非空标题、至少两个非空描述”收紧为“至少两个标题和描述同时非空的商品”。该等价性由固定资料 `reports/step28_synthetic_chinese_dataset/v13_dev_smoke_v1_20260727/reference/chinese_train_style_profile.json`（SHA-256 `5537f59fd558521d47a27702ba23e8a56620c4e14f2579e2658436f2729a3a34`）的独立证明约束：`seller_equal_weight_quantiles.title_missing` 的 0.05、0.10、0.25、0.50、0.75、0.90、0.95 七个节点都必须精确为数值零。机器证明为 `reports/step28_synthetic_chinese_dataset/design_preflights/v1_13_collision_contract_20260809/style_profile_title_missing_attestation.json`，原始 SHA-256 为 `ee3e84ac0ed111027c41ff1760db29935f6473b1b244445b51085fd7a4daf326`，规范自哈希为 `be951a3e6ee1c4cca58f26ca4b1a5658c0105adabcf66706c492a21f5f2bdaa8`；它及其精确 pin 必须进入 v1.13 draft。断言不成立时，不得声称分布等价，也不得继续本版本。

来源商品继续从标题非空商品中固定选择；目标商品改为从标题和描述同时非空、且未被更早登记覆盖占用的商品中固定选择。来源/目标卖家、所选商品和机制槽位由候选无关父结构确定，不因候选编号变化。

这样既保留“相同标题、不同完整商品上下文”的困难负例，又不会在来源和目标描述同时为空时制造永远无法通过的完整文档重复。若两侧非空描述仍偶然相同，则由整世界自然候选机制解决。

## 五、持久化与三层复核

每个拆分在读取任何恢复状态前必须取得拆分级排他进程锁；该锁覆盖状态重建、候选搜索、世界提交和最终合并。同一拆分的第二进程不得并发搜索或提交。

每个世界先完全在内存中搜索候选。首个合格候选形成不可变世界包，写入 fresh、按拆分序号命名的私有事务目录；全部成员写完并逐文件 `flush`、`fsync` 后，最后以 no-replace 方式写入 `WORLD_ACCEPTED.json` 作为唯一提交标记。标记必须精确 pin：世界编号、拆分序号、接受候选编号、候选无关父指纹、身份分配增量、商品和卖家文档哈希、每个世界包成员的相对路径、大小和 SHA-256，以及前一个已提交世界标记摘要。

没有有效提交标记的事务目录不属于已接受状态，恢复时验证路径边界后删除；存在有效标记的世界永不重新搜索候选。拆分的实时身份集合和文档集合只能由顺序连续且全部验证通过的世界提交标记重建。500 个世界全部提交后，才按拆分序号确定性合并成规范 CSV/JSONL，并一次性 no-replace 写入最终 `document_collision_registry.json`。它是最终封存，不是逐世界改写的数据库。

最终合并采用确定性 `publish-or-byte-identical-verify`（发布或逐字节相同验证）协议：每个缺失的规范成员先写入 fresh 临时文件，`flush`、`fsync` 后以 no-replace 原子发布；恢复时已经存在的最终成员只能与从 500 个已提交世界重算的期望大小和 SHA-256 逐字节验证，只有缺失成员可以补写，禁止删除或覆盖已有最终成员。全部规范表、文档注册表和拆分清单验证完成后，最后 no-replace 写入并同步 `SPLIT_SEAL_COMPLETE.json`，其中 pin 全部最终成员、文档注册表、拆分清单和第 499 个世界提交标记。未形成有效最终封存标记时不得发布拆分或启动后续拆分。

每个拆分的私有审计新增：

- `document_collision_attempts.jsonl`：每世界只记录接受的候选编号、候选数量、各类拒绝计数和结构指纹哈希，不记录被拒原文；
- `document_collision_registry.json`：排序后的本拆分商品/卖家文档哈希、计数、集合摘要和前序封存钉；
- 生成回执中的候选次数分布、最大候选编号、历史/前序/本拆分交集均为零的硬门。

封存阶段必须从暂存的公开商品和卖家资料重新计算全部哈希，逐项等于私有注册表，并重算前序拆分交集。独立质量审计不能信任生成回执或注册表，必须第三次从公开行重算，与 v1.2、v1.12、拆分内部和跨拆分集合比较。

注册表和回执均不得覆盖写入。最终规范表、注册表和拆分清单全部封存并交叉验证后，删除大体积逐世界事务包，只保留小型 `WORLD_ACCEPTED.json` 血缘标记和清理回执；失败或未提交事务包按失败清理纪律立即删除。

开发拆分的启动/授权回执必须钉住已封存训练拆分的 `STAGE_FINALIZED`、拆分清单和文档注册表的原始 SHA-256 与规范自哈希；审核甲同时钉住训练和开发，审核乙再钉住审核甲。缺少任何前序封存钉时不得开始后续拆分。

## 六、捷径与后选择防线

候选编号仅在私有审计中出现，而且是世界级常量，不能作为 M0、M1、M2 或 M3 输入。生成器只依据精确文档哈希接受候选，不依据近重复、模型分数、标签或科研指标挑文本。

正式种子前的设计预检必须重新运行现有可见文本反事实攻击，并增加以下固定报告：

- 1,000 个训练/开发设计世界的候选编号分布和拒绝原因；
- 候选 0 与最终候选之间结构、标签、identity33 和六项风格因子逐字节不变；
- 只在内存审计中构造、绝不进入正式数据的卖家级碰撞参与特征：卖家在被拒候选中参与商品文档碰撞和卖家文档碰撞的次数，按历史、同世界、先前世界、前序拆分分开的次数，候选 0 到最终候选是否改变该卖家的允许表述，以及资料贡献血缘是否改变（硬性必须为零）；
- 将上述卖家特征按配对构造左右值、和、绝对差及相等指示，与世界候选编号和拒绝总数一起输入既有 assignment-null（分配零信息）/捷径攻击模型，继续使用已经冻结的模型、阈值和多重比较门，不新增事后阈值；
- 商品/卖家文档对 v1.2、v1.12、拆分内部及跨拆分的精确交集全部为零；
- 字符三元组、词袋、主题/模板/表面统计攻击继续按既有反事实硬门执行。

候选次数分布只用于诊断，不得在看见正式结果后调整阈值、模板或候选上限。任何设计预检失败都要先形成失败边界并删除失败产物，再开新版本。

## 七、实现与验收顺序

1. 先实现纯哈希定义、行级基数门、精确历史 pin、风格资料零标题缺失证明和候选键派生；
2. 建立候选无关父结构、资料贡献血缘和只执行一次的试算身份分配，证明候选循环不接触实时集合；
3. 再把自然表述变化能力作为独立参数接入白名单商品词、高语义可见词和噪声表述，禁止替换原 `text` 能力，并证明所有选择血缘不变；
4. 修正精确标题克隆的来源/目标资格；
