# Step28-v13 v1.13 V9.1 模型视图承诺修复合同

日期：2026-08-21

状态：`IMPLEMENTATION_ONLY_NO_REBUILD_NO_QUALITY_AUDIT_NO_TRAINING`

## 1. 唯一修复目标

V9 第二次冻结质量审计在 `loaded_model_view_structure_binding` 阶段发现 3,012 个卖家画像摘要不一致：1,004 个世界的完整、代码遮蔽和代码中和画像全部使用了投影前内部 Step3 画像计算摘要，而数据集实际写盘的是冻结模型允许读取的精简画像。

V9.1 只修复这一个对象边界：`channel_structure_audit` 必须承诺模型实际写盘、实际加载的卖家画像投影。不得调整文本、身份、控制者、标签、世界规模、候选、随机权威、质量特征、模型、阈值或重抽样。

## 2. 唯一共享投影

科学公共模块定义唯一 `project_model_seller_profile` 和批量 UTF-8 排序投影。它只保留：

- `seller_uid` 连接键；
- 五个冻结文本字段；
- `item_count`；
- 标题和描述长度统计中的 `median`；
- 五项冻结风格统计。

内部来源、市场、拆分、原始卖家名、完整统计、审计字段和后加私有字段一律不进入模型视图。数据集写盘器和质量通道物化器必须调用同一实现，禁止复制第二份投影逻辑。

三种 `*_profile_sha256` 只对该投影后的、按 `seller_uid` UTF-8 排序的逐世界行列表计算。商品视图摘要公式不变。中和回执内的 `neutral_profile_sha256` 与外层结构回执必须绑定同一投影对象。

## 3. 同一随机权威与反事实等价门

V9.1 不获得新的数据抽样自由度。它必须复用 V9 的同一世界记录、同一随机密钥、同一 1,004 世界顺序和候选选择公式，使用新的输出根、政策字节、提交／树和一次性授权。

失效 V9 四份拆分清单作为只读终端谱系保留。V9.1 构建后必须逐文件比较：

- 除四个 `private/channel_structure_audit.jsonl` 外，68 个数据文件大小和 SHA-256 必须与 V9 完全相同；
- 四个结构审计文件的世界 UID、行数、行序、字段顺序和除画像摘要外的全部值必须相同；
- 每个世界只允许 `full_profile_sha256`、`masked_profile_sha256`、`neutral_profile_sha256` 发生确定性变化；
- 每个新画像摘要必须从该世界实际写盘的对应模型画像文件重新计算并相等；
- `full_item_sha256`、`masked_item_sha256`、`neutral_item_sha256` 必须逐值保持 V9 原值；
- 新旧四拆分的 pair labels、qrels、控制者、Identity33、商品／卖家／身份 UID 集合必须逐字节相同。

任一额外差异立即使 V9.1 构建失效，禁止解释、筛世界或换随机权威。

## 4. 必须新增的回归

1. 使用含额外内部字段的真实 Step3 画像，证明结构摘要等于共享投影摘要且不等于宽画像摘要。
2. 给被排除的内部审计字段加入任意值，模型投影和摘要必须不变。
3. 一世界真实写盘后，从三个画像 JSONL 逐文件回读，逐世界摘要必须与结构回执相等。
4. 篡改任一模型可见画像字段，冻结结构校验必须失败。
5. 旧 V9 根只读反事实必须精确复现 3,012 个旧不一致，并证明用共享投影重算后 3,012 个不一致全部关闭；不得修改旧根。
6. 政策测试必须拒绝新随机权威、替代输出根、放宽等价文件集合或允许第二次构建尝试。
