# Step28-v13 v1.13 V9.4.1 正式四组五百世界中文合成数据构建合同

日期：2026-08-29
状态：`READY_FOR_ONE_TIME_FORMAL_AUTHORIZATION`

## 1. 唯一修复目的

V9.4 方法资格根及其质量通过结论保持不变。V9.4 正式尝试一在完成训练 315 世界后，因新电话号码命中 v1.2／v1.12 历史身份排除库而机械失败；它没有形成数据结论，且其政策、权限、回执、路径和 315 世界永久不得复用。

V9.4.1 只修复正式身份值分配：在任何身份值进入可见文本以前，按标签无关的固定规则取得一个对历史、方法资格根和本轮均全局唯一的值。世界规模、公开平衡排程、文本生成、作者风格、身份机制、生产解析器、三十三维身份特征、碰撞定义和后续质量门均不改变。

## 2. 固定规模与科研边界

- 训练、开发、审核甲、审核乙各 500 世界，共 2,000 世界；
- 每世界 28 个卖家、12 个控制者和全部 378 个无序对，固定 20 正例、358 负例；
- 四拆分合计 56,000 个卖家和 756,000 个卖家对；
- 标签只由私有合成控制者归属定义，不读取英文或真实中文标签；
- 构建成功状态仍只能是 `BUILT_NOT_TRAINING_QUALIFIED`；
- 审核甲乙真值读取必须为零；正式根独立质量通过以前不得训练 M0／M1／M2／M3。

## 3. 渲染前确定性身份分配

每个身份资产仍先由冻结生成机制决定身份类型、关联卖家、角色、复用机制和资产标识。随后，新分配器只接收：全新身份权限、身份类型、资产标识、固定候选计数器，以及三个只读排除集合。它不得接收控制者编号、标签、检索相关性、模型分数、文本质量或候选世界结果。

候选计数器严格从 0 递增到冻结上限。每个候选由带域分隔的密钥散列映射到该身份类型原有的固定格式和值域；依次执行：

1. 拒绝命中 v1.2／v1.12 历史身份值散列；
2. 通过密封验证器拒绝命中 V9.4 方法资格根身份值；
3. 拒绝命中 V9.4.1 本轮此前已分配值；
4. 接受第一个通过三项检查的值，并立即在内存中占用。

这不是换种子、挑世界或按标签重采样。对于给定权限、资产顺序和排除库，结果唯一；碰撞只改变该资产的候选计数，不改变世界、卖家、机制、标签、商品数量、风格或任何其他变量。计数上限耗尽必须使整个尝试失败，不得扩上限后原路径续跑。

分配必须发生在渲染、生产解析和三十三维特征计算以前，禁止事后字符串替换。每世界必须按实际生成顺序证明分配器记录的每个“资产标识—值散列”与生成器身份计划逐行完全相等，不能只比较无归属的值集合；最终必须证明分配器全局集合与私有碰撞注册表完全相等。重复资产标识直接使整次尝试失败。

## 4. 防择种与一次性权限

V9.4 尝试一的六项权限承诺必须进入 V9.4.1 禁用集合。V9.4.1 使用新的实现、政策、命名空间、权限目录、授权文件、公开／私有输出路径和六枚全新 32 字节权限。第一次随机调用以前独占写入签发占用回执；六项权限各只抽一次，重复或命中任一历史禁用承诺立即永久失败，不得重抽。

签发只允许在新实现提交、推送且工作区完全干净以后进行。正式入口只接受该提交加唯一未跟踪授权文件；消费、失败、原始权限清理或完成回执任一存在即拒绝。消费回执引用中的文件摘要必须由独占写入前已经冻结的精确序列化字节计算，写入返回后不得再读取回执才能形成引用。消费后任何异常先写失败终态；随后验证并删除六个已消费原始权限文件，写入绑定失败终态的小型自哈希清理回执；最后删除临时和不完整最终根。清理回执只保存权限承诺，不保存权限字节。

## 5. 排程、碰撞与密封边界

公开 V9.4 平衡排程只作方法级同构复用，使用新的 V9.4.1 命名空间和新排程权限。四拆分的世界顺序、卖家槽、同市场余数类内噪声槽及完整排程承诺分别不同；模型可见标识仍被禁止。

完整脱敏商品文档、五字段卖家文档、世界／卖家／商品／卖家对标识、身份值和身份资产继续执行 V9.4 的历史、方法根、本轮内与跨拆分零碰撞规则。文档或标识碰撞不得通过候选世界、重渲染或重抽权限解决，仍直接使尝试失败。只有身份值有限命名空间使用本合同第 3 节冻结的逐资产计数器分配。

普通构建器不得读取方法根身份明细。钉住的密封验证器只内部保存 `asset_uid` 与 `value_sha256`，对单个候选只返回通过或失败；不得返回旧值、逐值散列、角色、机制、成员关系、标签或检索相关性。

## 6. 审计回执

公开根只保存按身份类型聚合的资产数、历史／方法根／本轮候选拒绝数、非零计数器资产数、最大已选计数器、固定上限和全局分配集合摘要；不得保存候选值或被拒绝值。私有根继续保存正式身份计划与身份碰撞注册表。

发布前必须验证：

- 分配器资产数等于身份计划行数；
- 每世界分配器新增的“资产标识—值散列”序列与实际身份计划逐行逐序相等；
- 最终分配集合与私有正式身份值集合相等；
- 历史、方法资格根和本轮交集均为零；
- 生产解析仍逐字重放最终被渲染的身份值；
- 审核甲乙真值读取为零。

## 7. 失败、质量与后续训练

V9.4.1 任一正式失败必须先记录运行编号、阶段、根因、关键摘要、结论边界和不可复用承诺，再删除失败载荷、六个原始权限、缓存、临时目录及本次专用失败代码；六个权限文件的实际消失必须由独立清理回执闭合。不得拼接 V9.4 的 315 世界。

正式根成功发布后仍须另行冻结并执行完整质量审计：七个控制者盲风格错排视图、十四个冻结模型、346 个单特征和 9,999 次按世界重抽样；审核甲乙保持密封。只有新的正式质量终态明确通过，才能签发训练资格并计算 M0、五个 M1、M2、M3-base 和 M3-joint。

## 8. 当前非数据预检证据

使用固定烟雾权限完成了四拆分各 500 世界、共 2,000 世界的“只规划身份、不生成文本、不写数据”预检。共规划 160,500 个身份资产；确定性分配器拒绝 7 个历史候选（电话号码 2、QQ 5）、1 个方法资格根候选（QQ），本轮内部候选拒绝为 0；8 个资产使用计数器 1，其余使用计数器 0，最大已选计数器为 1，远低于冻结上限 4,096。四拆分排程承诺均不同，最终全局分配集合与规划集合一致。

该结果只证明有限命名空间避让机制在完整抽象排程上闭合，且精确复现了 V9.4 缺少避让时会出现的历史命中类别。它没有生成自然文本、正式数据、随机权限、授权、标签结果、质量结果或模型结果。
