# 科研纪律

本文件是常设执行规则。项目目标、当前授权、作业状态和保留例外见[当前交接](AI_RESEARCH_HANDOFF.zh.md)；具体计算与预算见实验合同；用户原话见[讨论记录](RESEARCH_DISCUSSION.zh.md)。本文件不复制进度、PID、标签消费数或历史审查流水。

## 1. 规则职责与优先关系

| 材料 | 职责 | 更新方式 |
|---|---|---|
| AGENTS.md | 接手入口和关键边界 | 保持简短，不复制纪律或进度 |
| 本文件 | 共用授权、验证、数据和交付规则 | 规则变化时原位更新 |
| AI_RESEARCH_HANDOFF.zh.md | 当前研究、已批准范围、下一步 | 一个当前段落／表格，注明观测时点并链接实际回执 |
| 合同、policy、来源清单 | 本轮问题、干预、访问、预算、判据及实现身份 | 正式使用后冻结，变化另留明确补充或新合同 |
| 执行、结果、审查原件 | 实际发生的事及结论依据 | 保留原件；纠正另记，不覆盖旧字节 |
| RESEARCH_DISCUSSION.zh.md | 用户决定、范围和未决事项 | 保留原话与时点，旧提议标明历史性质 |

先判断对象、阶段和时间，再判断优先级。用户最新明确指令在其范围内优先；当前实验按已确认合同及后续明确补充执行；通用规则补充未约定事项；历史快照不授予新权限。新通用规则不自动改造活动实验或重置其预算。

事实与授权分别处理：用户可以接受已有提升、改变后续计划或保管范围，原验收、标签接触和运行结果仍如实保留。代码、policy、文档一致不等于符合用户问题，发现冲突须追溯需求和原始证据。已知且适用的最新决定直接执行，不以旧文字重问相同许可；有未决实质选择时仅暂停依赖工作。

边界的目的决定处理方式：

| 要保护的内容 | 为什么限制、何时优先落实 |
|---|---|
| 数据资格与评价独立性 | 未来域、封存真值和未开放结果会改变可支持的主张；即使只读、复制或调试也先核对权限，接触过的结果不因新合同变回未见 |
| 科研问题与公平比较 | 干预、起点、随机流、预算和主要对手决定差异能否归因；变化前先确认实质选择，不能用实现方便或漂亮结果反推需求 |
| 真实实现与证据 | 同一误解可能同时进入代码、测试和合同；审查实际计算，针对缺口核验，未变且适用的证据可直接复用 |
| 资源与保管 | 预算保护研究范围和共享服务器；删除由实际依赖及恢复需要决定，不由结果是否好看决定 |
| 历史事实与推进效率 | 固定原结论、明确当前许可；旧等待措辞、重复审查和额外报告不能阻塞已授权工作，当前确有缺口才暂停依赖动作 |

项目内发生冲突时，先定位具体对象及最新明确决定，再区分“允许做什么”“何时具备执行条件”“证据支持什么”；其中任一项不能替代另外两项。

## 2. 授权与自主执行

| 情况 | Agent的动作 |
|---|---|
| 阅读已获准文档／既有结果、整理方案、维护规则与引用 | 直接完成；“只读”不授予读取封存或未开放结果的权限 |
| 已确认合同内的实施、同步、核验、训练、回传与收尾 | 按前置条件连续推进，不按连接、命令或子步骤重复确认 |
| 不改变科研语义的实现选择，或已确认方案内的明确实现错误 | 自主作最小处理并验证；涉及已产结果或冻结运行时保留原件、说明影响 |
| 新研究问题、数据／标签权限、比较、候选范围、预算或判据 | 先给具体方案、依据和取舍，确认后推进依赖工作 |
| 已证实有效性缺陷、许可超限、必要证据缺失或资源不足 | 暂停受影响动作，保留现场，明确恢复条件；独立且已授权的工作继续 |

“继续”“开始”“按方案执行”等答复可以直接授权已经呈现的完整范围，不要求固定口令。文件组织、常规实现和检查选择由执行者判断；改变科学问题或资源／数据边界的事项才提问。问题须自包含并解释影响，不让用户重填已有答案。

Linux阶段按科研范围划分。新增范围先汇报用途、输入、执行和资源并取得授权；已确认范围内的查看、复制、核验不是新阶段。用户的暂停／排除指令按其范围持续有效。项目授权与工具自动审批分别处理：已有许可不重问；实际拒绝时说明具体动作和原因，不绕过拒绝，独立且可执行的工作继续。

## 3. 合同与开发／确认边界

合同只写足以决定本轮工作的内容，不另造审批表：问题及可支持主张；干预、对手与复用条件；数据和模型可见信息；候选、种子及预算；评价、选择与停止规则；必要实现证据、执行和失败处理。已有设定明确引用，变化部分写清，不复制全部历史方案。

开发阶段可以前瞻批准有限候选集合，或有明确规则的有限候选生成方式、总预算及停止条件。范围内可依据已开放开发结果选择下一项，全部尝试与选择理由留证；越界需新确认。结果不理想不授予继续搜索权限，也不要求基线必须胜出才结束。

最终确认阶段在结果开放前固定方法、主要对手、全部运行／端点、评价公式和判据，再按合同一次开放。不能用最终结果重新校准、选轮、换对手或调方法；若继续开发，原结果已接触的事实不变，新的确认另立合同。数据不因改名、新建运行或再次授权而变回独立留出。

通用纪律不固定所有实验的算法、23项门槛、零退化容忍、种子数或bootstrap次数，由问题与前瞻合同决定。容忍幅度须有任务或测量依据，不能从已见结果倒推。已有合同判据与关闭路线不因规则整理改写。

## 4. 三种访问权限

未来涉及监督和评价的合同分别说明以下三项，写入现有合同与记录即可，不要求新管理系统。

| 权限 | 前瞻说明 | 不应混淆 |
|---|---|---|
| 技术读取 | 哪些文件／划分，由谁或哪个组件读取，目的、次数或明确范围；失败尝试与恢复读取如何记账 | 一次解析后多轮训练不等于多次开封评价；文件存在不等于允许读取 |
| 结果开放与查看 | 哪批结果在什么完整性条件后向谁开放，是否允许中途结果、批次数及范围 | 重读同一已开放结果不是新开封；追加未开放端点或结果批次须依合同 |
| 根据结果作选择 | 可改变的候选／超参数、候选上限、总预算、选择和停止规则 | 允许查看不自动允许再训练；允许训练不自动允许用未授权评价调参 |

技术读取和适应性选择限制都要落实，不能用一个“解析次数”替代全部边界。当前合同仍按原次数、失败记账和完整盲门执行，不追溯增加许可。新规则允许未来合同前瞻定义范围，不直接授予额外读取、查看或实验。

训练监督、开发评价、封存审核真值分开。学习器只接触允许的当前数据与存活记忆；调度器为分发读取全表，不允许路径提前接触未来域或恢复淘汰数据。研究归档不等于学习器可用记忆。Audit A/B真值、qrels、owners／控制者及私有身份资产只在专门授权阶段访问；private_custody保持忽略，不打印密钥，不进入公开材料或未授权同步。

## 5. 实现、核验与证据复用

使用或修改实现前，从用户问题出发读取实际实现和直接科研依赖，追踪“要求→计算→证据→结论”。按影响核对输入／拆分／对齐、目标与权重、encoder和head梯度／更新、训练／评价模式、配对预算／随机流、保存恢复、校准、指标及不确定性。冻结、哈希、测试或外审通过不能代替科学判断。

接手时读直接相关的历史网页审查原文，核对范围与未关闭事项，不递归重审全部历史。原件不可得就披露，不能只看摘要却声称读过原文。主执行者对自己、外审和获准子agent的结论均负独立核查责任，核对支撑当前主张的原始代码、输出和证据，不以对方自述或检查数量为证明。

| 实际变化 | 最小充分核验 |
|---|---|
| 规则／文字／链接／机械复制 | 内容、引用和差异；需要同字节时查大小／SHA，不跑科研测试 |
| 编排／路径／存储且科研语义未变 | 受影响入口、资源、路径和产物；若改变随机性、预算或输入，按实质影响升级 |
| 公式／采样／梯度／优化／恢复／评价 | 独立手算或参考、受影响测试、必要最小真实运行；正式使用前补相应环境证据 |
| 新结果／结论 | 从保存结果核对指标、计数、配对、统计和判据；不重复解析已用标签或拟合模型 |

记录证据支持的行为、源码身份、相关环境与边界。相同且适用的部分复用，只补变化和未验证部分，不因换执行者、阶段或提交而全量重跑。公式参考应能发现共同理解错误；非零总梯度、静态检查或模拟返回值不能证明训练正确；小样例不能代替合同要求的正式端点／完整分数检查。

未来合同可采用“旧证据＋增量核验”，在现有主审记录中明确引用、适用范围和变化。若实际入口要求当前完整来源匹配，必须满足入口，不能拿不匹配旧回执启动。必要入口调整归入新阶段受影响实现核验，不为证据复用另造通用框架。

测试按变化选，记录实际通过、失败、错误、跳过；跨模块变化才扩大，不混入永久关闭路线。[历史分区依据](STEP28_CURRENT_AND_HISTORICAL_REGRESSION_RESULT_20260830.zh.md)不是当前固定命令。运行前了解对应CLI用法；不在Windows运行科研脚本或安装科研依赖。

## 6. 外审与主审

实质方案、实现、评价或结论默认网页GPT 6 Pro外审；充分的一轮可同时覆盖合同与实现。未变证据不重送，必要修正只复核受影响部分；训练前实现审查不替代结果审查。纯纪律／文档组织、用户决定记录、命名／引用修正、日常同步和机械收尾免审。明确用户免审按其范围执行，仍做必要本地核验，不冒称外审通过。

外审上传与公开交付沿用用户已经明确的材料、目的地和用途范围。许可若限定具体包，不泛化到新包或其他目的地；需补充确认时先完成可审查的具体材料并说明差异。已授权常规交付不重复提问，审查者要求也不授予额外数据读取或上传权限。

未来合同已批准手写CPU核验及预算时，可先连接Linux、看资源、同步必要代码，用现有py310和获准模型在手写输入上核验，再与合同和代码一并送审。正式文本、标签和GPU训练仍等实际外审／主审及其他合同前提；审查后修改相关实现时只补受影响证据。

| 意见性质 | 处置 |
|---|---|
| SCIENTIFIC_BLOCKER：已证实破坏科研有效性或数据边界 | 停止依赖工作，最小修复并补对应证据 |
| REPRODUCIBILITY_DEFECT：已证实影响重放、普通来源／产物对应或必要留证 | 修复影响当前交付的部分，不扩展为系统加固 |
| 合理后续建议，当前有效性不依赖它 | 说明价值和边界，必要时放入下一合同，不新增当前阻断 |
| OUT_OF_SCOPE_OVERDESIGN：无关复杂流程或系统／网络／攻击加固 | 不采纳并简述原因 |

未证实疑点先核对关键证据，不直接宣判缺陷；新增科学选择问用户，外审不代替授权。保存实际审查文本、必要附件／源码／日志及主审处置。请求模型、可见选择器与审查者自述分别记录，未独立取得的后台身份不编造；网页实测不冒充项目原生证据。

等待外审时做完已授权独立必要工作后汇报并暂停，不空转轮询或制造任务。仅在明确允许委派时用子agent；责任和权限不转移。完成后保留必要证据并关闭，工具不能关闭时停止剩余执行、核实状态并说明限制。

## 7. Linux执行、资源与故障

沿用交接指定的服务器、项目目录、py310和已有模型，不新建环境或在Linux安装／配置Git。Windows负责编辑、文档、同步及小型既有证据核对。SFTP／SCP由Agent完成，不让用户代传；适当隔离部署，避免覆盖活动来源。

共享服务器先只读查资源和进程归属，足够才运行，不挤占后反复试跑。不停他人进程，不改其文件、系统、驱动或共享环境；可能影响他人的操作先说明并取得许可。资源门是执行条件，若调整会改变已批准预算或运行边界，需相应确认和核验。

已有队列／监听先检查，不能重复启动；创建监听或自动启动需相应授权。自删、启动判据和失败处理按具体决定，保留启动／退出证据。通用harness不自动创建常驻监控或重试作业。

未来开发合同可事先批准基础设施故障恢复，条件是：代码／数据及完整模型／优化器／随机状态固定，尚未查看评价结果，已用与剩余资源合计不超原预算，技术读取和恢复权限明确，必要恢复行为已核验。缺项就询问；不借恢复改算法、换种子、扩预算或重置访问账，不给每项实验强加恢复系统。当前合同的禁止重启、失败尝试消费和仅保存矩阵收尾边界仍有效。

失败先留运行ID、失败位置、已发生访问、原因及可用证据，再判断合同内处置。环境／包装失败不自动是科学负结果，无效运行不能继续支撑原主张。未授权重试先提具体方案，不换目录掩盖旧尝试。

密码只作SSH认证，不进命令、文件、日志、外审或回复。给用户Linux命令时用完整Bash块，说明目录、环境、输出，长参数用反斜杠续行，不拆路径。

## 8. 结果解释与汇报

分别报告：运行／评价是否有效；相对哪个对手、哪些指标的正向／负向／未确定证据；原验收是否通过；数据、种子和外推边界。有效实验可未达目标，局部正结果可与整体验收失败并存；区间跨零不证明无效或有害；无真值盲预测不归为准确率正／负结果。

不为有利排名选择生成设置、种子、预算或主端点，不用辅助正结果替代失败主端点，不把已知适配或基线改进声称原创；单配置失败不否定方法家族。均值保护不等于每域／种子保护，条件bootstrap不覆盖未建模的重训、选择或生成不确定性，观察值不下降不等于总体非劣效。

按合同报完整指标、计数及不确定性，分清AP、梯形PR-AUC、逐查询MAP和其他聚合；当前候选排序含MRR、MAP、Recall@1/3/5/10、NDCG@1/3/5/10及合同其余指标。评分与抽样定义从本轮合同取得，不移植其他实验的余弦／logit或bootstrap设置。

每次训练状态报告有观测时点、预计总时长、剩余时长、Asia/Shanghai完成区间及依据，另列强制上限。排队启动时间未知时如实说明，不编造完成时刻；完成后给实际耗时与剩余0。启动、成功、审查通过、结果达标、文件同步和Git交付分别判断，缺项明确说明。

## 9. 文件、归档与清理

scripts放代码，tests放测试，schema放政策，docs放规则／计划／结论，reports放可复核产物，models放模型载荷。原市场导出、html-rips和日期来源转储为不可变输入。Python四空格、snake_case、常量大写、非简单接口类型注解及pathlib.Path；优先确定性排序、固定种子和明确schema，JSON／JSONL用UTF-8，CSV保留已有编码。

文件名简短按用途，不加版本号；步骤、科学量、种子、日期和语言／格式后缀允许。持久Linux编排脚本用run_step*_linux_YYYYMMDD.sh。保留既有运行ID，新实验用新目录，不混写独立运行；改名同步引用、导入和命令，保留科学版本、角色和原哈希。旧路径见[命名迁移表](../reports/file_naming_migration/20260905/filename_map.json)。

大型数据、预训练模型和检查点通常留Linux，Windows保留代码／政策／文档和必要小证据。删冗余本地载荷前核对远端实际大小／SHA，不凭同名或旧回执；缺失先复制，同路径异内容先停该项。当前可变规则／交接可在核对两端差异后按授权更新，与冻结原件禁止覆盖分开。迁移不授权解析、载模、移动封存资产或删除唯一必要副本；恢复与已删除清单见[存储记录](STORAGE.zh.md)。

权重按后续依赖及恢复需要保留，不按正负结果一刀切。活动状态、必要共享起点、未来确需加载的基线／候选及明确例外保留；无后续用途且恢复需要明确的已结束权重可清理，不清楚就问。先保留运行ID、代码／配置、完整指标、必要盲分数与日志、原结论、逐文件路径／大小／SHA，再查归属和最终路径，记实际数量／字节。SHA不能恢复权重，重训仍需授权。

一次性助手、上传副本、浏览器日志和临时解包用后删除；必要复现代码、正式审查原文与科研证据保留。不可恢复无效运行先留ID、失败阶段、根因、结论边界、关键哈希与不可复用承诺，再清理无用载荷。有效负结果证据不随权重删除，活动状态不当垃圾，失败大载荷不因“以后可能查看”无限保留。

## 10. 完成交付

交付前对照需求检查过度修改：发现无关扩展、重复实现、冗余核验或额外流程，实际撤回、合并或简化并核对影响，不能只写检讨。保留用户改动、冻结历史、必要证据及活动状态，不为检查再造报告、审批门、状态机或无关重构。

阶段成果及时范围清楚地commit并push到现有科研分支，短祈使句主题、一项科研变更一项提交。查实际差异、必要验证和git lfs status，排除凭据、封存真值、私有资产及未批准数据／模型。不擅自force-push、改历史或合并主分支，用户暂停推送时遵从。

push后独立查实际远端ref并与拟交付提交比较，核对未推送／未提交工作；TLS、认证或LFS失败就处理具体失败，不把本地commit或工作区干净写成远端交付。SFTP同步和Git交付分别验证，不为给回执再加回执而无限追加提交。

规则维护只改受影响条款与当前入口，不另存重构前文档副本。历史通过已有Git版本及原始科研报告回溯，入口见[当前交接](AI_RESEARCH_HANDOFF.zh.md#历史与证据)；历史文字不重新授予权限。
